## What each task shipped, and what it corrected in the plan

Every plan in this repository has needed correcting mid-flight. This one was no exception.

- **Task 1 (A55)** — `MD0221`, refused at *two* layers: a `Setting` validator, so a shared
  `pipeline.yml` is refused before `emit` reads it, and `_ext_scope` itself, because
  `model_construct` skips validators (that is **A62**, carried). Three plan corrections: `Why`'s
  fields are `tier`/`source`/`reason`, not the `settled_by`/`layer` the plan guessed; **`value:
  null` had to be exempted**, since an unanswered tier-4 setting contributes no fragment and an
  earlier draft refused the shipped spine at load; and `EmittedBy` has no `core`, so the code is
  `compiler` like `MD0208`, which is also a `pipeline.py` validator.
- **Task 2 (A58)** — the finding was bigger than the audit stated: **three spellings reach the
  same capability**. `yaml.unsafe_load`, an alias (`import yaml as y`), and a bare-name import
  (`from yaml import unsafe_load`) which has no attribute access at all. The check resolves the
  *module* behind a local name rather than matching text, because a spelling-matched check is
  what A60 is. `mendel-compiler` needed no exemption — it only ever calls `safe_dump`.
- **Task 3 (A59)** — the plan assumed `import` events could measure coverage. They cannot: every
  module is imported above the arm line on purpose, so none fires inside the region. `open` is
  the right signal for the opposite reason — the unwatched stage is precisely the one that reads
  files somebody else wrote.
- **Task 4 (A57)** — six rules now ask `_serialised_hints`; one deliberately still asks
  `model_fields`, because "has this field somewhere to go" is a different question and a computed
  field is not a destination. Also corrected the `FREE_TEXT_FIELDS` comment, which read "exactly
  two" above a set of seven — A33's drift, one file over.
- **Task 5 (A56)** — **the first version cut the honest path too.** `mendel upgrade` demoted a
  genuinely replayed override and re-flagged a question a person had answered; three A46/A54
  regression tests caught it. The fix separates claim from evidence: `resolve(prior=…)` takes the
  caller's records, so no single object supplies both. An unbacked claim is **demoted, not
  refused** — invariant 6 asks that tier 4 stay flagged, and raising would let a broken adapter
  halt a laboratory's build.
- **Task 6 (A70)** — the plan flagged the scope question and it was real. The first version put
  `MD0222` on every verb sharing `_refuse_a_divergent_directory`, and an `upgrade` test broke.
  That test documents `upgrade` already answering honestly. **`publish` alone refuses**, and the
  deciding distinction is what each verb does with the answer: upgrade produces a report a person
  reads, publish stamps a verdict onto the artifact. A scope test now keeps that a decision.

## Two method failures of mine, both in the ledger

Both are the same shape as Plan 1.11's wrong-worktree near-miss: **a verification ran happily
against a tree that was not what anyone thought it was.**

- **`git checkout <file>` to undo a probe, while the fix was uncommitted.** It restored the file
  to HEAD — the *pre-fix* state — so the probe and the fix were removed together and the tests
  then passed for the wrong reason. The A55 validator was wiped this way and re-applied.
- **Reversing a string edit hit the wrong occurrence.** Probe B in Task 2 replaced
  `modules.get(node.value.id, "")` with `node.value.id`; reversing it replaced the *first*
  `node.value.id` in the file, an unrelated line, leaving the scan silently wrong while the suite
  still ran green.

**Restore from a file copy, and commit the fix before probing.** Both are recorded in the guard
ledger under the tasks they happened in.

## One inert branch caught by probing, not by the next audit

Task 2's bare-name route was first written with an `if not exempt` guard copied from the attribute
route. Probing showed no file can take that branch — `yaml_strict.py` uses the attribute form — so
it was a condition nothing could reach. That is `MD0216`'s exact shape from Plan 1.10, and it was
removed rather than shipped. The mirror image also happened: a composed A58+A59 probe that could
not execute (a `yaml.unsafe_load` in a file that does not import `yaml`) reported green and looked
briefly like a gap. **A probe that cannot run proves nothing in either direction.**
