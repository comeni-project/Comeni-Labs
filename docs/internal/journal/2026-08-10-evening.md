## What each task shipped, and what it corrected in the plan

Every prior plan needed corrections mid-flight; this one was no exception, and the rule earned
itself again.

- **Task 1 (A44) / Task 2 (A45)** — the plan's code used `re`. `comeni-core`'s purity allowlist
  bans it, so both were rewritten with spelled-out `frozenset`s and a hand-rolled `${…}` scanner.
  Char classes are data here, not regex, on purpose.
- **Task 3 (A38)** — `via: meta` and `via: directive` now emit; only `ext` did before, so two of
  three routes recorded a value that reached no tool (issue #10, one level down). Meta injection is
  arity-agnostic Groovy (`[ it[0] + [k:v] ] + it[1..-1]`), validated in real Nextflow.
- **Task 6 (A46) + Task 14 (A54)** — these compose, and the composition was the hard part.
  `settings[].value` is the single writable home of a tier-4 answer; `MD0218` refuses a stored
  `human_override` that contradicts it, and `upgrade` derives the override at replay. A54 then
  demanded that `source: human` be backed by evidence — but the honest replay path was itself
  writing `source: human` with a null `human_override`, the exact inconsistency A54 named. The fix
  went past the plan's "add a validator": `resolve()` now records `human_override` on the
  `ParamDecision` whenever the resolution's source is `HUMAN`, so the decision *is* the evidence,
  and `MD0220` enforces the pair. **This is a design reconciliation worth a reviewer's eye.**
- **Task 11 (A50)** — `publish` no longer re-resolves against the installed registry; it certifies
  the files on disk (`pipeline.yml` is self-contained). A design consequence, surfaced: publish no
  longer re-runs conformance, because it reads no contracts — that guarantee relocated to `build`,
  where it always ran, and a rewritten test records the move. A safety-framed test change.
- **Task 12 (A51)** — rather than thread `loaded.displaced` from the CLI (the plan's route, which
  reintroduces the caller-forgets failure mode), `RuleTable` was given its own `displaced` list like
  the other three kinds, so `resolve()` reads all four off its arguments.
- **Task 16 (A42)** — the `ext.args` name-sort has *two* redundant sorts (materialisation and
  emit), so no end-to-end build watches either alone. The test reverses a materialised step's
  settings and calls `_ext_scope` directly — the only place the emit-time sort is observable.

## A near-miss worth recording

Mid-Task-14 the Bash cwd silently reset from the `.worktrees/plan-1.11` worktree to the **main
checkout** after a `cd` in a probe. Several verification commands (`grep`, `git log`, and a
`git stash`) then ran against `main`, which is at the audit-docs commit *without* any 1.11 fix —
so `make verify` reported 542 passing tests that had nothing to do with the work, and a `git log`
that appeared to show every commit gone. Nothing was lost: the `Edit` tool used absolute worktree
paths throughout, and `plan-1.11` held every commit. **Lesson: after any `cd`, the shell may land
in the main repo — use absolute worktree paths or `git -C <worktree>` for every command.** The
`542 vs 594` collected-test count is the tell that a run hit the wrong tree.
