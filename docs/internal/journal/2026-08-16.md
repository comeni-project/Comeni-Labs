## #38 — the measurement vocabulary

The issue asked for the vocabulary to be **derived from twenty real rules** rather than designed
abstractly. Plan 1.15 produced those twenty. This is the derivation: **twelve measurements where
there were six**, each cited, each declaring whether a tool can produce it.

**Five of the original six turned out to be assertion-only** — including `strandedness`, which
becomes featureCounts' `-s 2` and is this repository's own worked example of tier 3 working.
That is not a defect in any of them; it is precisely what the `sealed` profile exists to act on,
and it was written down nowhere a reader would find it.

The flag alone would not have been enough, so `MD0315` requires the reason: a reader cannot tell
*"no tool exists for this"* from *"the tool exists and nobody has vendored it"*, and those are
different amounts of work — one is research, one is a contract.

**The drafter half stays open and is the real residue.** Nothing writes a measurement, and the
issue's sharpest observation is that the drafting question and the measuring question are the
same one: a contract can be drafted from a module's `meta.yml` because the module is ground
truth, and a measurement has no equivalent source document. That is Plan 2's forge.

## #39 — arithmetic, without a solver

A `derives:` **`transform`**: a chain of *named unary operations with a literal operand*, left
to right.

```yaml
  - fact: genome_sa_index_nbases
    kind: integer
    source: genome_length
    transform: [{op: log2}, {op: divide, by: 2}, {op: subtract, by: 1}, {op: at_most, by: 14}]
```

**The shape is the argument, not the feature.** There is no parser, no precedence, and no way to
reference a second fact — which is the one thing a general expression language would buy and the
thing that turns a rule table into a program.
`docs/design/rule-tables-and-port-logic.md` §13.2 asked for arithmetic that does not reintroduce
a solver, and this satisfies both halves. That §13 reasoned its three limits from a registry
holding **one** rule and all three turned out to be real is the argument for the corpus that
replaced it as evidence.

**Nineteen of the twenty-one corpus rules now load.** R02b stays refused — it is the audit's own
contortion for R02, and a validating contortion would be the format endorsing the workaround it
replaced. R20 stays refused by design.

## The method, twice over

**A revert has to break the subject, not the claim about it**, and I got that wrong twice in one
day: weakening `assert expected in str(caught.value)` and weakening
`if not measurement.assertion_only` both left everything green, as they must. The reverts that
mean something edit the registry `.yml` and the code path.

**And one edit landed in the wrong checkout.** The shell's working directory reset to the main
checkout after a `cd` into `comeni-registry`, and the next edit went there. It was caught by
`make drift` reporting *"no drift: 27 shared files agree"* — impossible in the worktree, where
fifteen files differed. **The symptom was a gate turning green**, which is the one direction
nobody investigates.
