## The through-line: a hash over concatenated fields

Three of the eight defects were the same mistake at three depths, and finding the first two
did not stop me making the third.

1. **The layer digest was forgeable.** It joined `f"{name}:{content_hash}"` with newlines and
   escaped nothing, so one file named `a.yml:<sha of "alpha">\nb.yml` containing `"beta"`
   digested *identically* to a two-file layer holding `a.yml`/"alpha" and `b.yml`/"beta". Two
   structurally different directories, one digest.
2. **A file could impersonate a symlink.** After fixing (1) by hashing the name, links were
   still hashed as `"symlink:" + target` and files as raw bytes — so a file containing the
   text `symlink:/etc/passwd` matched a link pointing there. I had fixed the outer
   concatenation and left the inner one, which just moved the seam.
3. Both are now stated as one rule, in `digest.py`: **a hash over concatenated fields means
   nothing unless each field can be read only one way.**

Defect (2) was found only because the operator asked "did you fix the same hashes problem?"
after (1) landed. I had fixed one and assumed the fix generalised. **Re-attack after fixing;
do not infer that a class is closed from having closed an instance of it.**

Why this mattered more than a normal bug: Task 8 makes a layer something strangers
distribute, and the lockfile pins layers by digest to prove a pipeline was built against
exactly that registry. A forgeable digest makes that proof worthless, and unlike most bugs
here it is forgeable *deliberately*, by someone who wants to.

## The other five

**`Vocabulary` digested differently in every process.** Three digests under three
`PYTHONHASHSEED` values. The codebase-wide rule — "anything serialising a `frozenset` needs a
sorting `field_serializer`" — had been applied field by field, and `Vocabulary.types` is
`dict[str, frozenset[str]]`, so its sets are dict *values* and were invisible to that sweep.
Nothing had ever serialised a `Vocabulary`, so nothing noticed. Federation §4.1 has the
lockfile pinning the vocabulary, so every lockfile would have been spuriously dirty — while
looking perfectly stable inside any one process, which is how it would have passed review.

**`ShadowRecord.winning_layer` was an absolute filesystem path.** It became reachable from
`PublishBundle` the moment `PipelineIR.shadowed` landed, the egress guard walked it for the
first time, and there it was: `/tmp/xxxx/lab/contracts`, headed for a publishable artifact,
past the rule the lockfile has a dedicated test for.

**`drift_against` crashed on the two cases it exists to report.** First a contract deleted
from the registry — it built its comparison via `Lockfile.of`, which calls `registry.get`,
which raises `KeyError` on exactly that contract. I fixed that in Task 3 and introduced the
second: deriving the comparison from the *new* IR's nodes meant a contract still in the
registry but no longer used by the re-resolved pipeline was absent from the lookup, so a rule
change that routes away from a locked contract crashed — which is precisely what `upgrade`
is for. Only Task 7 exercised it.

**Layers compared by name, and a registry is a stack.** Inverting the stack produced *no
drift at all*: every digest unchanged, only their order moved, while invariant 11 has a
higher layer shadowing lower ones. The same name-keyed mapping collapsed two layers sharing a
basename, keeping the last — and Task 8 names the public layer `registry/`, so a lab stacking
it over their own `registry/` hits that on day one. Layers now compare positionally.

## Corrections to the plan

Beyond the defects, five places where the plan did not survive the code:

- **Two fixtures predated Plan 1.5.** They declared `have: [fastq.reads, annotation.gtf]`,
  and the spine has needed `genome.fasta` as a declared type since the missing-genome defect.
- **The plan contradicted itself, and byte-identical won.** It asked for a "replayed from a
  recorded decision:" prefix on the resolution reason *and* for
  `test_upgrading_reproduces_byte_identical_nextflow`. `reason` is emitted into `main.nf` as
  the comment above the parameter, so the prefix made an upgraded pipeline differ from the
  published one by exactly that string. Federation §4.1 promises byte-identical Nextflow; the
  wording of a comment promises nothing. The reason is verbatim; the replay fact lives in
  `resolved_by`. Both halves are pinned, each test pointing at the other.
- **The changed-rule test edited a rule Plan 1.5 deleted** — `param: strandedness`. It now
  swaps the aligner rows, the registry's one genuine decision.
- **`Registry.load` needed layer names passed in, not derived.** It is handed
  `<layer>/contracts` directories and the layer's name lives one level up.
- `Layers.paths` did not exist and three tasks assumed it; Task 3 adds it.

## Decisions, and why

**`os` stays off `comeni-core`'s allowlist.** Asked whether to add it, and the answer was no:
`Path.readlink()` already did the job, and `os` carries `os.system`/`os.popen`/`os.execv` —
process execution — into a set whose entire value is containing none. That is the hole the
2026-08-03 audit exploited with `import urllib.request`. The guard made me reach for the
narrower tool, which is the guard working rather than being in the way.

**The bundle writes files and sends nothing.** Publication is the door with no undo, so the
artifact and its transmission are separate acts and a person can read what they are about to
publish. Nothing in this plan opens a socket.

**`publish` refuses a non-conformant contract**, like `build`. A build you can rerun; a
bundle you have handed to someone you cannot. Publishing must not be the looser path.

**The public registry is labelled as what it is.** Its README says, in the second section,
that it is *not* a curated registry — every contract is a test fixture that happens to be
true, and "curated" in Mendel means a named human signed off, which has not happened. It was
published now because a registry living inside the tool's repository is not a registry, and
splitting it while it is small is cheaper than later.

### 1. Plan 2 — and it needs rewriting first

`docs/internal/README.md` already says Plan 2 "predates the types it references". After this
session that is worse, not better: `Goal` moved packages, `PublishBundle` gained two fields,
`resolve` gained two parameters, and the registry moved directory. **Do not execute Plan 2
task-by-task as written.** Re-derive it against the code first, the way Plan 1.7 was written
against real types.

Two known collisions to resolve while doing that:

- **Plan 2 Task 4 builds `ReplayingResolver` in `mendel-ai`; Plan 1.7 Task 5 built
  `replay.py` in `mendel-resolver`.** Not the same thing — one caches model answers across
  runs, one replays recorded decisions when a bundle is edited — but close enough to become
  two ways to do one job. The second should absorb the first.
- **Plan 2 Tasks 8–10 must draft contracts *from* `ModuleSpec`**, not re-parse modules a
  second way, and a draft that fails `conformance.check` must never reach the review queue.

tag was created rather than creating an unsigned one and calling it signed. `comeni-registry`
is at its initial commit with no release tag. Configure a key and tag `v0.1.0`.

## Traps

- **A hash over concatenated fields means nothing unless each field can be read only one
  way.** Three defects, one sentence. Anything new that digests structure needs attacking,
  not testing that it works.
- **Closing an instance of a bug class is not closing the class.** Re-attack after fixing.
- **A new test that passes may be testing nothing.** The basename guard passed against the
  broken code because a name-keyed mapping is last-wins, so changing the *second* layer stays
  visible and only the *first* disappears. Run every new guard against the pre-fix code.
- **`registry/` is the layer; `examples/` holds only the goal file.** A goal inside a layer
  would be read as a contract, which is why it stayed behind.
- **The `registry/` here and `comeni-registry` are currently the same content.** Nothing yet
  keeps them in sync, and no test notices if they diverge. Whoever changes one should change
  both until that is automated.
