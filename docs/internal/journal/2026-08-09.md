## Decisions taken today

- **`MD` prefix, bands of one hundred, codes never renumbered.** `M0100`–`M0107` →
  `MD0100`–`MD0107` (94 occurrences, PR #20). Two letters because the forge and API will emit
  codes; `MD` is exactly the set of packages that may not reach the network. `MF`/`MA`/`MI`
  follow; `N`/`W` stay free so a future Nightingale API is `NA` and cannot collide.
- **Diagnostics are data**, in `comeni-core` (not the compiler — the forge and API will emit codes
  too, and one registry every `explain` reads beats one per package).
- **`{value}` starts strict** — `[A-Za-z0-9_.:+-]`, int, float, bool. Refuse, never escape.
  Loosening later is backward-compatible; tightening is not.
- **`emitted.from_digest`** — because Nextflow runs `main.nf`, not `pipeline.yml`, so editing the
  file you were told to edit and forgetting `mendel emit` diverges the run from the documentation
  with every file digest matching.
- **`verify` is `upgrade --dry-run`**, not a fifth verb.
- **`ext.when` refused** — a setting that skips a process is a second routing mechanism competing
  with resolution.
- **`sealed` blocks on `needs_review()`, not on tier** — an override *is* the review.
- **No Action commits generated docs.** A check on two lanes instead: `make check` on PRs, a
  `generated-docs` job in nightly against `main`. A bypass on a protected branch exists forever,
  and a self-healing `main` means nobody ever sees the drift.

## What a fresh reader gets wrong

**The plan is not the authority — the spec is, and the code outranks both.** Executing Tasks 1
and 2 produced three corrections to a plan written two hours earlier against the same code:

- The strict loader is `comeni_core.yaml_strict.load`, not `comeni_core.loading.load_mapping_one_way`.
  Module *and* function both wrong.
- The plan's `field_validator` snippet had a **real bug**: `UnknownDiagnosticError` subclasses
  `KeyError`, and Pydantic converts only `ValueError`/`AssertionError` into `ValidationError`, so
  the error escaped the validator raw and `except ValidationError` would have missed it.
- The generator needed to *raise* on a `concern` with no heading rather than skip it, or a whole
  category would vanish from the public table in silence.

Expect Tasks 3–12 to need the same. Every plan in this repository has.

**`CLAUDE.md`'s invariant 14 is stale.** It says "exactly two fields may hold free text";
`FREE_TEXT_FIELDS` in `tests/test_egress.py` holds **six**, and its own comment says why — A16's
split took four to six *"by a refactor rather than by a new field crossing the boundary."* Plan
1.10 Task 12 corrects it. The invariant's argument was always right; only its count is wrong.

**A14 is still open**, and 1.10 running first defers it a third time. The reason is A14's own
logic: 1.10 moves the surfaces the guards watch, so auditing them first produces ledger rows
attesting to code that has since moved — which is exactly what A14 names. Round three should not
trust a ledger row dated before 1.10 merges without re-checking that the guard still calls the
code it claims to watch. That warning is carried in the round-two brief's new *Carried forward*
