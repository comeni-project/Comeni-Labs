## The three defects it found

The port name **is** the emit label — `emit.py` reads `PROCESS.out.<from_port>` — and it is
not a name for the semantic thing, which is what `type_id` carries. Three contracts had
confused the two:

| Contract | Declared | The module emits |
|---|---|---|
| `nf-core/samtools/index` | `bai` | `index` |
| `comeni/profile/fastqc` | `read_length` | `html`, `zip` |
| `comeni/profile/collect` | `profile` | `report`, `data`, `plots` |

**All three were latent.** The emitted spine reads only `bam`, `index` and `reads`, all of
which exist, because no goal has yet routed to an index or to a profile. Each would have
failed at launch the moment one did.

The samtools case is the one to remember: the contract's own comment reads *"nf-core
SAMTOOLS_INDEX emits bai/csi/crai"*. The author had read the module and still wrote the
wrong name. Reading is not comparing.

## Corrections to the plan, all found by running it

The plan warned to expect these. Four:

1. **`_names` returned first characters.** `re.findall` with one capture group returns
   strings, not tuples, so `match[0]` gave `['m', 'r']` for
   `tuple val(meta), path(reads)`. Every name in every diagnostic would have been one
   letter.
2. **The container regex assumed nf-core's ternary.** It took the last single-quoted
   alternative, and a module that simply names its image has none — `[-1]` raised
   IndexError. That is exactly what a laboratory wrapping one container writes.
3. **M0104 reported `path(meta)`.** It looked up the documented input by
   `d.name in slot.names`, walking `meta.yml` in file order, and `meta.yml` documents `meta`
   before `fasta`. The diagnostic carried the Groovy-map description and sent the reader
   looking for a sample map where a genome was missing. It now considers only elements the
   module declares as `path`.
4. **`--root` is not `--registry`.** The plan's unverified tests passed `--root tmp_path`
   alone, which leaves no registry either, so the goal died on "n_samples is not a declared
   measurement" before conformance ran at all.

And one the plan could not have predicted, found by wiring the checker to the CLI:

5. **M0106 asserted over modules it had not read.** "No module in this registry reads this
   `meta_key`" is a claim about all of them, and it was being made when *none* could be
   read. A registry with no vendored source reported every declared `meta_key` dead and —
   since M0106 blocks — refused the build over an inference drawn from zero evidence. It
   now requires that every module was readable. This is the same rule `M0100` exists to
   state, and it is worth generalising: **a conformance check must not assert a property
   over modules it could not open.**

## Decisions, and why

**The three bad contracts were fixed, not the test weakened.** The plan's baseline test says
"if this fails, the checker or the contracts are wrong". The checker was verified against
the modules by hand first; then the contracts moved. Semantic types are untouched — only
the channel names.

**`M0100` warns, never blocks.** A laboratory wrapping a bare container has no
nf-core-style module directory. That is legitimate, so it is recorded on the IR as
`unverified` and reaches a publish bundle, where a curator may decline to curate a claim
with no evidence behind it.

**`mendel explain` loads nothing.** It is documentation. Answering only when the registry
happens to load would answer the wrong question, at exactly the moment someone needs it.

**`_meta_keys` still parses every module twice.** Marked `KNOWN AND DELIBERATE` in place
and left alone, per the plan. Free at ten modules. Whoever notices it being slow gets a real
number instead of a guess.

**The gate guard was watched failing, and watching it is what fixed it.** `Gate` is a
`StrEnum`, so `assert ..., gate` rendered as bare `"test"` — indistinguishable from the
profile it was complaining about. The message now names `Gate.TEST` explicitly. Every guard
in this repository that was not watched failing has turned out to have a hole; this one had
a smaller one, in its message rather than its logic.

**Re-measured rather than copied:** the plan's claim that `nextflow lint` accepts a
reference to a channel that does not exist while `-preview` rejects it. With
`STAR_ALIGN.out.bam` changed to `STAR_ALIGN.out.NOSUCHCHANNEL`, lint reports "6 files had no
errors" and exits `0`; preview fails naming line 26 and exits `1`. The claim holds. That is
also the M0105 class, which conformance now catches with no Nextflow at all.

## Open questions

- **Does `M0104` have a false-negative shape?** It fires on `empty` placeholders in `path`
  slots. It says nothing about a `literal` or a `ports` entry pointed at the wrong slot —
  `nf_inputs` order is checked for *count* (M0102) and never for *meaning*. A contract that
  swaps two same-width channels passes every check here and fails at run time. Not filed;
  worth a look when the registry grows past hand-written size.
- **Conformance does not run at `Registry.load`.** By design — checking is a separate stage
  so loading stays free of filesystem archaeology, and it is what lets `check` be tested
  without a CLI. But it means a caller that loads a registry without going through
  `mendel build` gets no checking at all. Plan 2.5's publish path must call it explicitly.
- Carried forward, unchanged: the review queue at scale, structured quasi-identifiers in
  measurement declarations, and the docs still promising three protection profiles ahead of
  the plan ([#7](https://github.com/comeni-project/Comeni-Labs/issues/7)).

## Traps

- **The port name is the emit label, not a name for the thing.** `produces[].name` is read
  as `PROCESS.out.<name>`; `type_id` is what carries the meaning. Three contracts confused
  these, and all three read plausibly.
- **`--root` and `--registry` are different flags for different things.** `--registry` is
  where contracts live; `--root` is where module *source* lives, at `<root>/vendor`. The
  plan's own tests conflated them.
- **A conformance check must not assert over modules it could not open.** M0106 did, and
  refused correct builds. Any new check needs the same question asked of it.
- **`ModuleSpec` must not move to `comeni-core`.** `re` is not on the core's allowlist and
  the guard is right — the core must not know what Nextflow is, because its IR is the
  platform-neutral interface Wiener will consume. This is the kind of thing an implementer
  "corrects" on the way past.
- **`gate stub: PASS` still means the DAG executes and nothing more.** Conformance closes a
  different class. Neither is the other.
