## What Plan 1.5 found

Five defects, and **not one was reachable by any test that existed**. The through-line:
`-stub-run` proves the DAG executes, and nf-core stubs never read their inputs, so
anything about *what a process is actually handed* is invisible to it.

1. **No reference genome in the type system.** `genome.fasta` was not a declared type, so
   both index builders were called with an empty tuple where the reference belongs. You
   cannot build an aligner index without a genome. (`53642bc`)
2. **`STAR_ALIGN` handed an empty GTF** while `ch_annotation_gtf` sat in the same workflow
   feeding featureCounts two lines below. (`53642bc`)
3. **A test profile cannot glob over https.** `fromFilePairs` brace-expands by listing,
   which no HTTP endpoint supports. Found by running it. (`59f3f0e`)
4. **`Gate.TEST` never used containers.** It ran `-profile test` while `Gate.STUB` ran
   `-profile stub_data,docker`, so every process died with `command not found`. The gate
   had never been executed, so nothing noticed. (`f93b4df`)
5. **`PipelineIR` did not deserialise.** `review_level` is a `computed_field`, written on
   dump and refused on load by `extra="forbid"`. Nothing had read an IR back yet — but
   `mendel upgrade` reads a `PublishBundle` off disk (Plan 2.5) and the repair loop reads
   back an IR it sent (Plan 2). Both would have failed on a field the class computes for
   itself. (`557ab68`)

And the one that motivated the plan: **a resolved parameter reached no tool at all.**
`params.subread_featurecounts_strandedness = 2` was emitted and referenced by nothing.

## Decisions, and why

**Emptiness and deadness are different problems, and only one was in scope.** The registry
has three parameters and no defaults — that is *emptiness*, it is the forge's job, and
hand-authoring a registry was never the plan. A resolved value reaching no tool is
*deadness*, and no amount of forge output fixes it. Plan 1.5 fixed deadness only.

**Measured facts travel in `meta`; Mendel does not translate for tools.** nf-core modules
already contain their own encodings — `SUBREAD_FEATURECOUNTS` has
`if (meta.strandedness == 'reverse') { strandedness = 2 }` in its script block. Mendel
carries the fact and the module keeps the encoding. Measurements declare `describes`,
`meta_key` and optional `meta_values` (we ask `paired`, nf-core asks `single_end` — the
same fact spelled inside out).

**The strandedness rule was deleted, not wired.** Given `strandedness: reverse`, `-s 2` is
not a decision — it is the only correct answer, and the "citation" was the featureCounts
manual. It was a translation wearing a tier-3 badge. `examples/rules/rnaseq.yml` now holds
**one** decision, `producer_of: alignment.bam`, which is genuine: two defensible aligners,
the data picks one, Dobin et al. is a real citation for a real claim.

**`ext_args` carries no tier.** A tier is for a decision. `--readFilesCommand zcat` is
forced by TrimGalore emitting `.fq.gz`. Labelling it tier 1 would be defensible and would
dilute what a tier means, which is the one thing this project sells.

**`Param` was deliberately left untouched.** See below.

## What is next

### 1. Merge `runnable-spine`

Five commits, unpushed. Closes [#8](https://github.com/comeni-project/Comeni-Labs/issues/8).
CI has never seen them.

### 2. Revise the v1 criterion, or close it

Of its four clauses: `-profile test` runs green ✅, a counts matrix is produced ✅, the
plain-language prompt is Plan 2, and the module count is **10 distinct processes against a
15–20 target**.

The remaining canonical processes are QC breadth — `samtools stats`/`flagstat`/`idxstats`,
duplicate marking, `qualimap`, `rseqc`, `dupradar`, `preseq` — plus reference preparation.
None is needed for a correct counts matrix. **Do not treat breadth as the blocker:** a
pipeline with twenty modules that ignores every parameter is worse than one with ten that
does not. Either add them deliberately or revise the number.

### 3. Plan 2.5 — publication and the registry split

Written, nine tasks, ready. Now safe to run: it would have been publishing bundles built on
a spine that counted wrongly, through the door with no undo.

### 4. Plan 2 — AI adapters and the forge, now with Task 11

Task 11 was added yesterday: **parameter coverage drafted from `conf/modules.config`**.
`nf-core/rnaseq` 3.14.0's is 1167 lines, 78 `withName` blocks, 44 `ext.args`, many of them
Groovy ternaries — decision tables compiled into Groovy with their provenance lost. Across
nf-core's pipelines that is thousands of parameter decisions made by domain experts,
reviewed in PRs, released under DOIs. **That is the tier-2 corpus.**

`Param`'s domain and expression get designed *there*, against that corpus. Plan 1.5 left
`Param` alone for exactly this reason: the registry contains one genuinely chosen parameter
(`seq_platform`, tier 4, still reaching nothing), and designing a model from a sample of one
is how three plans in a row produced steps that did not survive contact with the code.

## Open questions

- **`seq_platform` is flagged at tier 4 and still reaches no tool.** Honest — it is
  genuinely unanswered — but it means one flagged decision has no effect until Plan 2
  Task 11. Recorded rather than quietly deleted.
- **The review queue at scale.** 200 modules is roughly 800 parameters; nobody writes 800
  rules, so decisions land at tier 4 correctly and honestly, and a review list with 200
  entries is equivalent to no review list. **This is the real scaling risk, and it is not
  determinism** — determinism is a property of resolution being a pure function over
  declared data and does not degrade with module count. Not filed.
- **Structured quasi-identifiers in measurement declarations.** The no-`string` rule blocks
  free text; it does not block `patient_age: integer` or `collection_date`. Harmless while
  `DataProfile` is study-level, dangerous the moment a clinical lab runs one goal per
  patient. Not filed.
- **Docs still promise three protection profiles** while v1's answer is "run the agent
  locally" ([#7](https://github.com/comeni-project/Comeni-Labs/issues/7)). Ahead of the
  plan, and in a public repo it reads as a promise.

## Traps

- **`gate stub: PASS` means the DAG executes and nothing more.** Five defects hid behind
  it. `NfInput.empty` now requires a `because`, and only `--gate test` catches the rest.
- **A resolved value needs somewhere to go.** nf-core modules read `task.ext.args` and
  `meta`. A `params.<x>` in the emitted workflow is read by nothing.
- **Do not re-add a rule that translates.** If a module already contains the encoding, the
  rule is not a decision. Check the module's script block before writing one.
- **Two plans share the date `2026-08-04`.** Filenames are a log; the execution order is
  the table in [`docs/internal/README.md`](../README.md).
- **`make check` no longer runs everything.** The slow tests are excluded by an `addopts`
  marker filter and run nightly. `uv run pytest -m slow` runs them locally.
