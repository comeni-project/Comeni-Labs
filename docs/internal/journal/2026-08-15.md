## The number that matters

**One in six became six in six.**

The design audit's sharpest finding was that of the six values reaching the generated Nextflow,
**five carried no `why:` at all** — including `strandedness: reverse`, which becomes
featureCounts' `-s 2` and is the flag this repository uses as its own worked example of the
system working. Every one of the six now carries a reason a reader can act on:

```
OK  star_align.ext_args            = '--readFilesCommand zcat'
OK  star_align.star_ignore_sjdbgtf = False
OK  samtools_sort.index_format     = 'bai'
OK  subread_featurecounts.min_mqs  = 0
OK  meta.single_end                = False
OK  meta.strandedness              = 'reverse'
```

The artifact's own header says *"Every value carries a `why:`"*. **It was false when it was
written and it is now true**, which is the one sentence in this plan worth keeping.

Two of those reasons are worth reading in full. `strandedness` now says it was **asserted, not
measured**, and cites Signal et al. 2022 — the citation the measurement always declared and never
reached the page. And the shipped registry no longer cites the STAR paper as the reason HISAT2
was chosen: the block's Dobin citation justifies the *axis* (read length decides the aligner),
and each row cites its own tool.

## What the guards did, which is again the part worth reading

**Eight guards failed unprompted across the plan** — none staged, all caught during ordinary
`make verify` runs. Three are worth naming:

- **A38's `Via` tripwire** failed the instant `Via.POSITIONAL` existed, before any of Task 7's
  own tests were written. It exists so that adding a member forces a decision — wire it into
  `emit.py` or refuse it at load — and it did precisely that, two plans after somebody built it.
  Updating it was a deliberate edit with a stated reason, not a widening.
- **The committed v1 fixture caught a second, unrelated break.** Landed in Task 0 for a digest
  test, it caught Task 2 making `MetaEntry.why` required — which is right for construction and
  wrong for *reading*, since a document written before the field existed cannot answer. Requiring
  it of one asserts the provenance is *missing* rather than *never recorded*.
- **`test_a_binding_with_no_declared_param_…` asserts its own fixture's premise** — *"the fixture
  needs a param-less one"* — and caught `samtools/sort` ceasing to be param-less. Naming a
  requirement rather than assuming it turned a confusing failure into one line.

**And one inert guard was found in code written the same hour** (Task 0). The schema check went
into two places; reverting the `is_stale` half changed nothing, because `upgrade` returns at the
`cli` branch and never reaches it. That half was protecting `emit` — the one verb whose job is to
cure staleness — and nothing tested it. The "nothing failed" row is kept in the ledger beside the
test that closes it, because that row is the more useful of the two.

## Two things that came apart, and both are lessons about closing findings

**"The test passes" and "the finding is closed" are different claims (Task 6).** A76 is that a
value moving 0 → 30 produces a byte-identical `why:`. Task 1's `for_value` made the two blocks
differ, so the headline assertion **passed on arrival** — before Task 6 changed anything. What
was still broken was the part a reader needs: `from_layer: null` on a value an overlay supplied,
and a reason that justified nothing. One assertion instead of four and A76 would have been ticked
at Task 1.

**A diagnostic that contradicts the documentation cannot be followed (Task 8).** Writing A77's
test walked into A112 before the task reached it: `MD0220` said *"set the decision's
human_override to the value"* while `pipeline-schema.md` said *"it is not where you write one"*
two paragraphs above. The test could not be written correctly by following the diagnostic. Both
now say the same thing.

## The free-text count, and the first increase that was not a refactor

Invariant 14's literal list went from seven to **ten**, in two steps, and the egress guard forced
both to be argued rather than absorbed. The `axis_reason` pair is a refactor — one field
splitting in two, same author, same door. **`override_reason` is not**: it is written by the
person answering a tier-4 question, in the artifact, after resolution — a new author at a new
moment, and the first such in the system's history. `CLAUDE.md`'s claim that every increase had
been a refactor was true when written and is now false; it was corrected rather than absorbed,
which is A33's own lesson applied to A33's own paragraph.
