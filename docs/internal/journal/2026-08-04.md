## Decisions made, and why

**v1 safety is a deployment question, not machinery.** If you need safety, run the agent
locally. This collapses the three protection profiles into one question a laboratory can
actually answer — where does the model run — instead of a matrix they must configure. It
also means `guarded`, `sealed` and `ProfilePolicy` do not need to ship for v1. Recorded on
[#7](https://github.com/comeni-project/Comeni-Labs/issues/7). Consistent with invariant 13:
local is the *safe* configuration, not the *lesser* one.

**Goal extraction will not be deterministic, and we should not try.** Prose → intent is
what models are for. The useful reframing: determinism does not own the extraction, it owns
the **acceptance** — the model proposes a `Goal` and `extra="forbid"`, the measurement
declarations, the vocabulary and the router either accept it or refuse it loudly. The
output is checkable. The *input* is the exposure, and it has already crossed before
anything can validate it. Full design space on [#7](https://github.com/comeni-project/Comeni-Labs/issues/7).

**auto-phylo / auto-phylo-pipeliner is not discussed anywhere in this repository.**
Operator's decision, made deliberately before going public. `pegi3s` appears only as what
is useful about it — a repository of ~190 containerised tools with documentation, and a
future forge ingestion source. Do not reintroduce a comparison.

**`ruff format` is not a gate.** 28 files are hand-wrapped in ways the formatter would
undo. A formatting sweep belongs in its own reviewable commit, not as noise on every future
PR. `ruff check` is the gate.

**Journal over status file.** See [README.md](README.md).

## What is next

Recommended order, and the order matters.

### 1. Prove the spine on real data — before Plan 2

**This is the biggest open risk in the project and it needs no AI.**

`gates.py:21-25` says it outright: `emit_config` deliberately does not emit a `test`
profile, because a real one needs real reference data and shipping fixtures as if they
demonstrated biological correctness would be the dishonest kind of green. Correct decision.
The consequence is that **`Gate.TEST` has never passed and cannot currently pass**, and
nothing has ever verified the emitted pipeline produces a correct counts matrix.

`-stub-run` proves the DAG executes and the channels line up. It proves nothing about
whether STAR and featureCounts agree on real reads, because nf-core stubs never read their
inputs. Plan 1 is a **verified compiler, not a verified pipeline** — different claims, and
the second is the one a biologist will judge.

Do this before layering prompt extraction on top, because if the spine produces an empty or
wrong matrix you want to know now. It will probably also surface the missing modules (see
below), since the gap between 10 and 15–20 is likely to be exactly what a real run needs.

**Not yet filed as an issue.** File it or just do it.

### 2. Close the gap to the v1 criterion

The criterion in `CLAUDE.md` reads: *"From a plain-language prompt plus a test dataset,
Mendel emits Nextflow that runs green on the nf-core test profile and produces a counts
matrix… ~15–20 modules."*

| Requirement | Status |
|---|---|
| plain-language prompt | Plan 2 Task 3 |
| runs green on `-profile test` | never run, not currently runnable — see above |
| produces a counts matrix | never produced |
| ~15–20 modules | **10 distinct processes** (12 contracts; `FASTQC` and `MULTIQC` each appear twice because of the profiling contracts) |

Either close the gap or revise the criterion. Do not leave it stated in terms of a gate
that cannot pass.

### 3. Plan 2 — `mendel-ai` and the forge (13 tasks)

Two halves that share a plan:

- **The three AI doors** — `1A` protection profiles, egress records, prompt store (first,
  because Task 1 cannot log a crossing with no record type) · `1` LiteLLM client ·
  `2` remaining ports · `3` prompt → `Goal` extraction · `4` decision store with replay ·
  `5` LLM ambiguity resolver · `6` repair, bounded to 3 · `6B` gate-failure classification ·
  `7` CLI wiring — **`--no-ai` arrives here**
- **The forge** — `8` nf-core `meta.yml` ingestion · `9` contract drafting and the approval
  queue · `10` vocabulary state proposals

Given the v1 decision above, Task 1A shrinks: the local-endpoint lane is the whole plan,
not one option among three.

### 4. Plan 3 — `mendel-api` and dashboard (9 tasks)

FastAPI + Postgres + ARQ + SSE (1–5), then a Vite/React SPA consuming a TypeScript client
generated from `openapi.json` (6–9). The dashboard renders the IR directly — every node
already carries its tier and review level, so there is no separate explanation layer.

### Also writable now: Plan 2.5

Deliberately unwritten until its types existed. They exist. Federation §8: lockfiles,
`mendel publish`, `mendel upgrade`, the pipeline catalogue, and splitting the registry out
of `examples/`.

## Open questions

- **Structured quasi-identifiers in measurement declarations.** The no-`string` rule blocks
  free text; it does not block `patient_age: integer`, `collection_date`, `postcode: enum`.
  Sweeney's {ZIP, gender, DOB} are all valid declarations today. Harmless while
  `DataProfile` is study-level — but a clinical lab running **one goal per patient** turns
  the profile into a per-patient record that crosses the tier-4 and publication doors.
  **Not filed.**
- **`mendel detect`** — a local, AI-free scanner that pre-fills a typed goal from a
  directory (`have` from file types, `paired`/`n_samples`/`read_length` from a cheap pass,
  states from a BAM header). Reduces how much the prompt has to carry, which is a privacy
  measure and not only an ergonomic one. Named inside
  [#7](https://github.com/comeni-project/Comeni-Labs/issues/7); parked deliberately as a
  separate part of the program.
- **Docs promise three protection profiles.** `docs/concepts/privacy-and-egress.md`,
  `docs/design/clinical-data-protection.md` and the table in `CLAUDE.md` present all three
  as coming. True when written, now ahead of the plan, and in a public repository it reads
  as a promise. Worth a pass.
- **No release tagged.** `CHANGELOG.md` describes `0.1.0` and links a comparison URL, but
  no git tag or GitHub release exists.

## Traps

Things a fresh reader gets wrong. The [gotchas in `CLAUDE.md`](../../../CLAUDE.md) cover
the code; these are about the project.

- **`gate stub: PASS` is not "it works".** It is "the DAG executes". See item 1 above.
- **`examples/` is not a registry.** It is hand-written test data. The real registry moves
  to `comeni-registry` at Plan 2.5. Do not add contracts there expecting them to ship.
- **Plans 2 and 3 predate the types they reference** and say things that are no longer
  true. `docs/internal/README.md` labels them for this reason. Read them for intent, verify
  every type against the code.
- **Work in a worktree, not the main checkout.** It is in `CLAUDE.md` as a convention; this
  session it caught a real bug that the main checkout structurally could not surface.
- **Do not farm implementation out to subagents.** Operator's instruction. Subagents are
  for review and design.
