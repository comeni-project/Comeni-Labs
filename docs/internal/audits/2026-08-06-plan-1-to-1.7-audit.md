> **The pattern, stated once.** Every guard reasons about the *surface it was written
> against*. The purity guard checks import **statements**, so attribute reachability and
> `exec` walk past it. The egress guard checks `dict`/`str`/`Any` **shapes**, so `Mapping`,
> `bytes` and an unconstrained `Annotated[str, ...]` walk past it. The construction guard
> greps for the **text** `DataProfile(`, so `model_validate` walks past it. The right
> question for the next guard is not "does this catch the bug I have" but **"what shape of
> violation does my break-test not have?"**

## Critical

### ⬜ A1. The purity guard does not enforce invariant 1; a pure package can shell out

`tests/test_purity.py`

Invariant 1 and CLAUDE.md's telemetry claim are both stated as *structural*: "the pure
packages cannot import an HTTP client, so telemetry can only live in `mendel-api`." That is
false. The guard is a static AST scan that flags banned **import statements** and calls to
`__import__`/`importlib.import_module`. It never reasons about modules reached as
**attributes of allowed ones**, and `exec` is a builtin needing no import at all.

Verified first-hand on the unmodified tree:

```
pathlib.os          -> <module 'os' (frozen)>
os.system reachable -> True
exec-import works   -> urllib.request
```

So a file in `comeni-core` importing only `pathlib` and `typing` — both allowlisted — can
call `pathlib.os.system(...)` to shell out, or `exec("import urllib.request as m")` to obtain
any module in the standard library. The reviewer demonstrated a `telemetry.py` inside
`comeni-core` that opened a TCP socket to a local collector and delivered a serialised
`Goal`, with `tests/test_purity.py` green.

**One correction to the reviewer's mechanism, kept because it matters.** They reported
`socket` as already present in `sys.modules`, reachable via `typing.sys.modules["socket"]`.
On this tree it is **not** (`socket preloaded -> False`), so that specific route raises
`KeyError`. The conclusion is unaffected — `pathlib.os.system` and `exec` both work — but the
route is different from the one reported, which is why subagent findings get re-run rather
than believed.

**Fix designed, not applied.** An allowlist over import *names* cannot express this, because
the problem is not what is imported but what is *reachable*. Options in D3.

### ⬜ A2. `Goal.model_validate` builds an unvalidated `DataProfile`, and `resolve()` never re-checks

`tests/test_construction.py`, `comeni_core/profile.py`, `mendel_resolver/resolve.py`

CLAUDE.md invariant 15 says:

> *"`MeasurementRegistry.profile()` is the only validating constructor,
> `tests/test_construction.py` enforces that nothing else builds a `DataProfile`, and `mendel
> build` re-routes every goal's profile through it. Delete that one call and `profile:
> {sample_name: ...}` builds cleanly — which is how it was watched failing."*

You do not have to delete anything. `test_construction.py` is an AST scan for a literal
`DataProfile(` call, and pydantic's `model_validate` is neither. Verified first-hand, public
API only, no code changes:

```
Goal.model_validate({"profile": {"sample_name": "PT-4471023", "organism": "patient tumour"}})
  -> [('organism', 'patient tumour'), ('sample_name', 'PT-4471023')]
```

`sample_name` is the exact example CLAUDE.md uses for what must be impossible. The
mapping-shorthand validator only *reshapes*; it never consults a registry.

The CLI's re-route (`cli.py`) does validate, so `mendel build` is safe — but that is an
application-layer step in `mendel-compiler`, not a property of the type. **Every other caller
is unprotected**, and `resolve()` copies the profile into the IR with no re-validation:

```
resolve(tainted_goal, registry, rules)
  IR.profile carries -> [('organism', 'patient PT-4471023 tumour; BRCA1 c.68_69del')]
```

From there it reaches `PublishBundle`. The unprotected callers are not hypothetical: the
resolver's own public API, `mendel-api` when Plan 3 builds it, and any library user.

**And one of them is a shipped CLI verb.** `mendel upgrade` takes its goal from the bundle
rather than from a file, so it never reaches the re-route that protects `build` and
`publish` — a gap in code I wrote in Plan 1.7 Task 7. Reproduced end to end against a bundle
carrying an undeclared measurement:

```
$ mendel upgrade --bundle tainted.bundle.json --out prof-up
exit code: 0
undeclared 'sample_name' reached the new IR: True
  [{'measurement': 'sample_name', 'value': 'PT-4471023', 'source': 'goal', 'by': None}]
```

No validation, no warning, and the result is a fresh bundle carrying it. That the CLI is the
only thing enforcing invariant 15 is exactly why enforcing it in the CLI is the wrong place:
the next verb forgets.

### ⬜ A3. Arbitrary strings — including paths and diagnoses — reach a published bundle

`comeni_core/marks.py`, `comeni_core/goal.py`, `tests/test_egress.py`

The 2026-08-03 audit's C3 reported this and it was recorded fixed. It was fixed in **shape**,
not in **substance**: the open `dict[str, Any]` is gone, so arbitrary *keys* are impossible.
Arbitrary *values* are not. `ParamValue` is
`int | float | bool | Annotated[str, ParamLiteral] | None`, and the egress guard exempts
anything carrying `__metadata__` — treating "has a label" as equivalent to "has a closed
domain". `ParamLiteral` has a label and no domain.

**Reachable today with no code change at all.** `DecisionRecord.chosen`, `.candidates[*]` and
`.human_override` are all `ParamValue` and all sit inside `PublishBundle`:

```json
"human_override": "diagnosis: BRCA1 c.68_69del pathogenic carrier"
```

`human_override` is the sharpest case: it is by design the slot for a human's answer, and it
is an unbounded string in the door with no undo.

**Three further routes, same root cause**, found separately:

1. **A parameter override.** `constraints.params[].value` accepts a path, which reaches
   `main.nf` (`params.star_align_seq_platform = '/data/patients/PT-4471023/S1_R1.fastq.gz'`),
   the IR and the bundle — *and prints `0 requiring review`*, because a goal override is
   tier 1, so it suppresses the tier-4 flag it replaced. False assurance arriving through the
   review mechanism.
2. **An unused `have` entry.** `GoalInput.type_id` is a `TypeId`, which validates nothing. A
   goal listing a path beside its real inputs builds normally — the entry is never needed —
   and the path lands in the bundle. Indistinguishable from a clean build.
3. **A layer directory name.** `--registry ./PT-4471023-overlay` puts that name into
   `registry_layers`, `LockedLayer.name`, the bundle and the lockfile. Introduced by Plan 1.7,
   by me, while reasoning that a name is safer than a path. It is safer, and still arbitrary.

**The root cause.** `Annotated[str, "..."]` is a **label, not a validator** — it constrains
nothing at runtime. This is true of every alias in `marks.py`: `ContractId`, `NodeId`,
`PortName`, `Subject`, `ResolverId`, `MeasurementId`, `TypeId`, `LayerName`, `Digest`,
`ModuleKey`, `ContainerRef`. The guard checks that strings are *named*, not that they are
*bounded*.

### ⬜ A4. A contract can point channels at the wrong inputs and pass every static check

`mendel_compiler/conformance.py`

`nf_inputs` is checked for **count** (M0102) and each placeholder's **width** (M0103), never
for **meaning**. Swapping two same-width channels passes clean. Reproduced against
`star/align`, whose slot 1 is the genome index and slot 2 the GTF, both `tuple val(_), path(_)`:

```
conformance:   clean, no diagnostics
gate lint:     PASS
gate preview:  PASS
```

```groovy
// swapped
STAR_ALIGN(TRIMGALORE.out.reads, ch_annotation_gtf, STAR_GENOMEGENERATE.out.index, false)
// correct
STAR_ALIGN(TRIMGALORE.out.reads, STAR_GENOMEGENERATE.out.index, ch_annotation_gtf, false)
```

`--gate test` **does** catch it (STAR exits `FATAL ERROR`), so it is caught nightly and is
invisible to conformance, `lint`, `preview` and `stub`. A laboratory running
`make check && make static && make stub` before publishing would ship it, and `mendel publish`
does not run `--gate test`.

Same class as the Plan 1.5 defect — *"a process handed an empty tuple where a genome belongs
is exactly as green as one handed a genome"* — still open for **swapped** rather than
**empty**. Named as an open question in the 2026-08-05 journal; now demonstrated.

**Fix designed, not applied.** nf-core names slots after what they carry and `meta.yml`
documents them; `InputSlot.names` already captures it. Compare the slot's element name against
the `type_id` mapped into it and flag an assignment that is **worse than an available
permutation** — testing permutations rather than absolute name matching is what keeps false
positives down, because the claim becomes "swapping two of these would match better", which is
the defect and nothing else.

### ⬜ A5. An installed overlay reroutes a pipeline silently

`mendel_resolver/router.py`, `comeni_core/ir.py`

Invariant 11 ends: **"Never let an installed overlay reroute a pipeline silently."** It does.

An overlay contract with a *different module key* is by definition not a shadow, so no
`ShadowRecord` is written. Winning on priority rather than tying means invariant 8 never fires
either — it is not ambiguity, it is a clean win, classified **tier 2 (convention), review
`none`**. Reproduced with a rival sorter at priority 99:

```
modules:        [... 'lab/rival/sorter@9.9.9' ...]   # replaced nf-core/samtools/sort
shadow records: []
needs_review:   ['star_align.seq_platform']          # the sorter is absent
selection:      tier=2 review=none
                reason='registry priority 99, over nf-core/samtools/sort@1.21.0'
```

The build output is indistinguishable from normal. The gap is between two documented rules:
invariant 11 says *never silently*, invariant 8 covers *ties*, and a priority win is neither.
The aligner escapes only because a rule pins it — luck, not design.

**Fix designed, not applied.** When a node's winning contract comes from a layer other than
the lowest, say so on stderr and in `needs_review()`, shadow or not. The information exists in
`selection.reason` and `registry_layers`; only the surfacing is missing.

### ⬜ A8. A resolved routing decision never reaches the pipeline; the record can contradict it

`mendel_resolver/router.py:211-224`, `mendel_resolver/resolve.py:85-97`, `resolve.py:152-172`

Invariant 9: *"Every ambiguity emits a `DecisionRecord`. Records are replayed on rerun rather
than re-asking the model — that is how determinism survives having a model in the loop."*
Records are emitted and replayed. **Their answers are then discarded for everything except
parameters.**

`_choose` picks `ordered[0]` by id order, appends an `Ambiguity` to `plan.ambiguities`, and
returns. The resolver is not consulted. Only afterwards — the loop over `plan.ambiguities` at
`resolve.py:85` — is `resolver.resolve(ambiguity)` called, and its `resolution.chosen` goes
into a `DecisionRecord` and **nowhere else**. `ir.nodes` and `ir.edges` are already built.

`_source_for` has the same defect in a more explicit form: it calls the resolver at line 160
and then writes `chosen=f"{chosen[0]}.{chosen[1]}"` — the locally computed `equally_good[-1]`,
not `resolution.chosen`. The resolver's answer is overwritten in the very statement that
records it.

Three consequences, in increasing order of seriousness:

1. **`ReplayResolver` cannot replay a module choice.** Plan 1.7's headline — "editing a curated
   pipeline replays every untouched decision, so only what you touched can move" — holds for
   parameters only. A recorded producer choice replays into a record that changes nothing.
2. **A `human_override` on a producer or a channel source is accepted, recorded, and ignored.**
   The reviewer's correction is stored in the bundle as though it took effect.
3. **The `DecisionRecord` can state something the pipeline does not do.** Nothing forces
   `record.chosen` to equal the contract in `IRNode.selection`. A published bundle is supposed
   to be the auditable object; here it can be an auditable object that is wrong. That is worse
   than the missing capability, because a reader has no way to notice.

Reproduced by reading the two call sites and confirmed by the flow: no assignment to
`node.contract_id`, `node.selection` or any `IREdge` occurs after `resolver.resolve` in either
site. Note that today's only shipped resolver is `FlagOnlyResolver`, which returns the same
candidate the code already picked, so **nothing is currently wrong in output** — the defect is
that the mechanism Plan 2 is about to plug a model into is not connected.

**Fix designed, not applied.** Resolve routing ambiguities *inside* `_choose`, before the
subtree is routed, and have `_source_for` use `resolution.chosen` to select from
`equally_good`. Both need the resolver threaded through `route()`, which today takes none. A
test asserting `record.chosen == ir.node(record.node_id).selection.value` for every
producer-subject record would have caught this on the day it was written.

### ⬜ A9. A symlinked contract is loaded by the registry and excluded from the layer digest

`comeni_core/digest.py:73-84`, `comeni_core/registry.py:64-65`

The symlink hardening added in Plan 1.7 hashes a link as its **target path**, never following
it — correct for a link pointing out of the layer, and what git does. But `Registry.load` opens
that same path with `read_text()`, which **does** follow it. So the bytes the registry routes
on and the bytes the digest covers are different bytes.

Reproduced end to end on a copy of `registry/` with one contract replaced by a symlink to a
file outside the layer:

```
layer digest before : sha256:6f19427a912de864e6c9914ff330e56c92061e8b0670bb153772a772e4d53917
layer digest after  : sha256:6f19427a912de864e6c9914ff330e56c92061e8b0670bb153772a772e4d53917
DIGEST UNCHANGED    : True
priority the registry actually loaded: 999
```

A priority bump large enough to win every routing contest, with a byte-identical layer digest
and therefore **zero drift from `mendel upgrade`**. This is invariant 11's closing sentence —
"never let an installed overlay reroute a pipeline silently" — defeated by the mechanism built
to prevent it, and it is worse than A5 because A5 at least changes the lockfile.

A symlinked *directory* is consistent rather than exploitable: `rglob` does not descend into
one, so neither the digest nor `Registry.load` sees anything inside it. Verified.

**Fix designed, not applied.** The digest and the loader must agree. Either refuse a symlink
inside a layer outright — a layer is a distributable unit and a link out of it is already
meaningless to whoever receives it — or resolve and hash the target's *content* under the
`_FILE` tag when the target is inside the layer, and refuse when it is not. Refusing is
smaller, more honest, and gives a message at load time instead of a wrong digest at publish
time.

### ⬜ A10. `digest_of` pins the parsed model, not the file, and six contract models drop unknown keys

`comeni_core/digest.py:32-40`, `comeni_core/contract.py`

`digest_of` hashes `model.model_dump_json()`. Only `Alternative` sets
`model_config = ConfigDict(extra="forbid")`; `InputPort`, `OutputPort`, `Param`, `NfInput`,
`Provenance` and `ModuleContract` do not. Pydantic's default is `ignore`, so an unknown key is
dropped at parse and cannot appear in the dump. Two materially different files therefore pin
identically:

```
digest equal: True
sha256:57eaa443df733acad5f312b154c4ac889a371facd3e7c407c151d246500ffe4d
```

— one file being the real contract, the other the same contract plus a top-level key and an
extra key on its first `Param`.

The lockfile's promise is *"this pipeline was built against exactly this contract"*, and it
cannot keep it against a file it has not hashed. There is a second, larger cost that has
nothing to do with lockfiles: **a misspelled key in a contract loads clean**. `ext_arg:` for
`ext_args:`, `state:` for `states:` — the contract is accepted, behaves differently from what
it says, and nothing in conformance checking looks for it, because conformance compares a
contract to its module and this is the contract disagreeing with itself.

**Fix designed, not applied.** `extra="forbid"` on all six. That is the same rule
`ShadowRecord` was given in Plan 1.7 for the same reason, so this is closing the class rather
than another instance — the recurring lesson of this audit. It will reject any contract in the
wild carrying a comment key, which is the point.

## Important

### ⬜ A6. `Mapping` and `bytes` walk through the egress shape rules

`tests/test_egress.py`

Two types the guard was never written against:

- **`collections.abc.Mapping`.** `_mentions_mapping` tests `issubclass(origin, dict)`, and
  `Mapping` is a **superclass** of `dict`, not a subclass — verified: `issubclass(Mapping,
  dict) -> False`. A field typed `Mapping[MeasurementId, ParamValue]` is a real dict at
  runtime with arbitrary undeclared keys, which is precisely the `{"patient_id": ...}` case
  the guard's own docstring claims to forbid. `collections.abc` is on `mendel-resolver`'s
  allowlist. The reviewer added such a field to the real `PublishBundle`; the guard stayed
  green and the bundle serialised `{'patient_id': 'PT-4471023', ...}`.
- **`bytes`.** Not `str`, not `dict`, not `Any`, no `FreeText` marker — and
  `bytes`/`bytearray`/`memoryview` appear nowhere in the guard. A `bytes` field on
  `PublishBundle` carried and serialised free text with all seven tests green.

Neither is currently *present* in a payload, so nothing is leaking today. Both are one
plausible field away — a `signature: bytes` on a lockfile is an obvious future addition, and
A1's D3 discussion makes an attribution mapping tempting.

### ⬜ A11. A duplicate parameter name crashes the emitter with an uncaught `TypeError`

`comeni_core/ir.py:114`, `mendel_compiler/emit.py:194`

`IRNode.set_param` appends unconditionally, `resolve()` calls it once per entry in
`contract.params`, and nothing rejects two entries with the same `name` — not
`ModuleContract.model_validate`, not `check_against`, not conformance checking. The emitter
then does `sorted((b.name, b.value) for b in node.params)`, which on a name tie falls through
to comparing two `ResolvedValue`s:

```
loaded OK with duplicate param names: ['seq_platform', 'seq_platform']
EMIT RAISED TypeError: '<' not supported between instances of 'ResolvedValue' and 'ResolvedValue'
```

Reproduced against the real `nf-core/hisat2-align.yml` with its one param duplicated. A
hand-authored or forge-drafted contract with a copy-pasted param gets a traceback from the
middle of the compiler rather than a diagnostic — the failure mode `mendel explain` exists to
replace. Note the near miss: with unique names the value is never compared, so this is
invisible until the day it is not.

`Registry.load` already refuses a contract ID declared twice in one layer, and for the stated
reason — resolving it by glob order would be a silent arbitrary pick. The same argument applies
one level down and was not made there.

**Fix designed, not applied.** A model validator on `ModuleContract` rejecting duplicate param
names, and `sorted(..., key=lambda pair: pair[0])` in the emitter so a tie can never reach an
unorderable comparison. Both — the first is the real fix, the second means the next unorderable
field does not resurrect it.

### ⬜ A13. A `DataProfile` accepts duplicate measurements, and `get` is first-wins

`comeni_core/profile.py:64-67`, `comeni_core/measurement.py:179-200`

`MeasurementRegistry.profile()` takes a `dict` and sorts it, so the validated path is
normalised and deduplicated by construction. `DataProfile.model_validate` with an explicit
`measurements:` list is neither. `get` then returns the **first** match:

```
A get(strandedness): reverse
B get(strandedness): unstranded
duplicates accepted: 2
same JSON? False
```

— two profiles asserting the same set of facts, differing only in list order, resolving
differently. Every tier-3 rule reads through `get`, so this reaches module selection and
parameter values, and therefore the emitted `.nf`.

Invariant 10 survives literally — the same `Goal` still gives byte-identical output — but the
property people will rely on is that the same *facts* give the same pipeline, and that is
false. The reachable route is A2's: `mendel upgrade` takes `previous.goal` verbatim, so a
bundle's profile never passes through the constructor that would have normalised it. A library
caller building a `Goal` directly has the same gap.

**Fix designed, not applied.** A model validator on `DataProfile` rejecting a repeated
`measurement` and sorting the list, so the validated and the deserialised paths produce the
same object. That is where the normalisation `profile()` already does belongs — in the type,
not in one of its two constructors. Same shape of fix as A2 and for the same reason.

## Clean — attacked and held

Recorded because a clean result is a real result, and these are the properties most likely to
be assumed rather than checked next time.

- **Groovy injection from registry data.** Registry layers are distributable now, so a
  contract is attacker-controlled input to the emitter. Quote break-outs in `ext_args` are
  escaped into an inert string literal; control characters are refused outright
  (`ValueError: control character in parameter value`); container break-outs did not reach the
  output.
- **Replay integrity.** A replayed tier-4 decision **stays tier 4 and stays flagged**. A
  forged `human_override` naming something that is not a current candidate is rejected by
  `_still_applies` and falls through to a fresh decision (`0 decisions replayed, 1 newly
  asked`); the forged value does not reach the IR. (A3 is about *what a string may contain*,
  not about replay letting an invalid one through.)
- **The egress transitive walk itself.** `_payload_types()` genuinely expands every nested
  `BaseModel` — `Goal`, `Constraints`, `RequiredStates`, `Lockfile`, `LockedContract`,
  `LockedLayer`, `ShadowRecord`, `DecisionRecord` and the new `PipelineIR` fields are all
  reached. The holes in A3 and A6 are types the walk cannot classify, not models it fails to
  visit.
- **The four doors.** No way found to widen them or add a fifth `EgressPayload` the door tests
  miss.
- **Rule-pinned selections resist overlays**, which is why A5 needed an unpinned module.
- **Environment invariance of publication.** 16 `mendel publish` runs across varying
  `PYTHONHASHSEED`, `LC_ALL`, `TZ`, `umask` and absolute-versus-relative registry paths produced
  byte-identical bundles and lockfiles. Invariant 10 holds against the environment, which is the
  half of determinism that is easy to assume — the half that broke is A8, inside the process.

## Minor

### ⬜ A12. A registry layer is identified by its directory basename

`mendel_resolver/layers.py:68`, `comeni_core/lockfile.py:77,125-137`

`names=[layer.name for layer in with_contracts]`, and `Lockfile.of` stores `name=path.name`.
The basename is not an identity:

| invoked as | recorded name |
|---|---|
| `--registry registry/` | `registry` |
| `--registry .` | `''` |
| `--registry ..` | `'..'` |
| `--registry ../lab-registry` renamed to `lab-overlay` | stack reported as changed |

Renaming a checkout directory reports *"the layer stack changed"* with no content difference,
and `--registry .` writes an empty `LayerName` into a published bundle and every `ShadowRecord`
in it. Both are noise rather than unsoundness — the positional comparison added in Plan 1.7
means a basename collision still compares the right digests — but a drift detector that cries
wolf on a `mv` is a drift detector people learn to ignore.

**Fix designed, not applied.** `registry.yml` already carries the layer's own `name`, added in
Plan 1.7 for exactly this reason — *"a layer that moves to its own repository cannot rely on the
directory it happened to be checked out into"*. Read it when present and fall back to the
basename only when it is absent. The manifest is loaded already; A7 is the other half of the
same omission.

### ⬜ A7. The registry drift detector ignores the manifest

`tools/check_registry_drift.py` — written this session. It compares the four declared kinds
and uses `registry.yml` only to check the target *is* a layer, never comparing it. `name`,
`version` and especially `licence` can diverge between Comeni-Labs and comeni-registry
undetected. One line.

## Operator decisions

### ❓ D1. What may a parameter value be?

A3 has an easy half and a hard half. Aliases with a known grammar — `Digest` is
`sha256:[0-9a-f]{64}`, `TypeId` a dotted identifier, `LayerName` a single path segment — can
be given real `StringConstraints`, and that fix is mechanical. `ParamValue` cannot: a Nextflow
parameter genuinely can be an arbitrary string.

1. **Reject path-shaped values** — refuse `/`, leading `~`, filename patterns. Cheap, catches
   the demonstrated attack, and is a blocklist with everything that implies.
2. **Parameters become closed vocabulary** — a contract declaring `seq_platform` declares its
   permitted values, exactly as measurements do. Consistent with the rest of the registry and
   makes the attack unrepresentable rather than filtered. This is Plan 2 Task 11's territory,
   where `Param`'s domain was deliberately left to be designed.
3. **Accept it and always flag it** — a free-text parameter value is legitimate but never
   clears review.

Recommendation: **2**, in Plan 2 Task 11, with **1** now as a stopgap, because A3 is a live
route into a published artifact and Plan 2 is not close.

### ❓ D2. Should `mendel publish` require `--gate test`?

A4 is invisible to every gate except `--gate test`, and publication has no undo. Requiring it
closes A4 at the cost of minutes, Docker and network per publish. The alternative is that the
bundle **records which gate it passed**, so a curator can refuse one that never ran the only
gate that checks wiring — `PipelineIR.unverified` already sets that precedent.

### ❓ D3. Can the purity guard survive as an allowlist?

A1 is not fixable by extending the import allowlist, because the problem is reachability, not
importing. Three options, none free:

1. **Ban attribute access to module objects** — flag `pathlib.os`, `typing.sys` and any
   `ast.Attribute` chain resolving to a module, plus `exec`/`eval`/`compile`. Extends the same
   static approach; catches the demonstrated routes; will not catch a determined author.
2. **Enforce at runtime, not statically** — install an import hook or audit hook in the test
   suite and assert the pure packages never open a socket while a build runs. Catches
   behaviour rather than syntax, and is the only version that resists cleverness.
3. **Stop claiming it is structural.** The honest fallback: the guard raises the cost and
   documents intent, and CLAUDE.md's "cannot" becomes "does not, and CI checks". This is worth
   real consideration — the 2026-08-03 audit already made the same call for
   `mendel-compiler`, on the grounds that "an honest banlist is better than a dishonest
   allowlist."

Recommendation: **2 plus 3** — keep the static check for cheap feedback, add one runtime
assertion that actually holds, and soften the claim to what is enforceable.

## Suggested order

Not a plan — a plan gets written against the code, as the last three did. This is what the
dependencies between the findings imply.

1. **A11, A13, A10, A12, A7.** Mechanical, no design left in them, and A10 will surface
   anything else the registry has been quietly ignoring. Do these first so later work runs
   against a registry that fails loudly. A11 and A13 are the same fix twice — a type that
   accepts a duplicate it cannot act on.
2. **A9, then A2.** Both are "the loader and the guard disagree about what was loaded". A9
   closes a silent-reroute route that A5's fix would not; A2 moves invariant 15 out of the CLI,
   where the next verb will forget it again.
3. **A8, before Plan 2.** This is the one that must not wait. Plan 2 plugs a model into
   `AmbiguityResolver`, and today that port cannot change a module choice — so the first thing
   tier 4 will be asked to decide is the first thing it cannot decide. Fixing it after the
   adapters exist means fixing it with a model in the loop.
4. **A5, A6, A3, A4, A1** — each blocked on or improved by an operator decision above.

Two of these findings (A8, A9) are in code written during Plan 1.7, and A9 is a direct
consequence of a hardening fix applied in the same session. That is now the third audit in a
row where the freshest code held the sharpest defect, and it is the argument for auditing at
the end of a plan rather than at the end of a phase.
