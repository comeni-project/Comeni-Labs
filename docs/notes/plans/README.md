# Plans

Step-by-step implementation plans, written before the work and executed task by task.

**They contain code that was proposed, not necessarily code that shipped.** Several steps in
every plan were corrected during execution; the corrections are recorded inline in the plan and
in the commit messages. A plan is a record of intent plus what intent met.

**Filenames are a log, not an order** — two plans share `2026-08-04`. The execution order, and
the argument for it, is in [`../README.md`](../README.md), which is the file to read rather than
this directory listing.

`make links` does not check this directory. A plan names files its own tasks create, which is
correct when it executes and broken until then.
