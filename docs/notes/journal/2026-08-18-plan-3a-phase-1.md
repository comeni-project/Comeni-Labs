## A defect phase 0 shipped, and why nothing caught it

`aggregate()` ended with `sorted(key=lambda q: (q.band, ...))`. **`Band` is a `StrEnum`, so
bands compared alphabetically** — `cosmetic` < `prose` < `routing` — and the queue put port
labels above the fields that decide which pipeline gets built. The exact inverse of the design's
consequence order, on the screen whose whole claim is consequence-first.

It ran that way for a phase. **Nothing asserted an order across bands**: `test_aggregate.py`
checks collapsing and `test_questions.py` checks projection, and both are right about what they
test. `Band.rank` declares the order now, with 1 and 2 left free for drift (phase 5) and blocked
proposals (phase 3) so they arrive in the right place rather than at the end.

## The audit found five things, and two of them mattered

Run before execution, against the code rather than by re-reading the plan.

**A test that could never fail.** The plan asserted
`expect(window.location.search).not.toContain("sort")`. **MemoryRouter never writes the address
bar**, so that string is `""` for the whole test and it passes even if the setter does nothing.
Confirmed with a throwaway probe rather than by reasoning, then rewritten to assert through
`useSearchParams`.

**Tests that would be green locally and red in CI.** `test_visits.py` needs Postgres and CI has
none — and **no existing API test touches the database**, because `test_health.py` deliberately
tests `strip_from`, the pure function, not the route that reads it. The visits tests now
`skipif` on the database being reachable, the same idiom `test_gates.py` uses for Nextflow.
**Verified by pointing at a dead URL and watching 5 skip rather than 5 fail.**

**A keyboard that would have died silently.** `useKeys` ignores keystrokes targeting a `SELECT`
— correct, since `J` in a field is the letter J — and every control is a `<select>`. Focus stays
there after a choice, so the next `J` is swallowed and the queue's keyboard stops working until
you click something neutral. Users report that as *"the keys sometimes don't work"*. The selects
blur.

The other two: a `keydown` dispatched outside `act()`, and a memo keyed on an array the caller
rebuilds every render.

## Two limits, stated rather than left to be inferred

**`since_last_visit` is per draft, not per question.** The timestamp is `draft.json`'s
modification time, so filling one hole in `fastqc` marks **every** `fastqc` question as new.
Watched happening: fill `priority_because`, and six rows return rather than none. A per-question
first-seen record is the honest version and needs a row per question. The design's phrase is
*"what moved"*, and a draft is what moves — but a reader would reasonably assume the finer
guarantee, so it is written here.

**`who` is `git config user.name`.** Attribution, not authentication: a shared installation gives
every curator the same baseline. It is on the model's docstring, and real accounts replace that
column's source and nothing else.

## What you still cannot do

- **No answer-all.** A question asked by two drafts is answered twice — phase 2, and it is not a
  wrapper: a partial failure needs its own refusal semantics.
- **`A` and `E` are not bound.** They act on the answer screen, which phase 2 builds. Half a
  keyboard map is right when half of what it drives exists.
- **The answer screen is still minimal** — no prose context, no collapsed evidence, no `MODEL`
  marker.
- **No proposals, no contracts, no drift, no sources** — phases 3–6. Their nav entries render
  `aria-disabled` with the phase that builds them.
- **No landing page**; `/` redirects to the queue for the whole of 3A. **No AI anywhere.**
- **The confirmable band still cannot be exercised.** Nothing has run `forge fill --model` over
  these drafts, so `suggested` is `null` throughout and every row says *Ask*. The band you would
  most want to see is the one you cannot.
- **Nobody has clicked it.** The exit criterion was driven with `curl` through the Vite proxy and
  the SPA fallback — every layer verified, but the mouse path is covered only by component tests
  against a mocked `fetch`.

## Corrections to the plan — two

1. **`Query(...)` in an argument default trips ruff's `B008`.** Rewritten with `Annotated`, which
   is FastAPI's current idiom and what the rule is actually about, rather than suppressed.
2. **The counts strip shared a row with the sort control.** `Controls` takes optional `rows` and
   `total` rather than the numbers being orphaned — they are what the controls just did.

Also finished a **phase 0** step left half-done: `Queue` was still using inline loading, empty
and error strings rather than the shared `States` its own task created.
