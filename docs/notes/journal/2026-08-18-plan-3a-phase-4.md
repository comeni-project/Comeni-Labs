## The audit corrected the spec before a line was written

**`unverifiable` and "no module file" are different conditions**, and §3.4 of the spec said they
were the same. Measured:

- `ops.check` skips a contract when **no registered source adapter** can re-fetch the tool's
  truth. The two `comeni/` contracts, because nothing knows how to read a `comeni/` tool.
- The vendored `main.nf` being absent is a **separate fact**.

**Every contract in this registry has a readable module**, so the two are independent and one of
them never fires today. Seen live:

```
comeni/profile/collect@0.1.0
  status per the list: unverifiable
  but the module reads: 1 of 4
```

The test that asserted `emits_total is None` for a `comeni/` contract **would have failed**, and
the exit criterion's step 6 was looking for a screen that cannot occur. Both were fixed before
execution. It is the second audit in a row where the finding was a claim about the world rather
than a bug in the code.

## Two things reported as absent rather than faked

- **Pipeline pins.** Nothing stores pipelines, so the design's fourth right-column row cannot be
  answered. The page says *"pipeline pins — not tracked yet"*. Reporting `0` would say *no
  pipeline uses this*, which is a different and unverified claim.
- **Per-field origin.** The design's left gutter stripe needs where each field came from.
  `contract.provenance` is per-*contract*; the per-field `FilledValue.by/how/why` lives on the
  **draft, which is discarded once a contract lands**. So the data does not exist, and inventing a
  stripe would be decorative. Closing it means either landing the provenance into the contract
  file or keeping drafts after landing — neither is a phase 4 question.

## The cost that will break first, written down now

`ops.check` reads every vendored module: **0.40s for these 12 contracts**. It is cached on
`digest_of_directory(registry_root)`, so it runs once per registry state rather than per request,
and a changed registry invalidates it by changing its digest.

**At the 5,800 contracts the design says this page must survive, the cold path is roughly three
minutes.** The fix then is a table the worker writes — the operator's decision on 2026-08-18
declined it deliberately for now. The number is here so the day it matters, it is already known
rather than measured in a panic.

## One plan correction, and it is the fourth of its kind

**`Contracts.test.tsx` waited on a static facet label**, which renders before the fetch resolves,
so the counts were read while still `{}`. Exactly phase 2's `Lookup` bug. The plan's own global
constraint — *a test must reach what it tests* — is what caught it, and the fix is to wait on a
row id, which only exists once data arrives.

Also predicted correctly and worth keeping: **FastAPI strips the `:path` converter when generating
OpenAPI**, so the schema reads `/api/contracts/{id}` even though the route is `{id:path}`. Without
`:path` a contract id with slashes matches only its first segment and answers 404.
