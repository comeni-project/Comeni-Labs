# 2026-08-18 — Plan 3 slice 1: the forge queue, end to end

The fourth entry today. [`2026-08-18-the-shared-question.md`](2026-08-18-the-shared-question.md)
reported Plan 2.5 and the pivot; this one reports the first slice of the interface.

## Where things stand

**`mendel-api` and `frontend/` exist, and the forge queue renders from a real workspace.**
`make verify` exits 0 — 1203 fast tests, 5 slow, 75 guards. Eight tasks, all ticked as they ran.

Two drafted modules (`fastqc`, `samtools/index`) raise **13 questions that render as 7 rows**,
because both ask the same six things and `produces[2].type_id` correctly stays alone — only
`fastqc` has a third output. The health strip reads **12 contracts, 10 matching, 2 unverifiable,
22 declared types**.

## What was built, and the one thing that made it cheap

- **`mendel-api`** mounts the forge's existing ASGI app rather than reimplementing it.
- **`OpenQuestion`** — one schema React and an agent both read.
- **Aggregation** — identical work collapses to one row, which is what keeps the queue bounded.
- **One database table**, and the restraint is tested.
- **An ARQ worker** that checks the registry against its sources and records that it happened.
- **The frontend**, with Tailwind's `@theme` mirroring the token system.

**The projection was cheap because of Plan 2.5.** `Hole` and `Ambiguity` are subclasses of one
`comeni_core.review.Question`, so projecting the second one in the Mendel slice adds an *arm*
rather than a schema. That was the argument for doing 2.5 first and it held.

**The forge backend existing was the other half of it.** `mendel_forge.http` was already a
mountable app with eleven routes, and its docstring named this plan as the thing that would mount
it. Slice 1 went to the forge rather than to Mendel for exactly that reason — spec §7.

## Three honesty bugs, all found by running it

None of these would have failed a test that was written before running the thing.

**1. `matching` counted contracts nothing had read.** The registry has 12 contracts and
`ops.check` reads **10** — two `comeni/` contracts have no adapter. The strip reported
`matching = contracts - drifted = 12`, claiming twelve were verified. That is precisely what
`CheckResult.skipped`'s own docstring warns about: *"a contract nothing checks looks exactly like
a contract that agrees."* The strip carries `unverifiable` now and a test asserts
`matching + unverifiable == contracts`.

**This is the design's `unverifiable` facet arriving from real data.** It was drawn on the
Contracts screen without knowing it would be non-zero on day one.

**2. A fresh database rendered "0 match their source".** `matching` is 0 before any check because
nothing was *measured*, not because nothing matches — and on an empty database that line reads as
catastrophe. The counts are withheld until `checked_at` is non-null, with a test.

**3. The plan's own call to `ops.show` was wrong.** It needs `registry_root` and `source_root` as
well as `workspace_root`: a hole's candidates are recomputed from the layer stack rather than
stored, so **a draft cannot be read without the registry it was drafted against.** Worth knowing
beyond this slice.

## Corrections to the plan — eight

1. **`packages/*` is a uv workspace glob**, so a bare directory breaks `uv sync` before any test
   can run. The manifest must exist for the test to fail for the right reason.
2. **`test_we_added_no_routes_to_the_forge` was wrong twice.** First it compared paths a mount
   does not expose; then it broke again when a *router* was added rather than a route, because
   `include_router` puts an `_IncludedRouter` in `app.routes` and it carries no path at all.
3. **`ops.show`'s signature**, above.
4. **`openapi-typescript` requires `typescript@^5.x`** and the Vite template installs TypeScript 6.
   TypeScript is pinned to `^5.9`: OpenAPI-first is a constraint, so the generator working
   outranks the newest compiler.
5. **Vite 8 uses rolldown**, and npm's optional-dependency bug (npm/cli#4828) left the native
   binding out. `@rolldown/binding-linux-x64-gnu` is an explicit devDependency — platform-specific,
   and CI may need the same.
6. **vitest could not start any worker under jsdom.** It pulls `@asamuzakjp/css-color`, which
   `require()`s an ES module and dies on Node 22 in *both* pools — so the pool was not the problem.
   happy-dom has no such chain.
7. **Alembic's generated files are excluded from ruff.** Linting generated files means either
   hand-editing every migration to satisfy a style it did not choose, or a `noqa` storm.
8. **`test_every_workspace_dependency_carries_a_lower_bound`** exists and I did not know it did.
   Workspace deps need `>=0.1.0`, or a released artifact would accept any version.

## What a fresh reader gets wrong

**"The queue shows the design's six facets."** It shows three *bands*, because slice 1 only has
questions — there is no drift, no proposal and no undrafted work in it yet. That is a real
deviation from `docs/design/forge-review.md` §4 and it is replaced in slice 3.

**"The confirmable band works."** Nothing has model-filled these drafts, so `suggested` is `null`
throughout and every row says *Ask*. The fast lane cannot be exercised until someone runs
`forge fill --model`. Correct behaviour, and the band you would most want to see is the one you
cannot.

**"Postgres holds the registry."** It holds one table with one fact: when a check last ran.
`test_the_registry_is_not_in_the_database` asserts there is exactly one table, so a second is a
deliberate act rather than a drift.
