# 2026-10-06 — 14.7.8.3a, forks

## Where things stand

- **The protocol can declare a fork**: a node whose arrows are the cases of a subject, which the
  pure interpreter takes from a snapshot the shell passes. `uv run pytest packages/mendel-authoring/tests -q`.
- **The subject is pluggable** (`mendel_authoring/forks.py`): `SettingSubject` today, its cases
  read off the setting's own declaration (a choice's option values, a toggle's `on` / `off`, any
  other kind open). A parameter, a fact or a plan property is one more subclass.
- **Coverage is checked when the protocol loads**: a closed subject needs exactly one arrow per
  option; an open one needs `DEFAULT` (`"*"`). At run time a value with no arrow is MI0216.
- **Nothing in the product changed.** The real protocol has no fork yet, the shell passes no
  snapshot (`interpret.NO_SNAPSHOT`: every subject takes its default), and the generated diagram
  is unchanged (`uv run python tools/generate_protocol_doc.py --check`).

## Decisions made, and why

- **Part 3 split: forks (3a) before stage ④ (3b)**, because stage ④ is the first user and the
  mechanism stands alone.
- **A fork is a switch over a pluggable subject**, not a condition per arrow: exhaustiveness stays
  checkable, and the interpreter only ever asks "which case?".
- **Coverage is a load-time refusal**, as every other protocol rule is, not a separate test.
- **#252**: the null was STAR's contract wrongly declaring no domain for `seq_platform`; the SAM
  `PL` list goes into the registry; a value that truly has none is left to the run; a Dev setting
  (3b) shows such registry gaps through a fork (decision commented on the issue).

## Traps

- **A toggle is stored as a bool**; `SettingSubject.value` maps it to `on` / `off`.
- **A fork's arrows carry no `on`**: the "one way straight through" counts exclude case edges, in
  the protocol and in `interpret._one_way_on`.
- `Setting` refuses short `help`, an undotted `key`, and a choice with no valid default; test
  settings must be real declarations.
