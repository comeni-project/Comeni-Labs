# 2026-08-25 — the screens, against the artboards that were drawn for them

**Read this first if you are picking the project up. This is the newest entry.**

W2's checkpoints 3–6 were owed. They were walked — in a browser, against the nine artboards
served side by side — and the walk turned into a conformance pass and then a build.
[`notes/audits/2026-08-25-w2-conformance-and-usability.md`](../audits/2026-08-25-w2-conformance-and-usability.md)
is the record; this is the handoff.

## What the walk found, in one sentence

**W2 carried the information across and left the design behind.** Every colour token matched the
artboards exactly; what diverged was size, weight, shape and emphasis — 2px bars where the
drawing has 7px blocks, 41px rows where it has 55, no pill on the active tab, and three of five
bar tints wrong. The screens were right and unreadable.

Two of those tints were also a **correctness** bug: `worst realtime` and `read / written` are
neutral in the artboards and were painted `--pea`, the app's word for *done*. The column scales
to its own maximum, so a failed run drew a **full green bar on the process that killed it**.

## What is different now

`/runs` is a **board**: four tiles (needs you · running now · succeeded 14d · typical run with
p95), a fortnight of runs per day stacked succeeded-over-failed, `phase`/`who` filters, and
pagination. `GET /api/runs` is a page — `{runs, total}` — and `GET /api/runs/summary` is new.
The drawing is at <https://claude.ai/code/artifact/55693858-69a2-49f1-baaf-33e0cf199d92>,
regenerated by `docs/design/runs-board/board.py`, which borrows `w2-mockups/build.py`'s chrome
rather than restating it.

The run page: the `--surface-2` header shelf, pill tabs, thick bars above their numbers, the
task table clustered left with an annotation column, a console that reads as a log rather than a
spreadsheet, a horizontal graph, and a failure banner that is a tinted block rather than a white
card with a red stripe.

`pair()` no longer prints `0.0` for a measured 3.8 MB against a 31 GB ask. `.live` and
`.breathe` exist in the product CSS, where they had been artboard-only names.

## Three defects of one family, and the family is the point

**`tsc` clean, tests green, rendered wrong. None was reachable except by opening the page.**

- the run graph's canvas computed to **15px** — `flex-1` with no flex parent
- a Tailwind class built by **concatenation** is never generated; every board row collapsed into
  a vertical stack
- a `position: fixed` menu inside a **`transform`ed** ancestor is positioned against that
  ancestor, so the graph's context menu drifted by exactly the pan

W1 and W2's journals both say the defects came from running it and not from tests. That is now
three sessions in a row, and the shape has sharpened: these are **layout** bugs, and a layout
bug is invisible to a type checker and to jsdom, which does no layout at all. Screenshot the
page.

## What a fresh reader gets wrong

- **"The audit's findings were all correct."** Two were not, and are withdrawn in place rather
  than deleted: the panel shadow was fine (a probe truncated `boxShadow` at 50 chars and read
  only Tailwind's transparent placeholder layers), and `6 Undecided` vs `5` was never a
  disagreement — `provenance` counts decisions, `needs_review` counts steps. The fix there was a
  missing noun, not a number.
- **"The board shows steps."** It shows **tasks**. `steps_declared` lives in the artifact and
  reading one per row is the cost the old `Board.tsx` comment was right about; tasks are one
  `GROUP BY` over the `run_task` projection W2 built.
- **"`npx tsc --noEmit` is the typecheck."** It is not. A real error in the settings overlay
  passed `--noEmit` and failed `tsc -b`. Use `npm run build` or `tsc -b`.
- **"The graph matches the artboard."** It matches its vocabulary. It has **no entry node** —
  `Graph.dc.html` draws `entry · reads / 12 samples` and nothing in the API knows either fact.

## Still open

**`wiener_core.overview` counts `ABORTED` as failed.** One run reads *1 failed* on the overview,
carries a `✗` without the console's failed-block, and is not named in the banner — it was
aborted, collateral of another process's failure. Three surfaces, three readings of one word.
It is a meaning decision in a **pure** package, so it was left for the operator.

**The board has no `PIPELINE` column**, because no field names what was run. A board cannot
answer *where is the RNA-seq one* without one; it needs a field on the run — the goal, or the
kept draft's name. The artboard draws the column and its note asks the question.

**Checkpoint 5's SVG-copy rung was never re-walked** after the graph was rewritten. The menu
item is wired and the token-resolving `svgOf` is unchanged, but nobody has pasted the result
into a file since.

## What is next — drive it as a user, and write down the friction

**Set a pipeline up by hand and actually run it**, end to end: draw it in the builder, answer
what it asks, keep it, gate it, send it to Wiener, and read the run. The point is not to
demonstrate that it works — the spine already runs — it is to find where the loop *rubs*, in the
same way that walking the forge as a user found that `forge draft` ranked the right type first
in 1 of 30 holes.

Everything on that path is deployed: `make dev`, then <http://localhost/build>.
