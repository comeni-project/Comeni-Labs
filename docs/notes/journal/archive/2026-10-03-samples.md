# 2026-10-03 — samples (14.7.6), built in seven parts

## Where things stand

- **A person can answer a question about their data with a sample**, one file or a pair, at
  protection level 0. Only the first 4 MB of each file leaves the browser; the server reads it in
  memory, measures it in a separate process, and keeps the facts, never the bytes. Scenario 1 was
  walked by uploading the real nf-core pair SRR6357070 (Chrome, `gemma3:12b`) and passes from the
  home page: paired yes (50,000 pairs), read length 101, Phred+33, all marked *measured · fastq
  1.0.0*, and the aligner's tier-3 reason reads *read_length is 101, measured by fastq@1.0.0 +
  read_length@1.0.0*.
- **Guards:** `uv run pytest tests/guards/test_inspector_pieces.py` (imports, never raises, never
  decides on a name); `uv run pytest tests/registry/test_inspection_conformance.py` (every FASTQ
  case against its golden report).
- **Speed:** a 4 MB gzipped FASTQ head is read in one pass with three measures in 0.21 s, against
  a 1 s budget (the conformance suite holds the budget).
- **Registry per request:** 10.69 ms before the layer signature, 1.55 ms after (#216).
- **The registry branch `inspectors`** (pieces, guide) is pushed and the submodule points at it;
  whether it is merged to the registry's `main` is in *Open questions*.
- The five known failures are unchanged (`test_forge_jobs.py` ×4, `test_full_cycle`, #219).

## Decisions, and why

- **One registry for tools, profilers and inspectors**, reorganised one folder per tool first:
  a separate inspector repository would have needed its own versioning, trust and layer story
  for the same kind of declared data.
- **Composed pieces** (codec, format, measure): a format and a measure are written once and
  combine, so hundreds of types do not need hundreds of inspectors.
- **One pass:** every measure is fed from one read of the head, so cost grows with the head, not
  with the number of measures.
- **Undetermined, never guessed:** below its threshold a measure says why; the measurement stays
  open and falls to tier 4.
- **A separate process** with a minimal environment, `cwd=/`, memory and time limits: a piece is
  code from a layer, and a failure is that inspection's answer, never a 500.
- **Bytes not stored:** the head is held in memory and piped to the child; the spec's
  `workspace/samples/` was dropped (14.7.6.4). The browser sends only the head (14.7.6.6, a
  review finding: the card said so before the code did).
- **`MEASURED`, not a new `INSPECTED`:** it already meant *a tool looked at the data and named
  itself*; the pieces and the evidence say which tool.
- **Steps returned, not streamed:** an inspection takes well under a second.
- **The cap ends the head** (#221, A); **Phred+64 never passes `h`** (#222, A); **upload is offered
  only where a trusted format reads one of the person's inputs** (#227, a).
- **A tier-3 reason names its measurer** (#233, A, operator): *check the premise* needs to say
  what to check.
- **Home always offers a conversation when a model is configured** (#229, A).

## Traps

- **Bare `pytest` truncated the dev database once this step.** Put the 5442 URL on the command
  line every time.
- **FastAPI's `UploadFile` spools past 1 MB to disk**; the route streams the multipart body itself,
  and the no-disk test patches `starlette.formparsers.SpooledTemporaryFile` (an inert version of it
  passed first).
- **A new measurement moves derived files:** `profile.pyi`, the forge goldens and the
  measurement-list test (the inspectors guide says how).
