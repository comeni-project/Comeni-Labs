## Where things stand

- **The worked case is STAR's genome index.** A derived fact computes nf-core's formula from
  `genome_length` and a decision gives `--genomeSAindexNbases` its value: 29,903 bp gives 6,
  3.1 Gb gives 14, and the setting's reason names the derived value and the stated length it
  came from. The registry change (STAR genomegenerate's `sa_index_nbases` param and the rule)
  is not made; the test builds it from an overlay.
- **Built:** `then: {fact: <id>}`; `round`; `hit: first | unique` (a tie asked at tier 4;
  `unique` only on settings); exact table checks over several facts (MD0311 gaps, MD0323 dead
  rows, MD0324); rule values against tool constraints (MD0325); the builder asks for the
  measurement behind a fact a setting takes; the forge drafts `rules:derive:` items.
- **Reviewed** after every task. Rulings and deferred minors are in the plan's *Deviations*.
  A reviewer's parallel database run collided with mine once; reviewers now run pure tests.
- **Waiting** (commented on #461): lists and units, choosing a set, shared values across steps.
