# 14.7.4 part 1 — What we keep and show of each model call — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this
> plan task by task, in one hand (`CLAUDE.md`: subagents are for review and design only). Steps use
> checkbox (`- [ ]`) syntax: **tick each step as it completes**; a step done differently is still
> ticked, with the deviation in the execution record at the end.

**Goal:** Every builder model call stores its raw reply, its session and its cached tokens, and
the conversation's header shows the session's tokens and calls, opening a list of the calls with
their replies.

**Architecture:** `comeni_ai.Client` stops discarding the reply text (`last_response`) and reads
cached tokens from LiteLLM's usage. `ai_invocation` gains `response`, `session_id` and
`cached_tokens`; `authoring_ai._record` and `record_calls` write them, with `session_id` passed by
the caller — never through the door-1 payload. The session view gains a `usage` total summed in
the query that builds it, so the existing poll carries it; a new calls endpoint is fetched only
when the panel opens.

**Tech stack:** Python 3.12, FastAPI, SQLAlchemy, Alembic, Pydantic; React 19 + TanStack Query +
Vitest.

**Spec:** [`docs/superpowers/specs/2026-09-29-the-consultants-words-design.md`](../specs/2026-09-29-the-consultants-words-design.md) §5.
**Issues:** #182 (store the reply), #191 (the counter) under 14.7.4 (#180).

## Global constraints

- **Asynchronous, never chatty:** no new polling loop; the counter rides the session poll; the
  call list is fetched on open and again only when `usage.calls` changes.
- **`session_id` never enters `AuthoringRequest`** — that is door 1's typed payload
  (`FREE_TEXT_FIELDS`); the session travels beside it as a keyword argument.
- **Recorded replies in tests, never a live model.**
- **Database tests against the throwaway Postgres** on `127.0.0.1:5442` (`alembic upgrade head`
  there first; `MENDEL_DATABASE_URL=…` on make's command line).
- **Run each check in its own call and read its exit code before committing** (memory:
  a failing check in an `&&` chain did not stop the commit here).

## Review focus

1. **A provider that returns no usage block** (Ollama sometimes): `cached_tokens` stays null, the
   total counts null as zero, nothing raises. Task 1.
2. **A call that never reached a provider** (no model configured, MI0106): a row with an empty
   `response`, counted as a call with zero tokens. Task 2.
3. **A session with no calls yet:** `usage` is all zeros, the header says nothing (no *0 tokens*
   clutter), the list is empty. Tasks 3–4.
4. **A long reply** (a model rambling): the panel collapses it; the column is `Text`, not bounded.
   Task 4.
5. **The poll stopped** (nothing pending) and a queued call lands later: the count catches up on
   the next poll the page makes, never through a new timer. Task 4.
