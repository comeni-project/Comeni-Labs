## Outcome and execution rules

The researcher can correct any fact or return a measurement to unknown. Conflicting
sample evidence asks a question. Corrections cascade through the pipeline and
affected reviews, including when node IDs survive. Truthful unbuildable corrections
persist. Manual work is preserved in a linked draft. Fact history is visible now;
**undo is explicitly deferred and must have a task-tree issue before Part F closes.**

Execute sequentially, task by task. Tick each step only after its check passes;
record deviations and actual commits in the execution record. Use the existing
dispatcher transaction and pure authoring package. Do not deploy intermediate
schema/application combinations, hand-edit generated clients or diagrams, or call
a live model from tests. Database tests use the throwaway Postgres, never dev data.

The work spans storage, protocol, API and UI; each task below is a coherent checkpoint,
not a claim it takes a few minutes. Re-estimate when execution reveals a substantial
scope change, following `CLAUDE.md`. Existing CI failures (#296) are baseline findings,
not exemptions from reporting final check results.
