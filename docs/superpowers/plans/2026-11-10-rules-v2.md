# Rules v2: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A setting can take its value from a measured or derived fact, a decision declares
its hit policy, and load checks tables over several facts for gaps, overlaps and dead rows, and
checks rule values against tool constraints. The forge drafts derived facts. STAR's index size
is the worked case.

**Architecture:** All rule logic stays in `mendel-resolver/rules/` (`format.py` models,
`validate.py` load checks, `table.py` resolution). The constraint evaluator comes from
`comeni_core.declared.constraints`. The forge gains one item kind and assembles it into the
rule file's `derives:`.

**Tech Stack:** Python 3.12, Pydantic v2, pytest.

**Spec:** `docs/superpowers/specs/2026-11-10-rules-v2-design.md`

## Global Constraints

- `mendel-resolver` stays pure. Same inputs and recorded decisions reproduce the output.
- The registry's `rules/alignment.yml` loads unchanged and keeps its digest: `hit` defaults to
  `first` and is left out of the dump; a literal `then` is unchanged.
- New codes: `MD0322` overlap, `MD0323` dead row, `MD0324` too many cases, `MD0325` a value the
  tool's constraints forbid. Declared in `diagnostics.yml`, emitted through `coded()`, listed in
  `docs/reference/pipelines/diagnostics.md` (regenerate with `tools/generate_diagnostics_doc.py`).
- No live model calls in tests; forge drafting uses recorded replies.
- No browser checks or walks (operator, 2026-11-10: at the end of parts 2–5).
- Commands as in phase 2's plan: pure tests with `uv run pytest`; database tests with
  `MENDEL_TEST_DATABASE_URL=postgresql+psycopg://mendel:mendel@127.0.0.1:5442/mendel`; the
  per-commit check `make lint types docs docs-status links doc-paths doc-sizes guards` run **on
  its own, before** `git commit`.
- A fresh reviewer after each task (operator's request, carried from phase 2).

## Review Focus

1. **A `{fact:}` whose fact is missing from the profile** must make the row not fire (next row,
   then tier 4), never emit `null`. Task 1 adds the test.
2. **A derived value that is not a whole number** reaching an integer param must be refused at
   load unless the chain ends in `round`. Task 1 adds the test.
3. **A one-fact table that passed `MD0311` before** must still pass, with the same message
   when it fails. Task 3 keeps the existing `MD0311` tests and adds none that change them.
4. **A tie under `hit: unique` at build time** must become a tier-4 question with both values
   offered, not a silent first match. Task 2 adds the test.
5. **A table over an extensible enum** keeps today's rule (a catch-all row is required). Task 3
   adds the test.
