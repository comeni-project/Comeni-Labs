# 14.7.8.3d Part E — Schema integrity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (CLAUDE.md: execute
> plans yourself; subagents review only). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Postgres runs in CI; `alembic check` holds each database to its models; every
enum-valued column carries a CHECK built from its enum; Wiener's children are bound to their
run inside one lab; a gate is bound to its draft.

**Architecture:** One throwaway Postgres (`make test-db`, port 5442; a service in CI) holds a
`mendel` and a `wiener` database at head. Each API package has one reachability helper that
skips without a database and fails when `COMENI_REQUIRE_DB` is set. Columns become
`Enum(native_enum=False, create_constraint=True, validate_strings=True)` under a `ck_` naming
convention; migrations spell the values out literally.

**Tech Stack:** Python 3.12 (uv workspace), SQLAlchemy 2, Alembic 1.19, Postgres 17, SQLite
(Wiener's behaviour tests), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-08-schema-integrity-design.md`

## Global Constraints

- **Never run bare pytest with the dev stack up.** Use `make test` (Task 1 makes it point at

- Migrations spell enum values literally; they never import an enum (a migration is history).

- Run `make check` (with `T`) separately before each commit; commit only after it passes.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
- After a migration: `make migrate` / `make wiener-migrate` (dev), `make test-db` (throwaway),
  and rebuild the baked containers (`docker compose build worker ai-worker wiener-api
  wiener-worker && docker compose up -d worker ai-worker wiener-api wiener-worker`).
- Nothing is pushed without the operator's go.
- Docs: no counts, no internal names in task pages (CLAUDE.md "Writing documentation").

- [ ] **Step 3: Write the helpers**

`packages/mendel-api/tests/mendel_postgres.py`:

```python
"""Whether the database answers, for the tests that need Postgres.

One helper instead of a copy per file. Without `COMENI_REQUIRE_DB` an unreachable database
skips those tests, as a laptop with no database expects; with it (CI sets it) the same answer
is a failure, so a run cannot go green by skipping storage.
"""

import os

from mendel_api.db import session_scope
from sqlalchemy import text

REQUIRED = "COMENI_REQUIRE_DB"


def _select_one() -> None:
    with session_scope() as session:
        session.execute(text("SELECT 1"))


def reachable(probe=_select_one) -> bool:
    try:
        probe()
    except Exception as failed:
        if os.environ.get(REQUIRED):
            raise RuntimeError(
                f"{REQUIRED} is set and the database did not answer: {failed!r}. "
                "Locally: `make test-db`."
            ) from failed
        return False
    return True
```

`packages/wiener-api/tests/wiener_postgres.py`:

```python
"""Wiener's opt-in Postgres, for the tests SQLite cannot hold (row locks, the migrations).

`WIENER_TEST_DATABASE_URL` names a migrated, throwaway Wiener database — never the configured
one, which may be somebody's. Unset, these tests skip; unset or unreachable while
`COMENI_REQUIRE_DB` is set (CI), they fail.
"""

import os

from sqlalchemy import create_engine, text

REQUIRED = "COMENI_REQUIRE_DB"
URL = os.environ.get("WIENER_TEST_DATABASE_URL")


def reachable() -> bool:
    try:
        if URL is None:
            raise LookupError("WIENER_TEST_DATABASE_URL is not set")
        engine = create_engine(URL)
        with engine.connect() as connection:
            connection.execute(text("SELECT 1"))
        engine.dispose()
    except Exception as failed:
        if os.environ.get(REQUIRED):
            raise RuntimeError(
                f"{REQUIRED} is set and Wiener's test database did not answer: {failed!r}. "
                "Locally: `make test-db`."
            ) from failed
        return False
    return True
```
