# Plan 3A, phase 8 — compose and prod

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement
> this plan task-by-task, sequentially, driving it yourself. Steps use checkbox (`- [ ]`) syntax,
> and **tick each one as it completes**. Do **not** farm the tasks out with
> `subagent-driven-development`; subagents are for review and design only.

**Goal:** `make dev` brings the whole thing up and says where it is; the same stack runs with a
prod overlay that changes safety and nothing else; and the nightly source check finally has a
worker to run on.

**Architecture:** One compose file defines the stack — db, redis, api, worker, web — and
`docker-compose.prod.yml` is an *overlay* that removes the unsafe parts. One multi-stage image for
the api and the worker, with a dependency layer so a source edit rebuilds in seconds. Dev gets a
writable registry clone so drift acceptance works there exactly as in prod.

**Spec:** [`notes/specs/2026-08-19-compose-and-prod.md`](../specs/2026-08-19-compose-and-prod.md)
— §3 holds the eight decisions, §2 the inventory.

**Preceded by:** [`2026-08-19-plan-3a-phase-7.md`](2026-08-19-plan-3a-phase-7.md) —
responsiveness, so this packages an application that answers in 5–10ms rather than 250ms.

**This ends Plan 3A.** 3B is the landing page and gets its own spec.

**This plan replaces an earlier draft of itself.** That one was written against a spec that had
separate dev and prod compose files, no registry clone, no measured Dockerfile and no `mendel-ai`
extra — all four changed when the operator's instruction landed: *dev should work as well as prod,
the only difference is safety.* Executing the old one would have silently dropped three decisions.

## Global Constraints

- **Work in the existing worktree** `.worktrees/plan-3-slice-1`, branch `plan-3-slice-1`.
- **Dev must be able to do everything prod can.** The overlay removes *unsafe* things — a live
  code mount, an auto-reloader, a database port on the host — never capabilities. Spec §3.1.
- **`make check` has no Docker.** Nothing here may make the fast lane need it: the compose test
  parses YAML and asserts, it does not run anything.
- **Do not serve static files from FastAPI.** Measured: `app.mount("/", StaticFiles(...))` puts a
  `Mount` in `app.routes` and `test_the_served_surface_is_the_openapi_document` fails. That guard
  is phase 6's and it decides this; nginx is the answer.
- **BuildKit is not available on this machine** — `docker buildx` is not installed and
  `DOCKER_BUILDKIT=1` errors. **No `--mount=type=cache` in the Dockerfile**; it would not build
  here at all. Layer ordering and multi-stage are the mechanisms.
- **A code is DECLARED in `comeni_core/diagnostics.yml` and EMITTED through `coded()`.**
  Regenerate with `uv run python tools/generate_diagnostics_doc.py` (`make docs` only *checks*).
- **No secret is committed.** `.env.example` carries defaults and placeholders; `.env` stays
  ignored.
- Ruff line length 100; the frontend gate stays clean.
- **Verify with `make verify`**, reading the exit code *before* filtering output.

## Task 1: The rung a container makes normal

**Files:** `comeni_core/diagnostics.yml`, `mendel_forge/land.py`,
`packages/mendel-forge/tests/test_accept.py`

**Measured:** `ops.accept` against a directory with no `.git` raises
`CalledProcessError: 'git branch --show-current' returned non-zero exit status 128` — a 500 with a
git traceback where a sentence belongs. Phase 5 built three rungs and missed the one a container
makes normal.

- [x] **Step 1: Declare `MF0107`**

```yaml
MF0107:
  emitted_by: forge
  concern: landing
  says: "the registry is not a git checkout"
  fires_on: [forge accept]
  refuses: true
  fix: |
    Point `MENDEL_REGISTRY_ROOT` at a git checkout you can write to. In a container that means
    mounting a CLONE — the registry baked into the image is a copy of the files, and a
    submodule's `.git` is a pointer that resolves to nothing inside a container.
  explanation: |
    Accepting a drift is a commit: it is how a value taken from a source gets a reason, an
    author and a place in history. A directory of the right files cannot carry any of that, and
    `git` answers `exit 128` rather than anything a person can act on.

    This is the case a container makes normal rather than exotic, which is why it was missed
    until one was built. `make dev` clones the registry for exactly this reason.
```

Then `uv run python tools/generate_diagnostics_doc.py`.

- [x] **Step 2: Write the failing tests — both shapes**

```python
# packages/mendel-forge/tests/test_accept.py  (append)

def test_it_refuses_a_registry_that_is_not_a_git_checkout(broken_registry):
    """`broken_registry` copies with `.git` excluded, which is exactly what an image built by
    `COPY registry/ ...` holds: the right files, and no repository."""
    registry = broken_registry(FASTQC, "nf_process: FASTQC", "nf_process: WRONG")
    assert not (registry / ".git").exists(), "the fixture now carries a repo — this is vacuous"

    with pytest.raises(ValueError, match="MF0107"):
        _accept(registry)


def test_it_refuses_a_git_pointer_that_resolves_to_nothing(broken_registry):
    """The shape a bind-mounted submodule has inside a container, and the reason this rung
    cannot be `(registry / ".git").exists()`.

    Measured: a submodule's `.git` is a FILE reading `gitdir: ../../../.git/worktrees/…`. Copy
    or mount it anywhere else and the file is present while git answers
    `fatal: not a git repository`.
    """
    registry = broken_registry(FASTQC, "nf_process: FASTQC", "nf_process: WRONG")
    (registry / ".git").write_text("gitdir: ../../../.git/nowhere/at/all\n")
    assert (registry / ".git").exists(), "the fixture must LOOK like a checkout"

    with pytest.raises(ValueError, match="MF0107"):
        _accept(registry)
```

```dockerfile
# One image, two commands: the API serves and the worker consumes. They import the same
# packages and read the same declared data; only the command differs, so two images would be
# two places to keep one dependency pin honest.
#
# **No BuildKit cache mounts.** `docker buildx` is not installed on the machine this was built
# on and `DOCKER_BUILDKIT=1` errors, so a `--mount=type=cache` Dockerfile would not build at
# all. Layer ordering does the work instead: measured 53s cold, 8.3s after a source edit.
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim AS builder
ENV UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_PYTHON_DOWNLOADS=never
WORKDIR /app

# The workspace's SHAPE first, so editing a module does not re-resolve the lock.
# `README.md` and `LICENSE` are build inputs, not documentation: the root pyproject declares
# `readme =` and `license-files =`, and `uv sync` fails without them. Each package carries its
# own pair, which the `packages/` copies below bring.
COPY pyproject.toml uv.lock README.md LICENSE ./
COPY packages/comeni-core/pyproject.toml   packages/comeni-core/README.md   packages/comeni-core/LICENSE   ./packages/comeni-core/
COPY packages/mendel-resolver/pyproject.toml packages/mendel-resolver/README.md packages/mendel-resolver/LICENSE ./packages/mendel-resolver/
COPY packages/mendel-compiler/pyproject.toml packages/mendel-compiler/README.md packages/mendel-compiler/LICENSE ./packages/mendel-compiler/
COPY packages/mendel-forge/pyproject.toml  packages/mendel-forge/README.md  packages/mendel-forge/LICENSE  ./packages/mendel-forge/
COPY packages/mendel-ai/pyproject.toml     packages/mendel-ai/README.md     packages/mendel-ai/LICENSE     ./packages/mendel-ai/
COPY packages/mendel-api/pyproject.toml ./packages/mendel-api/
# `--package mendel-api`, not the root: the root depends on `mendel-ai`, and the served API
# cannot reach the model path — 152MB of litellm and its stack for a verb it does not expose.
RUN uv sync --frozen --no-install-project --no-dev --package mendel-api

COPY packages/ ./packages/
RUN uv sync --frozen --no-dev --package mendel-api

FROM python:3.12-slim-bookworm AS runtime
# `git` because accepting a drift is a commit — `mendel_forge.land` shells out to it. Without
# it the refusal ladder cannot reach its own refusals.
RUN apt-get update \
 && apt-get install -y --no-install-recommends git \
 && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=builder /app/.venv /app/.venv
COPY packages/ ./packages/
# **The declared data is part of what this serves.** `settings.registry_root` and
# `source_root` are read by the queue, the contracts list, the drift report and the source
# catalogue — 224K and 788K, so baking them removes a class of "works on my host" failure.
# Dev mounts a writable clone over the registry anyway; see `make dev`.
COPY registry/ ./registry/
COPY vendor/ ./vendor/
ENV PATH="/app/.venv/bin:$PATH"
EXPOSE 8000
CMD ["uvicorn", "mendel_api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**The audit of this plan found three things.**

1. **This plan was stale before it ran.** Its first draft predated the operator's instruction
   that dev must work as well as prod, and it had separate compose files, no registry clone, no
   `mendel-ai` extra and an unmeasured Dockerfile. Executing it would have dropped three
   decisions silently. It was rewritten rather than patched.
2. **`mendel_ai` is used in exactly three places**, all inside functions — `ops.model_fill`,
   `filler.ModelFiller`, and one CLI verb — so Task 2 is three import moves rather than a
   refactor. Checked before planning it, because "make it an extra" is the kind of sentence that
   hides a week.
3. **`git rev-parse`, not `.git` exists.** Measured: a submodule's `.git` is a file holding
   `gitdir: ../../../.git/worktrees/…`, so it exists inside a container while every git call
   fails. The shortcut was in the earlier draft and would have made `MF0107` miss the case it
   exists for.

**Known weak points, stated rather than hidden:**

- **The dev registry clone diverges from the submodule.** `make dev-refresh` pulls it forward
  when clean and leaves it alone when dirty, which is right, and it is still a second copy
  somebody can forget. The alternative — mounting the submodule — does not work, which is the
  measurement §3.2 rests on.
- **No image has been built from this workspace end to end.** The deps layer, the timings and the
  size were measured with a probe Dockerfile; Task 3 Step 4 builds the real one and says to
  record the number rather than assume it.
- **`web` in the base means `make dev` builds the frontend image**, which is slower than the old
  `make dev`. That is the price of dev serving the same path prod does; if it becomes annoying the
  answer is a compose profile, not deleting the service.
- **The prod overlay is brought up once, by hand.** There is no test that it works, because a
  test that runs `docker compose up` may not live in `make check`.
