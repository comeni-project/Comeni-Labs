> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement

**Goal:** `make dev` brings the whole thing up and says where it is; `docker-compose.prod.yml`
runs the same services with the frontend built and served; and the nightly check finally has a
worker to run on.

**Architecture:** One image for the api and the worker, carrying the registry and the vendored
modules because they are read on nearly every request. Dev mounts the code live and keeps Vite on
the host; prod builds the SPA and puts nginx in front, because the API may not serve static files
without failing phase 6's guard.

**Tech Stack:** Docker Compose · `uv sync --frozen` · Postgres 17 · Redis 7 · ARQ · nginx.

**Spec:** [`notes/specs/2026-08-19-compose-and-prod.md`](../specs/2026-08-19-compose-and-prod.md)

`../../portfolio/docker-compose.prod.yml`, read while writing this. Where a shape here and one

## Task 1: The rung a container makes normal

**Files:**
- Modify: `packages/comeni-core/src/comeni_core/diagnostics.yml`,
  `packages/mendel-forge/src/mendel_forge/land.py`,
  `packages/mendel-forge/tests/test_accept.py`

**Why first:** it is a defect, it is in the code the rest of this phase packages, and it was found
by asking what a container does rather than by reading. **Measured:**

```
ops.accept(... registry_root=<a directory with no .git> ...)
  -> CalledProcessError: 'git branch --show-current' returned non-zero exit status 128
```

Phase 5 built three coded refusals for the ways a checkout is not somewhere to commit and missed
the one a baked-in registry makes normal. In a container that is a 500 with a git traceback where
a sentence belongs.

- [ ] **Step 1: Declare the diagnostic**

```yaml
# packages/comeni-core/src/comeni_core/diagnostics.yml  (beside MF0105)
MF0107:
  emitted_by: forge
  concern: landing
  says: "the registry is not a git checkout"
  fires_on: [forge accept]
  refuses: true
  fix: |
    Point `MENDEL_REGISTRY_ROOT` at a git checkout you can write to. In a container that means
    mounting one — the registry baked into the image is a copy of the files, not a repository.
  explanation: |
    Accepting a drift is a commit: it is how a value taken from a source gets a reason, an
    author and a place in history. A directory of the right files with no `.git` cannot carry
    any of that, and `git` answers `exit 128` rather than anything a person can act on.

    This is the case a container makes normal rather than exotic. The image carries the
    registry because it is read on nearly every request, and a copy of files is exactly what
    that produces — so an installation that wants drift resolution mounts a checkout over it,
    with git identity configured. Saying so in a refusal is what makes that a deployment
    decision instead of a crash.
```

- [ ] **Step 2: Write the failing test**

```python
# packages/mendel-forge/tests/test_accept.py  (append)

def test_it_refuses_a_registry_that_is_not_a_git_checkout(broken_registry):
    """The rung phase 5 missed, and the one a container makes normal.

    `broken_registry` copies with `.git` excluded, so this is exactly what an image built by
    `COPY registry/ ...` holds: the right files, and no repository. Before MF0107 this raised
    a `CalledProcessError` — a 500 with a git traceback where a sentence belongs.
    """
    registry = broken_registry(FASTQC, "nf_process: FASTQC", "nf_process: WRONG")
    assert not (registry / ".git").exists(), "the fixture now carries a repo — this is vacuous"

    with pytest.raises(ValueError, match="MF0107"):
        _accept(registry)


def test_it_refuses_a_git_pointer_that_resolves_to_nothing(broken_registry):
    """The shape a bind-mounted submodule has inside a container, and the reason this rung
    cannot be `(registry / ".git").exists()`.

    Measured: a submodule's `.git` is a FILE reading `gitdir: ../../../.git/worktrees/…`. Copy
    it anywhere else and the file is there while git answers `fatal: not a git repository`.
    """
    registry = broken_registry(FASTQC, "nf_process: FASTQC", "nf_process: WRONG")
    (registry / ".git").write_text("gitdir: ../../../.git/nowhere/at/all\n")
    assert (registry / ".git").exists(), "the fixture must LOOK like a checkout"

    with pytest.raises(ValueError, match="MF0107"):
        _accept(registry)
```

- [ ] **Step 3: Run it and watch it fail**

Run: `uv run pytest packages/mendel-forge/tests/test_accept.py -k git_checkout -v`
Expected: FAIL — `CalledProcessError`, not a `ValueError`. **Read the message**: it is the defect.

- [ ] **Step 4: Add the rung**

In `land.py`, at the top of `_refuse_an_unwritable_checkout`, **before** the first `_git` call:

```python
    try:
        _git(registry, "rev-parse", "--git-dir")
    except subprocess.CalledProcessError:
        raise ValueError(
            coded("MF0107", f"{registry} is not a git checkout")
            + "\n  accepting a drift is a commit, and a directory of files cannot carry one"
            + "\n  point MENDEL_REGISTRY_ROOT at a checkout you can write to — in a container,"
            " mount a CLONE rather than a submodule: a submodule's `.git` is a pointer at a"
            " path on the host, and it resolves to nothing inside the container"
        ) from None
```

**`git rev-parse`, not `(registry / ".git").exists()`** — and that shortcut was in this plan's
first draft. Measured: a submodule's `.git` is a *file* reading
`gitdir: ../../../.git/worktrees/…`, so it **exists** and git still answers
`fatal: not a git repository: (null)`. Copy or bind-mount that directory anywhere else and
`.exists()` says yes while every git call fails — which is exactly the container case MF0107 is
for. Asking git is the only check that answers the question being asked.

`land.py` needs `import subprocess` — it already has it.

- [ ] **Step 5: Run the accept suite and regenerate the docs**

Run: `uv run pytest packages/mendel-forge/tests/test_accept.py -q` — 13 passed.
Then `uv run python tools/generate_diagnostics_doc.py && make docs`.

**The other tests build a repo with `_repo()`, so they are unaffected** — if any of them now
fails, the fixture stopped making a repository and the finding is real.

- [ ] **Step 6: Commit**

```bash

git commit -m "fix(forge): a registry that is not a checkout refuses instead of crashing"
```

- [ ] **Step 2: Write the `Dockerfile`**

```dockerfile
# One image, two commands: the API serves and the worker consumes. They import the same five
# workspace packages and read the same declared data; only the command differs, so two images
# would be two places to keep one dependency pin honest.
FROM python:3.12-slim

# `git` because accepting a drift is a commit — `mendel_forge.land` shells out to it. Without
# it the refusal ladder cannot even reach its own refusals.
RUN apt-get update \
 && apt-get install -y --no-install-recommends git \
 && rm -rf /var/lib/apt/lists/*

COPY --from=ghcr.io/astral-sh/uv:0.11 /uv /usr/local/bin/uv

WORKDIR /app

# The workspace's shape first, so a change to source does not re-resolve the lock.
# **`README.md` and `LICENSE` are build inputs, not documentation**: the root pyproject
# declares `readme =` and `license-files =`, so `uv sync` fails without them. Each package
# carries its own pair inside `packages/`, which the next line already brings.
COPY pyproject.toml uv.lock README.md LICENSE ./
COPY packages/ ./packages/
RUN uv sync --frozen --no-dev

# **The declared data is part of what this serves.** `settings.registry_root` and
# `settings.source_root` are read by the queue, the contracts list, the drift report and the
# source catalogue — measured at 224K and 788K, so baking them costs a megabyte and removes a
# whole class of "works on my host" failure. Dev mounts over them anyway.
COPY registry/ ./registry/
COPY vendor/ ./vendor/

ENV PATH="/app/.venv/bin:$PATH"
EXPOSE 8000
CMD ["uvicorn", "mendel_api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**Check the uv image tag against what the lockfile expects** before committing — CLAUDE.md records
`uv` 0.11.18 on this machine, and a major mismatch is worth catching here rather than in a build.

- [ ] **Step 4: Build it**

`git mv docker-compose.yml docker-compose.dev.yml`, keep `postgres`/`redis` as they are, and add:

```yaml
  api:
    build: .
    container_name: ${API_CONTAINER_NAME:-mendel-api}
    depends_on:
      postgres: {condition: service_healthy}
      redis: {condition: service_healthy}
    env_file: [.env]
    environment:
      MENDEL_DATABASE_URL: postgresql+psycopg://mendel:mendel@postgres:5432/mendel
      MENDEL_REDIS_URL: redis://redis:6379
    ports: ["${API_HOST_PORT:-8000}:8000"]

      - ./registry:/app/registry          # a real checkout, so accepting a drift can commit
      - ./vendor:/app/vendor
      - ./workspace:/app/workspace        # drafts survive a restart
    # Single line on purpose — a folded block leaves the reload flag on its own line and it
    # is silently dropped. Cladewright's compose carries the same warning about gunicorn.
    command: sh -lc "cd packages/mendel-api && alembic upgrade head && cd /app && exec uvicorn mendel_api.main:app --host 0.0.0.0 --port 8000 --reload"

  worker:
    build: .
    container_name: ${WORKER_CONTAINER_NAME:-mendel-worker}
    depends_on:
      postgres: {condition: service_healthy}
      redis: {condition: service_healthy}
    env_file: [.env]
    environment:
      MENDEL_DATABASE_URL: postgresql+psycopg://mendel:mendel@postgres:5432/mendel
      MENDEL_REDIS_URL: redis://redis:6379
    volumes:
      - ./packages:/app/packages
      - ./registry:/app/registry
      - ./vendor:/app/vendor
    command: arq mendel_api.worker.WorkerSettings
```

Healthcheck intervals go to `2s/2s/30`, matching the reference — the existing `5s/3s/10` makes a
cold `make dev` wait longer than it needs to.

**`env_file: [.env]` requires the file to exist.** Either commit an empty `.env` (no — it is
ignored) or make `make dev` copy `.env.example` when it is absent. The Makefile does it.

- [ ] **Step 2: Rewrite `make dev`**

Following `Cladewright`'s `gui-up`: a pidfile, a log, `setsid` so the process group can be killed
together, and **printing the URLs at the end**, which today's foreground `npm run dev` never
reaches.

```make
DC       := docker compose -f docker-compose.dev.yml
RUN_DIR  := .run
PIDFILE  := $(RUN_DIR)/vite.pid
LOGFILE  := $(RUN_DIR)/vite.log

dev: ## the whole stack: db, redis, api, worker, and Vite on the host
	@test -f .env || cp .env.example .env
	$(DC) up -d --build
	@mkdir -p $(RUN_DIR)
	@if [ -f $(PIDFILE) ] && kill -0 `cat $(PIDFILE)` 2>/dev/null; then \
		echo "Vite already running (pid `cat $(PIDFILE)`)"; \
	else \
		setsid sh -c 'cd frontend && exec npm run dev' > $(LOGFILE) 2>&1 & \
		echo $$! > $(PIDFILE); sleep 1; \
	fi
	@echo ""
	@echo "  Forge:  http://localhost:5173/forge/queue"
	@echo "  API:    http://localhost:8000/docs"
	@echo "  Logs:   make dev-logs   ·   Vite: tail -f $(LOGFILE)"

dev-down: ## stop Vite and the stack
	@if [ -f $(PIDFILE) ]; then kill -- -`cat $(PIDFILE)` 2>/dev/null || true; rm -f $(PIDFILE); fi
	$(DC) down

dev-logs: ## tail the api and the worker
	$(DC) logs -f api worker
```

`.run/` goes in `.gitignore`.

- [ ] **Step 3: Bring it up and use it**

Run: `make dev`, then load `http://localhost:5173/forge/sources` and draft something.

**`POST /drift/accept` will answer `MF0107` inside the container, and that is correct** — the
mounted `registry/` is a submodule whose `.git` is a pointer at a host path that does not exist
in the container. Measured before this plan was written. Accepting a drift from a container
therefore needs a **clone** mounted over it, not the submodule; the guide says so in Task 6.

That is the finding this phase produces about phase 5's feature, and it should be checked by
running it rather than assumed: if it answers `MF0105` instead, the pointer resolved and the note
above is wrong.

**The audit found six things, and two are defects rather than packaging notes.**

1. **Accepting a drift crashes when the registry is not a checkout.** Measured:
   `CalledProcessError: exit 128`, not a coded refusal. Phase 5 built three rungs and missed the
   one a container makes normal. Task 1.
2. **Serving the SPA from FastAPI fails phase 6's guard**, measured — `app.mount("/",
   StaticFiles(...))` puts a `Mount` in `app.routes` and
   `test_the_served_surface_is_the_openapi_document` fails. This is the first time a guard from
   one phase has decided a design question in another, and it decided this one correctly.
3. **The API reads a megabyte of declared files at runtime**, which is not the shape a web-app
   compose file assumes. `registry/` 224K and `vendor/` 788K, read by the queue, the contracts
   list, the drift report and the source catalogue. Baked in *and* mounted in dev, for different
   reasons.
4. **`make dev` never prints anything today** — `npm run dev` in the foreground never returns.
   The reference repo solved this with a pidfile and `setsid` two years of habit ago, and the
   spec said to follow it.
5. **This plan's own first draft got `MF0107`'s check wrong**, in the container case it exists
   for. `(registry / ".git").exists()` is **true** for a bind-mounted submodule and git still
   fails: the file reads `gitdir: ../../../.git/worktrees/…`, which resolves to nothing outside
   the worktree. Two tests now, one per shape.
6. **`README.md` and `LICENSE` are build inputs.** The root pyproject declares `readme =` and
   `license-files =`, so a Dockerfile copying only `pyproject.toml`, `uv.lock` and `packages/`
   fails in `uv sync`. Each package carries its own pair inside `packages/`.

**Known weak points, stated rather than hidden:**

- **No image has ever been built from this workspace.** Task 2 Step 4 says to expect the first
  build to fail and to record what — five workspace packages behind `uv sync --frozen` in a
  slim image is not a thing this repository has done, and a plan written against files rather
  than against a green build should say so.
- **The uv version in the Dockerfile is pinned by tag**, and CLAUDE.md records 0.11.18 on this
  machine. If they disagree the lockfile may not resolve; check before committing.
- **`env_file: [.env]` makes compose refuse when the file is absent.** `make dev` copies the
  example, so `docker compose up` **run by hand** on a fresh clone fails where `make dev` works.
