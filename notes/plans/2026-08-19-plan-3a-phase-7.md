# Plan 3A, phase 7 — responsiveness

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement
> this plan task-by-task, sequentially, driving it yourself. Steps use checkbox (`- [ ]`) syntax,
> and **tick each one as it completes**. Do **not** farm the tasks out with
> `subagent-driven-development`; subagents are for review and design only.

**Goal:** A screen answers in about 10ms instead of 250ms, navigation stops refetching,
`mendel build` drops under half a second, and the test suite stops spending most of its time
parsing the same files over and over.

**Architecture:** Two mechanisms, deliberately in different places. The pure packages get *speed*
— libyaml, and one walk of the layer instead of five — and no cache. `mendel-api` gets the cache,
keyed on the registry digest, beside the one phase 4 already built.

**Spec:** [`notes/specs/2026-08-19-responsiveness.md`](../specs/2026-08-19-responsiveness.md) —
§3 holds the six decisions.

**Audit:** [`notes/audits/2026-08-19-performance-audit.md`](../audits/2026-08-19-performance-audit.md),
A132–A145. Every number in this plan came from there.

**Preceded by:** [`2026-08-19-plan-3a-phase-6.md`](2026-08-19-plan-3a-phase-6.md), complete.
**Followed by** phase 8, compose — which this reorders itself ahead of, so compose packages a
fast application rather than a slow one.

## Global Constraints

- **Work in the existing worktree** `.worktrees/plan-3-slice-1`, branch `plan-3-slice-1`.
- **This touches `comeni-core`'s loader and `mendel-resolver`'s stacking**, so **`make verify` is
  the gate, not `make check`** — CLAUDE.md names the files whose change `make check` waves
  through, and a loader is upstream of every one of them.
- **No cache in a pure package.** Spec §3.1. Speed there, caching in `mendel-api`.
- **No timing assertion in the test suite.** Spec §3.4 — guard by counting. A millisecond budget
  on a CI runner is a flake generator.
- **Byte-identical output is the real gate.** Invariant 10. A loader change that altered one
  emitted digest would be a correctness bug wearing a performance costume; the golden files and
  `make verify` are what catch it, and Task 5 diffs a built `pipeline.yml` across the change on
  purpose.
- **libyaml must not become a requirement.** PyYAML installs without it; the fallback is real.
- Ruff line length 100; `npx tsc --noEmit`, `npx oxlint src`, `npx vitest run` clean.

- [x] **Step 1: Write the failing test**

```python
# packages/comeni-core/tests/test_yaml_strict_loader.py
"""Which parser reads declared data, and what must stay true whichever one it is.

A31 is why this file exists: `yaml.safe_load` takes the LAST value for a repeated key, and a
contract that reads two ways is a contract whose digest pins what survived parsing. Swapping
the tokeniser for libyaml is a performance change that must not touch that.
"""

import yaml
from comeni_core import yaml_strict
from comeni_core.yaml_strict import DuplicateKeyError

import pytest


def test_the_fast_parser_is_used_when_libyaml_is_available():
    """13.6× on this machine, and the whole registry load 244ms -> 49ms. If libyaml is not
    installed the fallback is correct and this test says so rather than failing."""
    if not hasattr(yaml, "CSafeLoader"):
        pytest.skip("PyYAML built without libyaml; the fallback is what runs")
    assert issubclass(yaml_strict._StrictLoader, yaml.CSafeLoader)


def test_a_repeated_key_is_still_refused(tmp_path):
    """The whole point of this module, under whichever base is active."""
    path = tmp_path / "thing.yml"
    path.write_text("declares: contract\npriority: 0\npriority: 999\n")
    with pytest.raises(DuplicateKeyError) as raised:
        yaml_strict.load(path)
    assert "priority" in str(raised.value)


def test_the_refusal_still_names_both_lines(tmp_path):
    """The line numbers come from `start_mark`, which is the C parser's on the fast path. A
    swap that kept the refusal and lost the lines would pass the test above and still make
    the message useless."""
    path = tmp_path / "thing.yml"
    path.write_text("declares: contract\npriority: 0\npriority: 999\n")
    with pytest.raises(DuplicateKeyError) as raised:
        yaml_strict.load(path)
    assert "line 2" in str(raised.value) and "line 3" in str(raised.value)


def test_both_bases_parse_the_shipped_declared_data_identically():
    """53 files were compared while auditing; this keeps that true rather than remembering it.

    Not a performance test — an equivalence test. If the two parsers ever disagreed about a
    declared file, the fast one would be changing what the registry says.
    """
    from pathlib import Path

    if not hasattr(yaml, "CSafeLoader"):
        pytest.skip("only one parser is available")

    root = Path(__file__).resolve().parents[3]
    files = sorted(root.joinpath("registry").rglob("*.yml"))
    files.append(root / "packages/comeni-core/src/comeni_core/diagnostics.yml")
    assert len(files) > 30, "the scan found almost nothing — it is not scanning"

    slow = _loader(yaml.SafeLoader)
    fast = _loader(yaml.CSafeLoader)
    for path in files:
        text = path.read_text()
        assert yaml.load(text, Loader=slow) == yaml.load(text, Loader=fast), path


def _loader(base):
    class L(base):
        pass

    L.add_constructor(
        yaml.resolver.BaseResolver.DEFAULT_MAPPING_TAG, yaml_strict._construct_mapping
    )
    return L
```

- [x] **Step 3: Swap the base**

In `yaml_strict.py`:

```python
try:  # libyaml, when PyYAML was built against it — 13.6× on the declared data
    from yaml import CSafeLoader as _Base
except ImportError:  # pure Python; identical behaviour, and the audit compared 53 files
    from yaml import SafeLoader as _Base


class _StrictLoader(_Base):  # type: ignore[misc,valid-type]
    """`SafeLoader`'s behaviour, refusing a repeated key rather than taking the last one.

    **The base is libyaml's parser where it exists**, which is a performance change and not a
    semantic one: the duplicate-key check lives in `construct_mapping` below, which is Python
    on both paths, and `start_mark` carries the line numbers on both. Audit A134 compared 53
    declared files under the two and they parse identically.

    The fallback is not decoration — PyYAML installs without libyaml, and a module that raised
    `ImportError` there would trade a performance problem for an availability one.

```

and `_construct_mapping`'s final line becomes `_Base.construct_mapping(loader, node, deep=deep)`.

**Update the module docstring**: it says *"`yaml.safe_load` stays the mechanism"*, which stops
being literally true. It becomes *"`SafeLoader`'s constructor set stays the mechanism"* — the
safety property is the constructor set, not the tokeniser, and that distinction is exactly what
makes the swap safe.

## Task 2: walk the layer once, not once per kind

**Files:**
- Modify: `packages/comeni-core/src/comeni_core/declared/layered.py`,
  `packages/mendel-resolver/src/mendel_resolver/layers.py`
- Create: `tests/test_declared_loading.py`

**Interfaces:**
- Produces: `layered.bucket(layers: Sequence[Layer]) -> dict[int, dict[DeclaredKind, list[Path]]]`;
  `stack(layers, kind, *, buckets=None)` — optional, so `Registry.load` and `Vocabulary.load`
  are unchanged.

**Measured:** one walk plus one bucketing pass is **7.3ms**, and it runs **five times** — once per
`DeclaredKind`. Removing four takes the load from 49ms to **~20ms**, and takes the ~2,960 `Path`
objects per load (A143) with it.

- [ ] **Step 1: Write the counting guards**

```python
# tests/test_declared_loading.py
"""How many times loading a registry reads each file.

**Counted, never timed.** A test asserting "the load takes under 30ms" fails on a busy CI
runner and teaches everyone to re-run rather than look. The redundancy this phase removed is
exactly countable, so the guard counts — and the numbers below are what the audit measured
before the fix: 5 walks, 5 bucketing passes per file, 217 parses for 39 files.
"""

from pathlib import Path

from comeni_core import yaml_strict
from comeni_core.declared import layered
from mendel_resolver import layers

ROOT = Path(__file__).resolve().parent.parent
REGISTRY = ROOT / "registry"


def _declared_files() -> list[Path]:
    return [p for p in layered._files(REGISTRY) if p != REGISTRY / layered.MANIFEST]


def test_the_layer_is_walked_once_per_load(monkeypatch):
    """Not once per `DeclaredKind`. Five kinds meant five walks."""
    walks = []
    real = layered._files
    monkeypatch.setattr(layered, "_files", lambda path: walks.append(path) or real(path))

    layers.load(REGISTRY)

    assert len(walks) == 1, f"the layer was walked {len(walks)} times"


def test_declared_kind_is_asked_once_per_file(monkeypatch):
    """The bucketing question has one answer per file per load, and it used to be asked once
    per file PER KIND."""
    asked = []
    real = layered.declared_kind
    monkeypatch.setattr(
        layered, "declared_kind", lambda path: asked.append(path) or real(path)
    )

    layers.load(REGISTRY)

    assert len(asked) == len(_declared_files())
    assert len(set(asked)) == len(asked), "a file was bucketed twice"


def test_each_declared_file_is_parsed_at_most_twice(monkeypatch):
    """A CEILING, not a target — and it is asserted so the refactor that would reach one
    stays visibly refused. Spec §3.3: getting to one parse means changing `Kind.parse` to take
    pre-parsed data across five kinds, measured at about 6ms, and it was declined.

    Two: once to bucket the file, once for the kind that claimed it.
    """
    parsed = []
    real = yaml_strict.load
    monkeypatch.setattr(yaml_strict, "load", lambda path: parsed.append(path) or real(path))
    monkeypatch.setattr(layered.yaml_strict, "load", yaml_strict.load)

    layers.load(REGISTRY)

    files = _declared_files()
    assert len(parsed) <= 2 * len(files), (
        f"{len(parsed)} parses for {len(files)} files — the redundancy is back"
    )
```

**`_files` and `MANIFEST` are private names**, and reaching for them couples this test to the
module's internals. That is the trade: the alternative is a timing assertion, and spec §3.4 is
why this is the better one.

- [ ] **Step 3: Add `bucket()`**

In `layered.py`, beside `declared_kind`:

```python
def bucket(layers: Sequence[Layer]) -> dict[int, dict[DeclaredKind, list[Path]]]:
    """Which files in each layer declare which kind — asked once, read by every kind.

    **`stack()` used to ask this per kind**, so a five-kind load walked each layer five times
    and parsed every file five times to read one line from it. Measured at 7.3ms per pass over
    the shipped registry, four of them pure repetition (audit A133, A143).

    Keyed by `Layer.index` rather than by name or path, because identity is the index —
    invariant 11, and two layers may share a name.
    """
    found: dict[int, dict[DeclaredKind, list[Path]]] = {}
    for layer in layers:
        nested = _nested_layers(layer.path)
        mine: dict[DeclaredKind, list[Path]] = {}
        for path in _files(layer.path):
            if path == layer.path / MANIFEST:
                continue
            if any(path.is_relative_to(other) for other in nested):
                continue
            mine.setdefault(declared_kind(path), []).append(path)
        found[layer.index] = mine
    return found
```

- [ ] **Step 4: Have `stack()` take it**

```python
def stack[K, T](
    layers: Sequence[Layer], kind: Kind[K, T], *, buckets: Mapping[int, ...] | None = None
) -> Stacked[K, T]:
    """Load one kind across a layer stack. Later layers win, and say so.

    `buckets` is `bucket(layers)`, computed once by a caller loading several kinds. Optional
    so `Registry.load` and `Vocabulary.load` — which load exactly one kind — stay unchanged.
    """
    known = buckets if buckets is not None else bucket(layers)
```

and the per-layer `mine = [...]` comprehension becomes:

```python
        mine = known.get(layer.index, {}).get(kind.which, [])
```

**Keep the comment that is there.** It explains that the layer rather than a subdirectory is
scanned, and why `registry.yml` is exempt — both still true, and both now facts about `bucket()`.
Move it there rather than deleting it.

- [ ] **Step 1: Write the failing test**

```python
# packages/mendel-api/tests/test_registry_cache.py
"""The loaded registry, cached on its digest.

The same shape as `services/checked.py`, which phase 4 built for `ops.check` — and for the same
reason: a digest is a key that a changed registry invalidates by construction, where a clock
serves a stale answer for exactly as long as it is wrong.
"""

from mendel_api.services import registry


def test_a_second_read_does_not_reload(monkeypatch):
    calls = []
    real = registry.layers.load
    monkeypatch.setattr(registry.layers, "load", lambda root: calls.append(root) or real(root))
    registry._load.cache_clear()

    registry.stack()
    registry.stack()

    assert len(calls) == 1, "the second read reloaded"
    registry._load.cache_clear()


def test_a_changed_registry_invalidates_it(monkeypatch, broken_registry_copy):
    """The half that must fail otherwise: a cache that never invalidates passes the test
    above perfectly."""
    from mendel_api.settings import settings

    registry._load.cache_clear()
    first = registry.stack()

    changed = broken_registry_copy(
        "tools/nf-core/fastqc/fastqc.contract.yml", "nf_process: FASTQC", "nf_process: OTHER"
    )
    monkeypatch.setattr(settings, "registry_root", changed)

    second = registry.stack()
    assert second is not first
    assert second.registry.contracts["nf-core/fastqc@0.12.1"].nf_process == "OTHER"
    registry._load.cache_clear()
```

- [ ] **Step 3: Write the service**

```python
# packages/mendel-api/src/mendel_api/services/registry.py
"""The loaded registry, for a registry in this exact state.

**Cached here and not in `mendel_resolver`.** A cache in a pure package is a module-level
mutable store on the path invariant 10 is about, and the 1346-test suite — the biggest single
beneficiary of phase 7 — is the caller a cache serves worst, because its tests mutate
registries in temporary directories. So the pure packages got *faster* (244ms -> ~20ms) and
this is the only place that remembers. Spec §3.1.

**Same key as `checked.py`**, and deliberately: the digest is 4.6ms over the shipped registry
and a changed registry invalidates it by construction.

**No single-flight.** Two concurrent cold requests both load; at ~20ms that does not matter,
and at 244ms it would have (audit A144).
"""

from functools import lru_cache

from comeni_core.artifact.digest import digest_of_directory
from mendel_resolver import layers
from mendel_resolver.layers import Layers

from mendel_api.settings import settings


@lru_cache(maxsize=4)
def _load(digest: str) -> Layers:
    """The digest is the argument rather than a global, so `lru_cache` does the invalidating
    and there is no hand-written expiry to get wrong."""
    return layers.load(settings.registry_root)


def stack() -> Layers:
    return _load(str(digest_of_directory(settings.registry_root)))
```

- [ ] **Step 5: Let the forge's ops take a preloaded stack**

`ops` loads internally in **five** places — `draft`, `model_fill`, `check`, `drift` and
`accept` — of which the API reaches **four**: `drift` and `check` on the read path, `draft` and
`accept` on the write path. Without this, the two slowest endpoints bypass the cache entirely.

Add an optional parameter to the requests the API sends:

```python
class DriftRequest(BaseModel):
    ...
    stack: Layers | None = None
    """A preloaded layer stack, when the caller already has one. `None` loads. The CLI never
    passes it; `mendel-api` does, because otherwise the endpoint this exists for is the one
    endpoint the cache cannot reach."""
```

with `stack = req.stack if req.stack is not None else layers.load(req.registry_root)`.

**Checked while auditing this plan, not assumed:** `Layers` is accepted as a field under
`extra="forbid"`, `model_dump()` succeeds, and `model_dump_json()` succeeds with `stack=None`.
And it does not reach the generated client — **no forge request model appears in the API's
OpenAPI schema**; only `DriftReport`, a response, does. So the field is safe on both counts.

   for a single kind. That is why `buckets` is an **optional keyword** rather than a required
   parameter — a required one would have been a breaking change to two public classmethods for
   no gain, since loading one kind has no redundancy to remove.
2. **The counting guards must reach `layered._files` and `MANIFEST`**, which are private. Named
   as a cost rather than discovered: the alternative is a timing assertion, and §3.4 is the
   argument for paying this instead.
3. **`Layers` as a field was verified rather than assumed**, and it works: accepted under
   `extra="forbid"`, `model_dump()` and `model_dump_json()` both fine, and no forge request model
   is in the API's OpenAPI schema, so the generated client does not grow a registry-shaped type.
4. **The API loads a registry in six places, not four**, and one module does it twice.
   `services/health.py` and `module_page.contracts_with_role` were missing from this plan's first
   draft — found by grepping for `layers.load` instead of listing from memory, which is the same
   habit that found the greedy route in phase 6.

**Known weak points, stated rather than hidden:**

- **Task 2 is the risky one.** It changes what `stack()` scans, and a bug there is a *loading*
  bug: a file silently dropped from a bucket would remove a contract from the registry, and the
  first symptom would be a routing change rather than an error. `make verify` plus Step 1's
  byte-diff are the two independent checks, and the counting guards do not cover it — a bucket
  that loses a file passes all three counts. **The golden files are what actually catch this.**
- **The cache makes `Layers` shared across requests**, so a mutation anywhere becomes a
  cross-request bug. Task 3 Step 4 says to check every call site; nothing enforces it afterwards,
  and a guard for it would be worth writing if anything ever does mutate one.
- **`refetchOnMount: false` is the aggressive half of Task 4.** With a 30s `staleTime` it means a
  screen remounted within the window shows cached data immediately — which is the point, and it
  is also the setting most likely to be the one somebody wants back.
- **Nothing here is measured on CI's hardware.** Every number is this machine, and the audit says
  so; the counting guards are what CI actually enforces, which is why they are counts.
