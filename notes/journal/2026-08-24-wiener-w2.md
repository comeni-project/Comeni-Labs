## What exists that did not this morning

`overview(state, declared)` in `wiener-core` replaces `stats()`: same §9.3 arithmetic, but every
declared process gets a row **before the run reaches it**, ordered by the artifact. That is what
lets it be the front door rather than a log — the table's length is known before the first event,
so it does not grow as the run discovers work.

`GET /api/runs/{id}/overview` and `/tasks` serve it. `run_task` gained four columns: three
derived (`peak_rss_bytes`, `realtime_ms`, `pct_cpu`) so the Tasks tab is an `ORDER BY` rather than
5,000 JSON documents, and `labels` — A200's resolution, written from the admitted event by the
*impure* projection, so `wiener-core` still never sees a lab string.

The screens: `Overview`, `TaskRow` with two callers and a test holding the count, `Tasks`
virtualised, `Failure`, `Menu`, and `Walk` — draw → keep → gate → run as one sequence.

**`--hover` now exists.** It was referenced five times in `frontend/src/build/` and defined
nowhere from Plan 3C until today, so five hover states were dead CSS — most of why the builder
felt inert. Writing the guard found two more: `--profiled` and `--settled` were names for tiers
that never existed in the palette.

## The defects, and where each came from

**Six were found by running it or by a guard, and none by a test written to pass.** The split is
the useful part.

| found by | what |
|---|---|
| **Checkpoint 1, on a real run** | `steps_finished` counted a process whose every task FAILED — `0d3a4e3d` read **2 of 5 finished with zero successes**. §5's one honest bar advancing on failure |
| **the drain test** | the console paged **once** at 200 and subscribed. Invisible on every run anybody had, because the largest is five tasks |
| **the drain test, again** | *mine*: the paging loop's `setEvents` updater closed over the loop's mutable `page`, and React runs updaters later. 437 events came back as 237 |
| **the gesture test** | the task row had no menu — the exact shape of bug *a menu on one page and nowhere else* describes |
| **rules-of-hooks lint** | a `useQuery` placed after an early return; five Graph tests failed with it |
| **checking against the artboards** | the overview was **missing a whole column**, and six smaller divergences |

**One guard proved nothing and passed anyway**, which is worth more than the defects. The
batching test asserted the events array had not changed synchronously after fifty messages —
true with the fix *and* without it, because React batches renders on its own. A guard that passes
on the code it was written to reject is a green tick over an open hole. The frame count is what
discriminates. That is A67's lesson from a new angle: a guard must be watched failing **against
the specific defect**, not merely watched failing.

## What a fresh reader gets wrong

- **"The plan was followed exactly."** Fourteen deviations are in its execution table. Two are
  structural: `OverviewOut.rows` is a declared shape rather than the plan's `list[dict]`, because
  an untyped generated client is the drift it exists to prevent; and the walk is **`Walk.tsx`,
  not `Rail.tsx`**, because `Rail.tsx` already existed as Plan 3C's side rail. The plan asked for
  a name that was taken.
- **"`steps_finished` is monotonic."** It is not and cannot be — Nextflow discovers tasks as
  channels emit, so a step with three tasks done is finished until a fourth is submitted. Pinned
  by a test, because the monotonic alternative is the one that looks better and is false.
- **"The old runs have the new numbers."** They do not. The migration back-fills nothing on
  purpose: the columns derive from `run_event`, so an old run re-projects if anybody needs it.
  Every run before today reports `null` for the three derived columns and for `tag`.
- **"The resource line is broken on the failed run."** It is absent, which is the rule working:
  half a comparison invites the reader to supply a ceiling they do not have.
- **"W2 is all Wiener."** Task 14 is a Mendel screen — §13's scope creep with a stated reason.
  It is built and still cuttable in one commit.
