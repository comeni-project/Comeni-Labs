## The rename keeps both ids, which is the point

```
proposed id : qc.index_stats
approved as : qc.idxstats
filled value: qc.idxstats
```

A rename is a judgement about somebody's suggestion. Keeping only the approved id would lose what
was judged, and the next reviewer reads a decision with no subject.

## Two audit-class findings, both in tests I wrote *after* the audit

The audit before execution caught one real thing: the test for the central claim — that approving
bypasses the candidate check — used a fixture whose only hole has **no candidates**, and
`Question.legal` returns `True` for a hole with none. `fill` would have accepted the value too.
Fixed before running: it now asserts the `MF0003` refusal first.

**Then execution found two more of exactly that shape, in `test_verify_with_proposals`:**

- **It never reached the rung it was testing.** `verify` stops on `complete` while any hole is
  open, so `loads` was `[]` and every assertion over it passed by being empty. Measured:
  `rungs reached: ['complete']`. The test now settles every remaining hole first and asserts
  `Rung.LOADS in rungs` before anything else.
- **Both halves asserted on `Diagnostic.summary`**, which is a fixed sentence for the whole rung
  — *"the layer stack does not declare something this contract names"* — and never names the
  type. `detail` is the field that carries it. **The negative half is what caught this**: it
  failed, and it should have passed.

**The lesson is not "write more tests", it is "write the half that must fail".** A single positive
assertion cannot tell you it is vacuous; adding *the same draft without the approval must still
be refused* found two defects in one run. Then reverting the wiring turned the positive test red
and restoring it turned it green — watched, per `CLAUDE.md`.
