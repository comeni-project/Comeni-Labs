# 2026-08-19 — Plan 3A phase 7: responsiveness

**This phase did not exist this morning.** It was created by a measurement: the operator asked
whether the tool was fast enough — *"max like half a second for normal stuff doing in the browser.
it's a tool, not a server"* — and nothing had ever been timed. Compose became phase 8, and 3A is
nine phases rather than eight.

**Audit:** [`../audits/2026-08-19-performance-audit.md`](../audits/2026-08-19-performance-audit.md),
A132–A145. **Spec:** [`../specs/2026-08-19-responsiveness.md`](../specs/2026-08-19-responsiveness.md).
**Plan:** [`../plans/2026-08-19-plan-3a-phase-7.md`](../plans/2026-08-19-plan-3a-phase-7.md),
28 steps, all ticked.

## Before and after

Every number measured on this machine with the same harness, before and after.

| | before | after |
|---|---|---|
| `GET /api/contracts` | 253 ms | **10 ms** |
| `GET /api/sources` | 249 ms | **8 ms** |
| `GET /api/contracts/{id}` | 253 ms | **6 ms** |
| `GET /api/contracts/{id}/drift` | 263 ms | **8 ms** |
| `GET /api/registry/types/{id}` | 246 ms | **5 ms** |
| `layers.load` | 244 ms | **17.8 ms** |
| `mendel build` | 1.47 s | **0.38 s** |
| the fast test suite | 207 s | **60 s** |

- `make verify`: **exit 0**.
- Frontend: **68 tests**, `tsc`, `oxlint` and `vite build` clean.
- **The emitted pipeline is byte-identical** to the pre-phase build, checked by building on both
  sides of the change and diffing the whole output directory.

That last line is the one that matters. This phase rewrote the loader every declared file passes
through; invariant 10 says same goal → byte-identical `.nf`, and a loader change that altered one
digest would be a correctness bug wearing a performance costume.

## What was actually wrong

**One function, called from everywhere.** Not a codebase full of inefficiency — the audit went
looking for that and recorded the negative result as A141: the module page's whole graph is 1.9ms
at 2000 contracts, `candidates.for_field` is 0.1ms, and no handler blocks the event loop.

Two defects inside `layers.load`:

- **The layer was walked five times per load** — once per `DeclaredKind` — and each file was
  parsed to read its `declares:` line on every pass. 217 parses for 39 files.
- **libyaml was installed and unused.** `yaml_strict` subclassed the pure-Python `SafeLoader`;
  `CSafeLoader` is 13.6× faster per file.

**The base-class change alone took the test suite from 207s to 60s.** One line.

## Three decisions worth carrying

**Speed in the pure packages, caching only at the API.** A cache in `comeni-core` or
`mendel-resolver` would be a module-level mutable store on the path invariant 10 is about — and
the 1346-test suite, the biggest single beneficiary, is the caller a cache serves *worst*, because
its tests mutate registries in temporary directories. So the pure packages were made faster
(244 → 17.8ms) and `mendel-api` is the only thing that remembers. The cost of that line is ~18ms
instead of ~5ms in the CLI, which nobody feels.

**The performance property is guarded by counting, never timing.** `tests/test_declared_loading.py`
asserts the layer is walked once, `declared_kind` is asked once per file, and no declared file is
parsed more than twice. A millisecond budget on a CI runner is a flake generator that teaches
people to re-run; a count that must equal the file count fails loudly and for one reason.

**The frontend was configured to distrust its own cache.** `new QueryClient()` with no options
means `staleTime: 0` and `refetchOnWindowFocus: true` — every navigation and every alt-tab
refetching a 250ms endpoint. Every mutation since phase 2 already invalidates precisely, so the
defaults were hiding latency behind more latency.

## What the tests caught that the plan did not

**The parse-count guard corrected itself.** It first asserted a *total* of `2 × files`, which
looks equivalent to *"no file more than twice"* and is not: `registry.yml` is read once by
`layer_name` and is not a declared file, so the honest count was 73 for 36 files and the test
failed on arithmetic rather than on a defect. Counting per file says what is meant and needs no
fudge term — and the manifest now has its own one-line test.

**The third cache test caught the thing the wiring missed.** Two of six call sites were reading
through the cache and the endpoints were still slow, because `ops.check` and `ops.drift` load a
registry *internally* — so the two endpoints the cache exists for were the two it could not reach.
A test that counted loads across three service calls found it; a test that asserted "the service
returns the right rows" never would.

**The plan's own audit found two more before a line was written.** `Layers` works as a pydantic
field under `extra="forbid"` and does not reach the generated client (checked, not assumed), and
the API loaded a registry in **six** places rather than the four the first draft listed —
`services/health.py` and `module_page.contracts_with_role`, found by grepping for `layers.load`
instead of listing from memory.

## What is still true and was not fixed

- **A138 — the digest key is O(files).** 4.6ms at 39, 240ms at 2039. Right at today's size; at
  the 5,800 the design talks about, the *key* becomes the cost. The answer there is a key that is
  not O(files), and nobody is near it.
- **A142's second half — `REGISTRY` is eager at import.** The libyaml swap took it from 69.5ms to
  ~4.8ms. Making it lazy would save the rest and give up the guarantee that an undeclared
  diagnostic code is unrepresentable, which is worth more than 4.8ms.
- **One parse per file.** Each declared file is still parsed twice — once to bucket it, once by
  the kind that claimed it. Getting to one means changing `Kind.parse` to accept pre-parsed data
  across five kinds. **Measured worth: about 6ms.** Refused, and asserted as a ceiling so the
  refusal stays visible.
- **`module_page.contracts_with_role` loads a whole registry to answer one question about roles.**
  The cache makes that free rather than making it right.

## What is next

**Phase 8 — compose and prod**, which now packages a fast application rather than a slow one.
Its spec and plan are already written and audited; only the execution is left, and then 3A is
complete.
