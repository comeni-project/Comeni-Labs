## The loop that produced this, and why it worked

**Spec → plan → audit the plan → execute → journal.** The operator's protocol, unchanged across
four phases. The audit step is the one that earned its place:

| Phase | What the audit found before a line was written |
|---|---|
| 1 | a test asserting on `window.location`, which `MemoryRouter` never writes — it passed on `""` and could not fail |
| 1 | `test_visits.py` needed Postgres; **CI has none**, and no existing API test touches the database |
| 2 | `ShowResult` did not carry `proposed`, so the API could write a proposal and never read one back |
| 3 | the test for *"approving bypasses the candidate check"* used a hole with **no candidates**, where `fill` would have accepted the value anyway |
| 4 | **`unverifiable` and "no module file" are different conditions** — the spec said they were the same |

Four of those five are the same shape: **a test that cannot fail**. Two more of that shape were
found during execution, in tests written *after* their own audit — phase 3's verify test never
reached the rung it tested, and both its halves asserted on a `Diagnostic` field that never names
the type.

**What catches them is writing the half that must fail.** A single positive assertion cannot tell
you it is vacuous. Adding *the same draft without the approval must still be refused* found two
defects in one run.

## Five things that shipped wrong and were caught by running them

1. **The queue sorted backwards.** `aggregate` sorted on `Band`, a `StrEnum`, so bands compared
   alphabetically — cosmetic above routing, the exact inverse of consequence order. It ran that
   way for a whole phase because **nothing asserted an order across bands**.
2. **Every `/forge/*` URL 404'd.** The frontend's routes and the API's forge mount shared a
   prefix, and on one origin the dev proxy resolved it in the API's favour. Invisible to every
   test — client-side navigation never leaves the SPA, so only a refresh or a pasted link fails.
   The API moved under `/api`.
3. **`oxlint` could not run at all** — npm's optional-dependency bug, the second instance in this
   frontend after rolldown.
4. **A stale `uvicorn` served pre-change code** for a debugging round. `pgrep -af uvicorn` before
   believing a 404.
5. **Four separate assertions matched twice** because `Refusal` deliberately renders a code in the
   message *and* in the `forge explain` hint. It is a rule now, not a surprise.

## What is true that a fresh reader will doubt

**The forge works end to end, in a browser, against a real registry.** Draft a module, watch its
questions sort by consequence, answer one or answer it across every draft asking, decline what
does not fit, approve it under a better name, and land the contract with its new type in one
commit. Every value carries who set it and why, and `forge show` proves it.

**Landing was actually run** — into a throwaway clone, producing one commit with
`types/qc.idxstats.yml` beside the contract.

**The partial batch was exercised deliberately**, not hoped for: filling one port's type
differently on two drafts makes their dependent name candidates diverge, so one accepts `input`
and the other refuses it with `MF0003` — and the refused draft is `null` on disk, not half
written.

## What is not true, and would be easy to assume

- **Nobody has clicked any of it.** Every phase was driven with `curl` through the Vite proxy and
  by loading each URL. The mouse path has 52 component tests against a mocked `fetch` and no
  human.
- **The confirmable band has never been seen.** Nothing has run `forge fill --model` over a draft,
  so `suggested` is `null` everywhere and the `MODEL` marker exists only in a test. **The band the
  design most wants you to see is the one nobody has.**
- **No AI is wired into the interface at all**, and none is planned before 3C.
- **Three phases remain**: drift (5), sources and drafting (6), compose and prod (7). Then 3B, the
  landing page, and 3C, Mendel.

## Two costs written down before they bite

**`ops.check` is 0.40s for twelve contracts and roughly three minutes at 5,800.** It is cached on
the registry digest, so it runs once per registry state — but the cold path is the first thing
that breaks at scale, and the fix is a table the worker writes, deliberately declined for now.

**`queue.read()` re-reads every draft on every request, and `answer_all` reads them all again.**
Fine at two drafts. Measure before designing around it.

## What is next

**Phase 5 — drift.** Every field checked rather than only the one that differs, and a verdict
derived from the field rather than hardcoded: *does this change what gets built?* A container bump
and a `type_id` change are wildly different events. The contracts list already has the facet, and
it currently reads `0`.
