## What you can do now

Break a contract, and the row is **first in the queue**, above every question. Follow it to
`/forge/contracts/<id>/drift` and read what moved, what each side says, the line in the module it
says it at, and a verdict answering *does this change what gets built?* Take the source's value,
and one commit lands on `forge/drift` with your name and your reason. The row leaves the queue and
the contract reads `matching`.

**That loop was run end to end**, against a real clone with a real drift in it, and `git show` was
read afterwards rather than assumed:

```
forge: nf-core/fastqc@0.12.1 container -> quay.io/biocontainers/fastqc:0.12.1--hdfd78af_0

the vendored module was bumped and the registry tag was left behind

Accepted by rafael.

 tools/nf-core/fastqc/fastqc.contract.yml | 2 +-
```

Queue `total: 0` afterwards, facet `{drifted: 0, unverifiable: 2, matching: 10}`. Before the
accept it read `drifted: 1, matching: 9`.

All three refusals were checked by hand against a real checkout, not only in tests: **MF0105** on
a detached HEAD — which is what the default configuration is, `registry/` being a submodule —
**MF0101** on a dirty tree, **MF0104** on a field that has not moved. Each is one sentence with a
code, not a stack trace.

## The four decisions worth carrying

**Two checkers ask this question and they overlap.** `ops.check` compares three values a source
states; `conformance` compares structure and emits MD0101–MD0108 — and MD0101 *is* `nf_process`,
MD0107 *is* `container`. They are not merged, because one must be able to refuse a build and one
must only report. What is declared instead is the coverage: one table in `mendel_forge/drift.py`,
with a totality test on each half.

***"Every field checked"* is only honest if you name what nothing checks.** Three groups, all
thirteen fields: value (3), structure (4), **nothing (6)**. And the uncomfortable half is on the
screen rather than in a spec — `consumes`, `roles`, `priority` and `id` are read by the router and
verified by nothing at all. A port's `type_id` is the most consequential value in a contract and
no source can state it.

**The verdict is a fold, never a case analysis**, over a three-way impact classification read out
of `router.py`, `resolve.py` and `emit.py`. Binary was the obvious design and it is wrong: the
design's own sentence — *"nothing routes differently, `container` is not read by the router"* —
does not say nothing changed.

**Accepting patches one line.** `samtools/index.contract.yml` carries eight comments that *are* its
reasoning, and a YAML dumper deletes every one. The patched text is validated through
`ModuleContract.load` — the real loader, vocabulary and all — before anything is written.

## What the audit of the plan found, before a line was written

Ten things. Three changed the shape of the phase:

1. **`ops.update` re-opens every hole.** It re-drafts from source and prefills nothing from the
   landed contract, so accepting a container bump would re-ask every port type a human settled
   last month. That is why accepting is a patch and not a re-draft.
2. **`GET /contracts/{id:path}` is greedy and phase 4 registered it first.** A drift route added
   after it fails as a **200 carrying the module page**, which no ordinary test would catch.
3. **`/forge/contracts/*` is a splat**, so `:id/drift` cannot be a second react-router pattern.

Two were tests that could not have failed:

4. **`fastqc.contract.yml` has zero comments**, so the comment-survival test — which holds the
   whole argument for patching a line — would have passed over its own guard. Counted rather than
   assumed: `star/align` 11, `subread/featurecounts` 10, `samtools/index` 8, fastqc **0**.
5. **`Controls.tsx` hand-listed three bands**, so `blocked` had been unreachable from the UI since
   phase 3 and no test noticed. Found while checking where `drift` needed adding.

## Five things that shipped wrong and were caught by running them

1. **A guard nobody remembered caught the write in the wrong file.**
   `test_only_land_and_the_workspace_write_to_disk` scans `mendel_forge/` for `.write_text` and
   allows exactly `land.py` and `workspace.py`. `ops.accept` wrote a contract — so the code moved
   into `land.py`, which is what its own docstring says it is: *the only thing in the package that
   writes under a registry root*. **The guard was not widened**, and that is the whole point of
   the entry: the allowlist was the cheaper fix and the wrong one.
2. **`container: >-` was patched rather than refused.** MF0102's guard tested
   `line.startswith("container: ")`, which a block scalar satisfies — so the header would have
   been replaced and its body orphaned. Found by writing the test that makes the refusal
   non-vacuous, which is the fifth time that habit has paid this month.
3. **One drift produced two queue rows.** `container` is checked by both checkers, so a single
   bumped tag rendered twice, with the same subject, leading to the same screen. The drift
   *screen* still shows both — that is the declared coverage — but a queue row is a piece of work
   and that was one piece of work. Invisible to every test until the thing was run.
4. **`verdict_for(refusing=…)` was passed every diagnostic**, not the refusing ones. MD0100 warns
   and never blocks, so a contract with no module source would have read as one that cannot be
   built. Nothing reaches it today; the parameter was named for a property nothing checked.
5. **The required `why` made a test look like a broken mutation.** The accept button is disabled
   until a reason is typed — which is the rule the screen exists to enforce — and the first
   version of the refusal test clicked it without one.

## What is true that a fresh reader will doubt

**A container bump reads `breaks`, not `rebuilds`, and that is correct.** MD0107 *refuses*, so a
contract whose container disagrees with its module cannot be emitted at all. The design's worked
example — *"nothing routes differently, `container` is not read by the router"* — was written
before conformance covered `container`, and the code is stricter than the design assumed.
`REBUILDS` is reachable through `nf_include`, which no conformance check reads.

**`REROUTES` cannot fire from a value check.** Every field a source states outright is `BUILDS`.
The branch is exercised by a unit test calling `verdict_for` directly, and it is written down
twice because a verdict with one reachable branch reads like a working verdict.

## What you still cannot do

- **Nothing knows what upstream says.** [#64](https://github.com/comeni-project/Comeni-Labs/issues/64).
  Every check here is the registry against the **vendored** copy, and no screen may imply a newer
  version exists.
- **Nothing schedules the check.** `checked_at` is real; *"next nightly"* is not, and the cron
  lands with Compose in phase 7 where there is a Redis to run it.
- **A structural disagreement has no resolution path** but a re-draft that re-opens every hole.
  Fixing that means seeding a re-draft from the landed contract, which is its own piece of work.
- **Nobody has clicked any of it.** The whole walk-through was `curl`; the screen has nine
  component tests against a mocked `fetch` and no human. That is now six phases running.
