# The gate — Mendel's half of the execution boundary

**2026-08-23**, branch `mendel-wiener-boundary`, unmerged.
Plan: [`../plans/2026-08-23-mendels-half-of-the-boundary.md`](../plans/2026-08-23-mendels-half-of-the-boundary.md)
Spec: [`../../docs/design/execution-boundary.md`](../../docs/design/execution-boundary.md)

Seven tasks, 52 steps, all executed. `make verify` green — 1509 backend tests, 5 counts-matrix,
75 guards — plus 189 frontend tests, `tsc -b` clean.

**The loop closes.** Draw a pipeline, keep it, gate it, read the verdict. Measured end to end
through the real stack: `lint` **1.6s**, `preview` **~10s**, and the route that starts one
returns in **5ms** because it writes a row and hands the work to ARQ.

---

## What this was

The operator asked to move toward running pipelines for the MVP, and asked whether that was
another Lab's job. It is — **Wiener's**, not Nightingale's — and the question turned out to be
worth a spec before a plan, because the boundary was documented three times in three
incompatible ways.

The thing that unlocked it was noticing that **"schedule" was doing three jobs**:

| Level | What | Who |
|---|---|---|
| **task** | order STAR before samtools, submit, retry, resume | **Nextflow**, mature |
| **run** | accept a run, launch and supervise it, relaunch it, remember it | **Wiener**, zero lines |
| **fleet** | cost, drift, quotas | Wiener, later |

Dispatch-and-check-and-retry *is* Wiener's whole purpose — at the **run** level. What it must
not do is the task level, because that is a workflow engine and a second one would be worse.

Mendel's half is what this branch built: **emit for any executor, and gate its own artifact.**

## The two rules that constrained the code

**§6 — the executor never enters the artifact.** Made executable as a *signature*:

```python
assert list(inspect.signature(emit_config).parameters) == ["pipeline"]
```

A one-parameter signature **cannot express** a per-target emission, so it fails when somebody
reaches for the wrong design rather than after they have threaded it through and
`Pipeline.emitted`'s digests already depend on a deployment choice. Watched failing; in the
ledger.

**§3 — a gate and a run must not share a label.** The builder had a disabled *Run pipeline*
button whose tooltip read *"Running a pipeline is Wiener's job, and Wiener is not built."* Still
true. It is now **Keep** and **Gate**, and that sentence lives in `Gate.tsx` and in a test.

## Three things found by executing that neither audit pass caught

The plan was audited twice before a line was written — seventeen findings, three critical. The
audit was worth it. It was also not enough, and the pattern in what it missed is the useful part.

### A175 — `MA` was already taken, and a comment said otherwise

The audit moved the new diagnostic off `MD` (correct — `MD` is reserved for the three pure
packages) and onto `MA`, on the strength of the header sentence in `diagnostics.yml`:

> `MF`, `MA` and `MI` belong to the forge, the API and the AI adapters

`MA0001`–`MA0007` have belonged to the **AI adapters** since forge phase 2. The sentence was
wrong positionally, and nothing had ever caught it because no API code existed to collide.

**A31's strict loader caught it** rather than letting the second win:

```
DuplicateKeyError: 'MA0001' is declared twice, at line 1868 and line 2132.
```

The code is `MI0001`. The sentence is corrected. **The lesson is about method**: in the same
audit I verified `concern: artifact` was illegal *by reading the generator*, and took the prefix
*from a comment*. One habit found a bug; the other made one.

### A176 — nothing in the browser had ever called the draft routes

3E built `POST /drafts`, `PUT /drafts/{id}` and `POST /drafts/{id}/keep`, and **wired none of
them**. `useGraph`'s 5-second idle save takes a `save` callback that no caller passes, so it has
never fired in production either.

Neither audit pass could have found it: both checked what the plan *said* against the code, and
this is a fact about the code the plan **builds on**. It surfaced the moment a gate needed an
artifact and there was no draft id in the browser to name one.

So Task 6 grew `useKeep` and an explicit **Keep** button. That is a scope addition and it is the
honest one — a Gate button with no draft id is the disabled control 3C shipped and the operator
rejected.

### Installing Nextflow is not one `curl`

`get.nextflow.io` installs a **launcher**; the real jar downloads on first run. Left alone that
download happens *inside the first gate* — as a non-root user, against a root-owned `NXF_HOME`,
needing the network, arriving as a confusing gate result. The launcher also writes a temp file
into its **working directory** while downloading:

```
mktemp: failed to create file via template '/app/nxf-tmp.XXXXXX': Permission denied
```

`nextflow -version` now runs at build time, before the chown and while `/app` is still
root-writable. The image is self-contained and an air-gapped install works.

## Two defects the plan found before execution

Both by asking *what does a container actually do* — phase 8's method:

- **`MENDEL_DRAFT_ROOT` had no volume.** Set on `api` and `worker`, backed by nothing, so `keep`
  wrote into one container's ephemeral layer and the worker could not see it. A gate would have
  run `nextflow` in a directory that does not exist and reported a Nextflow error — *a true
  message about the wrong thing.*
- **The runtime image had no Nextflow and no Java.** Invisible because `run_gate` degrades
  honestly rather than crashing.

## Two predictions the plan got wrong, both in the good direction

Recorded because a plan that is only ever wrong pessimistically is a plan nobody calibrates.

- **"Task 1 Step 8 is where it will run long."** Regenerating recorded digests has broken tests
  every previous time emission changed. **Nothing moved.** The golden diff was purely additive —
  15 insertions, 0 deletions — and `make verify` went green first try. The committed fixtures
  carry no `emitted:` block this touches, and the archived v1 fixture predates the record.
- **"If PREVIEW fails on a null parameter, that is the finding."** It passed. `-profile
  stub_data` supplies the params and `-preview` builds the DAG without reading them.

## What is deliberately not built

**STUB and TEST cannot run in the container.** They pass `-profile ...,docker` and need a
daemon, which means mounting the host's Docker socket into the worker — **root-equivalent access
to the host**. That decision is not taken here; §8 leaves it to Wiener, which has to solve
isolation anyway. `LINT` and `PREVIEW` need no Docker, so the loop closes without it, and a test
holds the UI to offering only those two.

---

## What a fresh reader gets wrong

- **"Mendel does not run Nextflow."** False, and always was. `Gate.TEST` has been a real
  `nextflow run` since Plan 1.5. The true statement is narrower: *Mendel runs its own artifact
  against data somebody else published, and never a laboratory's data.*
- **"The Run button was removed because running is unimplemented."** It was replaced because
  *run* is the wrong word for what Mendel does. Gate and Run are different operations with
  different data, and the test between them is one question: **does it take a samplesheet?**
- **`gate_run` is not run history.** It remembers gates. The day a row there carries an input
  path, the boundary has moved without anyone deciding to move it.
