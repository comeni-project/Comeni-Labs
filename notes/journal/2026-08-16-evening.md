## #43 — declared data is files, and that is the convention rather than a local quirk

The question was whether to collect the data into one SQL database that auto-generates a
human-readable table. The answer is no, and
[`docs/design/declared-data.md`](../../docs/design/declared-data.md) is the argument.

**Two things made the question easier than it looked.** The generated table it asked for already
exists — `diagnostics.yml` plus `tools/generate_diagnostics_doc.py` is exactly the shape
TypeScript (`diagnosticMessages.json`) and Rust (a generated error index) use, and it got its own
page earlier the same day, after the issue was filed. And most of what *looks* like a table in
this repository is not data: `_OPS`, `_REDUCERS`, `DOORS`, `_TIMEOUTS` map names to functions and
types, which no database can hold.

**The evidence is external on purpose**, because the operator asked what the convention is
"regardless of current rules inside this repo". Every comparable curated catalogue — nixpkgs at
100k+, Homebrew, conda-forge, Bioconda, nf-core modules — keeps its data as files in git. The
honest counterexample is crates.io moving its index off git around 2023 for performance, and it
does not transfer: crates.io is machine-published, so it had no review step to lose.

**A database stays legitimate as a derived, gitignored index** if loading ever becomes measurably
slow. At 37 files it is not, and building one now would be optimising an unmeasured cost.

**The substantive half was split out as [#49](https://github.com/comeni-project/Comeni-Labs/issues/49)**
rather than closed with the rest: `MD0000`–`MD0099` is reserved for "loading declared registry
data" and is empty, so a malformed contract surfaces as a Pydantic traceback while every other
stage refuses with a code, a subject and a fix. That is the real complaint under the question.

### What the plan did not predict, and it was not small

**The layer digest became machine-dependent.** The submodule puts `LICENSE`, `README.md` and a
`.git` *file* beside the declared kinds, and that file reads

## A130 — human, model, or none

The operator asked what best distinguishes the three. It takes two fields, because the per-value
answer and the "none" answer need different kinds of evidence.

# One source for a diagnostic code

The operator asked whether `diagnostics.md` is generated and whether a code has one source of
truth that moves when the code moves. **The document half was already true**; the emission half
was not.

## What was wrong

`comeni_core/diagnostics.yml` has always been the only place a code is *declared*, and
`docs/reference/diagnostics.md` has always been generated from it in full, with `make docs
--check` on every pull request. Nothing there needed changing.

But **twelve of ninety emission sites were validated and seventy-eight were string literals** —
`raise ValueError(f"MD0001: {where} is not valid YAML")`. Nothing tied the code to the registry.
A typo would ship, print to a user, fail `mendel explain`, and never appear in the generated
page. Every code in source happened to be declared, which is correctness by vigilance.

The repository already had the answer and had applied it once: `Diagnostic.code`'s validator,
whose docstring says *"This makes an undeclared code unrepresentable — invariant 7's shape, a
closed vocabulary, applied to diagnostics."* It was never extended to the other seventy-eight.

**`coded()` is that extension.** A string builder rather than an exception factory, because
twelve exception types carry codes and several emissions are not raises at all — the CLI prints
`mendel: MD0210: …` and `MD0202` is a report line.

## Both directions, and the reason neither half is enough

`coded()` refuses an undeclared code — but only when the error path runs, and **a diagnostic's
error path is by definition the one a green suite does not take.** That is A14's argument
arriving at the one part of the system that is *only* error paths. So the static scan is not
belt-and-braces; it is the half that runs at all.

The scan also gives the second direction, which is the operator's decision: **a declared code
that nothing emits is refused.** It would otherwise appear in the generated page and answer
`mendel explain` while being unable to happen — documentation of a refusal that does not exist.
Reserving a *band* stays legal, because that is a comment rather than an entry.

**`UNLOCATABLE` is deleted rather than emptied.** It held one code and existed only because
three emission shapes had to be matched by pattern. With one shape there is nothing to exempt:
the list was a symptom of the thing this change removed.

## The conversion was where the mistakes were

Three, and all three produced **syntactically plausible output**:

- A regex left unbalanced parentheses. The messages are implicit multi-line concatenations, so
  the closing paren belongs after the *last* adjacent literal, not the first.
- `ast` reports column offsets in **UTF-8 bytes**, and these files are full of em dashes and
  arrows. Slicing by character silently duplicated the tail of every long message.
- A `Constant` inside a `JoinedStr` matches the same test as the `JoinedStr` — `f"MD0306: {x}"`
  yields both — so seventeen messages got one replacement nested inside another.

**All three were caught by reading the diff of one file before converting the other sixteen.**
That step was in the plan because a mechanical edit across seventeen files is exactly the change
whose failure is cheapest to bisect and most tempting to batch. It earned itself three times in
one afternoon.

A fourth, smaller: an import inserter that looked for a line starting with `from` spliced an
import **into a docstring** — the sentence was *"…indistinguishable\nfrom filenames…"*. The AST
knows which lines are imports; a regex does not.

## Two things worth keeping

**`marks.py` cannot import `diagnostics` at module level.** `diagnostics.py` imports `Line` and
`Text` from it, so the import is the cycle that file's docstring exists to warn about. Two
function-local imports, on the precedent of `Pipeline.of`.

**A revert-and-watch loop left stale bytecode.** Restoring a file byte-for-byte can reproduce its
size and mtime, so CPython reuses the cached `.pyc` and the *reverted* code keeps running — a
test failed against a message the source plainly no longer contained. Clear `__pycache__` after a
loop that restores files. This ledger is built on revert-and-watch, so that is worth more than
the twenty minutes it cost.

## The canary held

`docs/reference/diagnostics.md` is **byte-identical** across seventy-eight converted sites, and
so is a built `pipeline.yml`. Nothing about what a code *says* moved, which was the whole claim.
One intended output change, predicted in the spec: `MD0202` was `  MD0202  line` and is
`  MD0202: line`, because `coded()` writes one format and a report line is not worth a second.

## Five things found that the plan did not predict

1. **`kind:` was the wrong key.** `Measurement` already has one, meaning the kind of its *value*
   (`integer`, `enum`). The first implementation stripped it and broke every measurement. It is
   **`declares:`**.
2. **A layer could swallow a layer nested inside it.** Globbing the whole layer meant an overlay
   checked out *inside* the public registry loaded as the base layer's own files. A directory
   carrying `registry.yml` is now recognised as a layer and skipped.
3. **`MD0005` refused a legitimately empty overlay.** It refuses only a *completely* empty
   directory now — the unchecked-out submodule it was written for.
4. **The digest's extension allowlist swallowed `.github/ci.yml`.** Dot-prefixed paths are
   excluded. Caught by the guard written for issue #46's `.git` file, which is the second time
   that guard has paid for itself.
5. **`MD0003` is retired.** It refused a `.yml` no kind read — prevention *by construction*,
   because the directory was the file's identity. A file that declares itself loads from
   anywhere, so **A26 moves from detected to prevented** and the code can no longer fire.

## The part to learn from, because it cost the evening

**The fixture sweep took several hours and should have taken one.** About thirty test files build
layers by hand, and every one wrote files that no longer announced themselves.

- **A first codemod patched by *basename across every file*.** `a.yml` was labelled a measurement
  in one test and a contract in another, and both labels landed on the same write — 24
  `DuplicateKeyError`s from one bad rule.
- **The working mechanism is one helper that derives the kind from the directory at *runtime*,
  and it must walk *ancestors***, not the immediate parent: `contracts/nf-core/fastqc.yml` sits
  two levels below the directory that names it.
- **The loop was the real cost.** Run a 2.5-minute suite, patch one batch, re-run. **One
  diagnostic run collecting every failure, then one fix pass, is worth ten of those** — and the
  moment that pattern appears is the moment to stop and say so rather than push through it.
