# 2026-08-16, evening — issue #41: code and documentation organisation

**Eleven tasks, one branch, nothing deferred.** The complaint was that `ls docs/` showed the
working record before it showed anything a reader wanted, `comeni_core/` was twenty-four flat
modules, and the error codes were two-thirds of the way down a page about CLI flags. All three
are fixed. Read [the spec](../specs/2026-08-16-code-and-documentation-organisation.md) for the
argument and [the plan](../plans/2026-08-16-code-and-documentation-organisation.md) for the
tasks, each with its corrections recorded inline.

## The evidence that nothing moved

`tools/refactor_oracle.py` existed for one job: a pure reorganisation must produce a
byte-identical pipeline. It built the RNA-seq spine and digested the three emitted files, and it
was run after every task.

```
pipeline.yml       f1f2d7e5e9cca6a3
main.nf            76355bbf9f10d6e6
nextflow.config    72ddb081638edf76
```

**Recorded on `main` at `7315347` from two independent builds that agreed, and unchanged through
all eleven tasks.** It is deleted now — its whole value was in being written *before* the work,
and a checker kept afterwards would be asserting that today's output matches today's output.

It never caught a regression. That is worth saying plainly rather than dressing up: it was
cheap insurance that did not pay out, and the reason to have written it is that the branch moved
every module in `comeni-core` and split three more, and `make check` alone cannot tell a
relocation from a rewrite.

## What the tasks found that the plan did not predict

**Three plan-ordering defects, all the same shape.** Task 5 was written to repair paths that Task
1 breaks, so Task 1 could never end green; Task 8's front door links to two files Task 9 creates,
so Task 8's own `make links` step could not have passed. Both fixed by moving the work, both
recorded in the plan rather than smoothed over. **A plan that verifies at every task boundary has
to be written in dependency order, and reading it forward is not enough to see that** — the
breakage is always in the task *before* the one that repairs it.

**The spec's "one module per verb" was wrong.** Three of the six CLI verbs share the entire
resolution flow, so splitting by verb would have duplicated it three ways. `cli/` splits by *what
a verb does to a pipeline*: `resolve_verbs` produces one, `artifact_verbs` acts on one that
exists, `report` prints, `parse` reads arguments. Recorded in Task 4.

**Six `monkeypatch.setattr(cli, "run_gate", …)` sites broke on that split**, because `run_gate` is
looked up in the calling module and the calling module changed. One test needed two patches where
one had done — `test_a4_a_failed_gate_publishes_nothing` builds and then publishes, so the gate is
invoked from both modules. **Nothing in the repository had recorded that the gate runs twice
there**; the split is what surfaced it.

**A guard that scanned nothing reported nothing and passed.** `test_architecture.py`'s first
version filtered by `{".venv", ".worktrees", …} & set(path.parts)` — and this repository's plans
execute in `.worktrees/<name>/`, so every path matched and the scan skipped the whole repository.
It passed while sitting on the file that holds the string it searches for. Fixed by enumerating
roots; then emptying the roots tuple was watched doing the same thing, so `len(paths)` is asserted
now. **Same defect as `make drift`'s `REGISTRY ?= ../comeni-registry`**, twice in two plans from
two authors, and it is A67's silent direction: the check goes green *faster*.

**The diagnostics generator could not see a hand edit outside its markers.** It spliced a table
into `cli.md` and read the surrounding text back out of the file it was comparing against, so the
header and prose were equal to themselves by construction. The whole page is generated now, and
`make docs` refuses a hand-edited heading — watched.

**`contributing.md` carried seven root-relative links that no gate had ever checked**, because the
file was at the root when they were written. Every one broke on the move to `docs/guides/`. That
is the case for `make links` in one sentence.

## The link checker

Written and run **before** the move, which is what makes its report attributable — a checker
introduced after a repair can only confirm a repair somebody already believed in. It found six
broken links in `docs/` and the root on the pre-move tree, and reports **zero** now.

It skips fenced code blocks (a first draft reported eleven `assert x == [a, b]` lines as links,
and a checker whose output is mostly noise is one people stop reading) and it does not check
`notes/`, because a plan naming files its own tasks create is correct when it executes and broken
until then.

## What is not done

**`ARCHITECTURE.md` describes five stages, and `comeni-core` now has five directories named for
them.** That correspondence is real and it is not enforced. Whether the two should be generated
from each other — or whether a test should assert the directory names against the stage names —
is a question this plan did not answer and did not pretend to. It is the obvious next thing for
somebody who wants the layout to stay honest.

**A tier-4 setting's own `why.reason` stays stale after a human answers it.** Writing
`human_override` and `override_reason` in `decisions:` is the documented way to answer a tier-4
question, and the setting beside it goes on saying *"no rule covered … please review"* until the
next `upgrade` propagates it. `MD0223` does not catch it: `for_value` is `null` on a value nothing
resolved, and absence is not disagreement. Found while writing
[`driving-mendel.md`](../../docs/guides/driving-mendel.md) §6, where it is stated rather than
smoothed over. **Filed as [#48](https://github.com/comeni-project/Comeni-Labs/issues/48) rather than folded in quietly** — it is a defect in the
explanation layer, which is what Plan 1.14 existed to repair, and it deserves the same treatment.

**`docs/design/` was left alone.** Six design documents and two HTML mockups, none of them
touched. The logo sketch was deleted — 33 KB of branding exploration with no markdown beside it —
and `dashboard.html` and `forge-review.html` stay, each beside the document that argues it in
prose, because separating a claim from its evidence by file extension is not organisation.

# Later the same day — issues #43 and #46

Two abstract issues, taken in the order the operator chose: decide what form data takes, then
move it.

## #43 — declared data is files, and that is the convention rather than a local quirk

The question was whether to collect the data into one SQL database that auto-generates a
human-readable table. The answer is no, and
[`docs/design/declared-data.md`](../../docs/design/declared-data.md) is the argument.

**Two things made the question easier than it looked.** The generated table it asked for already
exists — `diagnostics.yml` plus `tools/generate_diagnostics_doc.py` is exactly the shape
TypeScript (`diagnosticMessages.json`) and Rust (a generated error index) use, and it got its own
page earlier the same day, after the issue was filed. And most of what *looks* like a table in
this repository is not data: `_OPS`, `_REDUCERS`, `DOORS`, `_TIMEOUTS` map names to functions and
types, which no database can hold.

**The evidence is external on purpose**, because the operator asked what the convention is
"regardless of current rules inside this repo". Every comparable curated catalogue — nixpkgs at
100k+, Homebrew, conda-forge, Bioconda, nf-core modules — keeps its data as files in git. The
honest counterexample is crates.io moving its index off git around 2023 for performance, and it
does not transfer: crates.io is machine-published, so it had no review step to lose.

**A database stays legitimate as a derived, gitignored index** if loading ever becomes measurably
slow. At 37 files it is not, and building one now would be optimising an unmeasured cost.

**The substantive half was split out as [#49](https://github.com/comeni-project/Comeni-Labs/issues/49)**
rather than closed with the rest: `MD0000`–`MD0099` is reserved for "loading declared registry
data" and is empty, so a malformed contract surfaces as a Pydantic traceback while every other
stage refuses with a code, a subject and a fix. That is the real complaint under the question.

## #46 — the registry leaves

`registry/` is a git submodule of `comeni-registry`, pinned at **`fb2ded9`**, tagged **`v0.2.0`**.

**The prerequisite was the interesting part.** `comeni-registry`'s public `main` was three commits
behind — no `roles/`, the old rule format, six measurements instead of twelve. A submodule pins a
SHA, so pinning a stale remote would have pinned a registry that cannot build the spine. Those
landed and were tagged before anything else was touched.

**Every test path is unchanged.** All 33 files that load `ROOT / "registry"` are byte-identical,
which is the whole reason a submodule beat a fetch-to-`.registry/` target or a data package.

### What the plan did not predict, and it was not small

**The layer digest became machine-dependent.** The submodule puts `LICENSE`, `README.md` and a
`.git` *file* beside the declared kinds, and that file reads
`gitdir: ../../../.git/worktrees/issues-43-46/modules/registry` — a path naming the worktree and
the checkout location. `digest_of_directory` walked `rglob("*")`, so two clones of the same
pinned commit would pin different digests, and `pipeline.yml` would record whichever machine ran
the build.

**`make verify` was green the entire time.** 814 fast, 5 slow, 73 guards, no drift. Nothing in
the repository compares a digest across machines. **What caught it was building the spine on
`main` and on the branch and diffing the two `pipeline.yml` files** — the technique
`tools/refactor_oracle.py` used for issue #41, applied by hand one day after that tool was
deleted. The lesson is not that the oracle should have been kept; it is that *"this change is a
pure relocation"* is a claim with a cheap test, and the test is comparing artifacts rather than
running the suite.

The remedy is an allowlist. `declared_entries()` in `comeni_core.declared.layered` returns the
`DeclaredKind` directories plus `registry.yml` — what invariant 11 already says a layer *is* — and
both the digest and `layers.load()`'s symlink scan use it, so there is one definition of a
layer's files rather than two. A blocklist would have had to name `.git`, then `.github`, then
whatever the next layer repository carries; the same reasoning that made `test_egress.py` an
allowlist after `object`, `Path` and `Any` arrived one audit apart.

**It also nearly reintroduced A9.** `(path / "contracts").is_dir()` *follows* a symlink, so a
`contracts/` linked out of the layer would have been walked as an ordinary directory — the exact
exploit the allowlist was written on top of. A symlinked kind directory is explicitly refused,
and that is one of the watched reverts.

**The closing proof:** `pipeline.yml` built from the submodule is **byte-identical** to
`pipeline.yml` built on `main`, layer digest included.

### The drift subsystem is deleted

`tools/check_registry_drift.py`, `tests/test_registry_drift.py`, `make drift`, the `REGISTRY`
variable, its line in `make verify`, and nightly's `registry-drift` job. With one copy, drift is
impossible rather than detected — the operator's third goal, met by removing the mechanism.

It also retires a shape that had already failed: `REGISTRY ?= ../comeni-registry` resolved to
`.worktrees/comeni-registry`, where `CLAUDE.md` requires the work to happen, and printed
*"skipped"* rather than failing — so Plan 1.15 Task 0 edited all twelve contracts under a green
`make verify`. That default was repaired in the round-four work. **An optional check that skips
when its input is missing reports success for the wrong reason**, and deleting the target removes
the shape rather than the bug.

### The new failure mode, and the state nobody had produced

A clone without `--recurse-submodules` leaves `registry/` existing and empty, so every path check
passes and the failure arrives 33 times as missing contracts. It now arrives once, in two places
with the same sentence — `layers.load()` for a direct `mendel build`, and a `make check`
prerequisite, because a contributor's first command is `make check` and it would otherwise spend
seventy seconds reaching the wrong diagnosis.

**Watched failing by producing the state by hand**, `mv registry /tmp/… && mkdir registry`. It is
the repository's least-testable class of guard — one for a state that only occurs on somebody
else's machine — and it would otherwise have shipped unread.

### What this costs, recorded because it is real

A change touching both the engine and the registry is **two pull requests**, and the engine one
cannot merge until the registry one does and the pointer is bumped. That is the price of goal 2,
independent versioning, and `docs/guides/contributing.md` says so to a contributor's face rather
than leaving them to find it.

### Also removed

`realrun/` — 664K and 68 tracked files of stale build output, referenced by nothing, carrying a
`pipeline.ir.json` that Plan 1.10 retired. It survived issue #41's sweep because nothing links to
it. Recoverable from history.

## A36 — a separator that separated nothing

`digest.py` prefixes every content hash with `_FILE = b"file\x00"`. Round two set it to `b""`
and ran the whole suite: **436 passed.** Its sibling `_LINK` went with the symlink branch A9
removed, so there is one entry kind and a separator between one thing and nothing.

**The audit's option 1 — delete it — was priced out rather than argued down.** It said changing
the tag is *"free today and expensive after the first lockfile a stranger holds"*.
`comeni-registry` is now published and tagged `v0.2.0`, and a layer digest is what a
`pipeline.yml` pins, so deleting it would move every digest in every existing artifact. Option 3
instead: invent the second entry kind **in the test** and assert the two hash differently. Moves
nothing, and turns *"this line cannot be wrong"* into *"this line is tested"*.

## #49 — `MD0001`–`MD0009`

Every other stage refuses with a code, a subject and a fix; loading refused with a Pydantic
traceback naming a model class and a field path. That says what shape was expected, not which of
thirty-seven files is the wrong shape.

**Six of the nine were existing refusals gaining a prefix**, not new logic — `MD0003` is A26's,

**Two of the nine tests were green before the codes existed**, and the reason is worth keeping.
`pytest` names `tmp_path` after the test that asked for it, so a refusal quoting the layer path

`/tmp/pytest-of-…/test_MD0004_a_layer_contains_0/registry` — and `assert "MD0004" in message`
passed against a message carrying no code at all. **That is A68's shape: a guard comparing a name
against itself.** `_refusal()` scrubs the path now.

`MD0000` stays unallocated. A code of all zeroes reads as a placeholder.

## A130 — human, model, or none

The operator asked what best distinguishes the three. It takes two fields, because the per-value
answer and the "none" answer need different kinds of evidence.

`ValueSource.MODEL` is the per-value answer, and it is a **claim**: a resolver sets its own
`source`, and round three already recorded that a future adapter can set it untruthfully. So
`model` appearing is informative and `model` *not* appearing proves nothing.

`Pipeline.ai` is the other half and is a different kind of fact — how the build was *configured*,
not a self-report about a decision. `available: []` says nothing was wired to a model, so nothing
could have been consulted. `MD0225` refuses a file whose values claim a model while `available`
says none was wired.

**The other direction is not checkable, and that is written beside the field rather than implied.**
A model-backed build whose adapter writes `source: resolver` everywhere is indistinguishable from
a deterministic one. A field that implied more than that would be worse than no field.

**`available` is `list | None`, and the null is the interesting part.** `None` means the file
predates the question; `[]` means somebody looked and nothing was wired. Collapsing them would
refuse every version-3 artifact for contradicting a statement it never made — **which is
`MD0223`'s own `for_value` lesson arriving in a second field, one task before #48 fixed it in the
first.** The spec called it out before the code was written, which is the only reason it did not
have to be found twice.

`pipeline.yml` is at **version 4**. Four totality guards caught the new section on the way in —
`SERIALISED_SHAPE`, the `Pipeline` field list, `_PIPELINE_MODELS`, and two `set(raw) == {…}`
assertions. A new section has to be declared in five places and all five said so.

## #48 — the answered question with the resolver's reason

`stale_reasons` skipped every setting whose `for_value` is `None`. A tier-4 value nothing
resolved also has `for_value: null`, so **the one case where a human is most likely to be editing
was the one case the check could not see.**

Three conditions now, each held by a different test. Dropping `key in answered` turns it into a
nag on every *unanswered* tier-4 setting — correct output saying "please review" — and eleven
tests failed to say so.

**Two existing tests refused after the fix, and both were completing their own premise rather
than absorbing a regression.** One asserted *"the value, the `human` source and the decision's
override all agree — a person answered, and the record proves it"* while leaving `why.reason`
reading *"no rule covered … please review"*. The record did not prove it. That is issue #48
written as a docstring nobody had re-read, roughly a plan and a half before anyone filed it.

**A user-visible behaviour change, documented rather than left to be discovered:** answering a
tier-4 question is now a two-part edit, and the one-part edit exits 2.
`docs/guides/driving-mendel.md` §6 was written yesterday describing the defect as a rough edge and
now shows the refusal and the cure.
