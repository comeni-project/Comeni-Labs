# 2026-08-16, evening — issue #41: code and documentation organisation

**Eleven tasks, one branch, nothing deferred.** The complaint was that `ls docs/` showed the
working record before it showed anything a reader wanted, `comeni_core/` was twenty-four flat
modules, and the error codes were two-thirds of the way down a page about CLI flags. All three
are fixed. Read [the spec](../specs/2026-08-16-code-and-documentation-organisation.md) for the
argument and [the plan](../plans/2026-08-16-code-and-documentation-organisation.md) for the
tasks, each with its corrections recorded inline.

## The evidence that nothing moved

`tools/refactor_oracle.py` existed for one job: a pure reorganisation must produce a
byte-identical pipeline. It built the RNA-seq spine and digested the three emitted files, and it
was run after every task.

```
pipeline.yml       f1f2d7e5e9cca6a3
main.nf            76355bbf9f10d6e6
nextflow.config    72ddb081638edf76
```

**Recorded on `main` at `7315347` from two independent builds that agreed, and unchanged through
all eleven tasks.** It is deleted now — its whole value was in being written *before* the work,
and a checker kept afterwards would be asserting that today's output matches today's output.

It never caught a regression. That is worth saying plainly rather than dressing up: it was
cheap insurance that did not pay out, and the reason to have written it is that the branch moved
every module in `comeni-core` and split three more, and `make check` alone cannot tell a
relocation from a rewrite.

## What the tasks found that the plan did not predict

**Three plan-ordering defects, all the same shape.** Task 5 was written to repair paths that Task
1 breaks, so Task 1 could never end green; Task 8's front door links to two files Task 9 creates,
so Task 8's own `make links` step could not have passed. Both fixed by moving the work, both
recorded in the plan rather than smoothed over. **A plan that verifies at every task boundary has
to be written in dependency order, and reading it forward is not enough to see that** — the
breakage is always in the task *before* the one that repairs it.

**The spec's "one module per verb" was wrong.** Three of the six CLI verbs share the entire
resolution flow, so splitting by verb would have duplicated it three ways. `cli/` splits by *what
a verb does to a pipeline*: `resolve_verbs` produces one, `artifact_verbs` acts on one that
exists, `report` prints, `parse` reads arguments. Recorded in Task 4.

**Six `monkeypatch.setattr(cli, "run_gate", …)` sites broke on that split**, because `run_gate` is
looked up in the calling module and the calling module changed. One test needed two patches where
one had done — `test_a4_a_failed_gate_publishes_nothing` builds and then publishes, so the gate is
invoked from both modules. **Nothing in the repository had recorded that the gate runs twice
there**; the split is what surfaced it.

**A guard that scanned nothing reported nothing and passed.** `test_architecture.py`'s first
version filtered by `{".venv", ".worktrees", …} & set(path.parts)` — and this repository's plans
execute in `.worktrees/<name>/`, so every path matched and the scan skipped the whole repository.
It passed while sitting on the file that holds the string it searches for. Fixed by enumerating
roots; then emptying the roots tuple was watched doing the same thing, so `len(paths)` is asserted
now. **Same defect as `make drift`'s `REGISTRY ?= ../comeni-registry`**, twice in two plans from
two authors, and it is A67's silent direction: the check goes green *faster*.

**The diagnostics generator could not see a hand edit outside its markers.** It spliced a table
into `cli.md` and read the surrounding text back out of the file it was comparing against, so the
header and prose were equal to themselves by construction. The whole page is generated now, and
`make docs` refuses a hand-edited heading — watched.

**`contributing.md` carried seven root-relative links that no gate had ever checked**, because the
file was at the root when they were written. Every one broke on the move to `docs/guides/`. That
is the case for `make links` in one sentence.

## The link checker

Written and run **before** the move, which is what makes its report attributable — a checker
introduced after a repair can only confirm a repair somebody already believed in. It found six
broken links in `docs/` and the root on the pre-move tree, and reports **zero** now.

It skips fenced code blocks (a first draft reported eleven `assert x == [a, b]` lines as links,
and a checker whose output is mostly noise is one people stop reading) and it does not check
`notes/`, because a plan naming files its own tasks create is correct when it executes and broken
until then.

## What is not done

**`ARCHITECTURE.md` describes five stages, and `comeni-core` now has five directories named for
them.** That correspondence is real and it is not enforced. Whether the two should be generated
from each other — or whether a test should assert the directory names against the stage names —
is a question this plan did not answer and did not pretend to. It is the obvious next thing for
somebody who wants the layout to stay honest.

**A tier-4 setting's own `why.reason` stays stale after a human answers it.** Writing
`human_override` and `override_reason` in `decisions:` is the documented way to answer a tier-4
question, and the setting beside it goes on saying *"no rule covered … please review"* until the
next `upgrade` propagates it. `MD0223` does not catch it: `for_value` is `null` on a value nothing
resolved, and absence is not disagreement. Found while writing
[`driving-mendel.md`](../../docs/guides/driving-mendel.md) §6, where it is stated rather than
smoothed over. **Filed as [#48](https://github.com/comeni-project/Comeni-Labs/issues/48) rather than folded in quietly** — it is a defect in the
explanation layer, which is what Plan 1.14 existed to repair, and it deserves the same treatment.

**`docs/design/` was left alone.** Six design documents and two HTML mockups, none of them
touched. The logo sketch was deleted — 33 KB of branding exploration with no markdown beside it —
and `dashboard.html` and `forge-review.html` stay, each beside the document that argues it in
prose, because separating a claim from its evidence by file extension is not organisation.
