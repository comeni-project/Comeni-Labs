## What you can do now

`/forge/sources` lists what each source can read with the column that makes it a tool rather than
a directory listing: **undrafted first**, then drafted, then landed. Start one, and you land in
the queue with its questions open.

**Run end to end against the real registry**, which needed nothing manufactured — three vendored
tools have no contract:

```
sources: ['nf-core'] | counts: {'undrafted': 3, 'drafted': 0, 'landed': 10}
POST /api/sources/draft  {"ref":"nf-core:samtools/faidx","name":"faidx","version":"1.24"}
  -> tools/nf-core/samtools/faidx.contract.yml, 11 holes
GET  /api/questions      -> total: 11, asked by ['faidx']
forge show faidx         -> id = 'nf-core/samtools/faidx@1.24'
```

The CLI reads back what the browser wrote, which is the criterion every phase since 0 has been
held to.

**Drafting it again refuses with `MF0010`, and the first draft is untouched** — mtime unchanged,
still `@1.24` rather than the `@9.9.9` the second attempt asked for. The refusal fires before the
write, which is the only version of that refusal worth having.

**A body carrying `workspace_root` answers `extra_forbidden`** on `['body', 'workspace_root']`.
That is the phase's constraint enforced by the model rather than by a check somebody remembers.

## Two defects older than this phase

**`Workspace.save` overwrote a draft silently.** `mkdir(exist_ok=True)` then `write_text`, no
check — so drafting onto a taken name replaced every answer, proposal and decision on it and said
nothing. True since forge phase 1. Survivable in a CLI a person types deliberately; one careless
click in a form. `MF0010` refuses it, and the CLI gets the fix too.

**The forge's HTTP transport could not be called from a browser at all**, and was mounted where a
browser could reach it. Its request models carry `registry_root`, `source_root` and
`workspace_root`; `settings.py`'s own docstring says *a second place that decides where the
registry lives is a second answer to that question*. That is why every phase since 2 re-exposed
forge operations through routes that supply the paths — and why `main.py`'s docstring saying it
*"never re-exposed route by route"* had been false for four phases.

## The rule that came out of it

> **The served surface is exactly the OpenAPI document.**

FastAPI does not merge a mounted sub-app's schema into its parent, so anything mounted is a
surface `frontend/src/api/` cannot be generated for and an agent reading the schema cannot find.
That decides the mount without appealing to risk — and it also rules out the tempting alternative:
`include_router` *would* put those routes in the document, and it is **worse**, because it would
type and advertise operations that take filesystem paths.

The two transports differ in **who chooses the context** — per call, in the body, versus from
configuration. Neither is wrong; mounting one inside the other made the served app inherit the
more permissive model.

**The module was deleted rather than left unmounted**, on the operator's instruction not to leave
hidden dead code — and the measurement backed it: zero production consumers once the mount went,
exercised only by its own two test files, and `fastapi` an optional extra in `mendel-forge` that
nothing installed. Keeping it would also have shipped a contradiction, since
`driving-the-forge.md` documented mounting it with a worked example and no caveat.

**What was lost, stated rather than glossed:** `test_http.py` held CLI-to-HTTP payload parity —
*two transports over one operation cannot drift*. With one transport that is vacuous, and it does
**not** transfer to `mendel-api`, whose payloads are deliberately different shapes: `AnswerRequest`
is screen-shaped and `FillRequest` is CLI-shaped. What does transfer is *a route holds no logic*,
already asserted in `test_answer_route.py`.

`test_mount.py` **inverted rather than disappeared**: it asserted the mount existed, and now holds
the rule that says why it should not, plus the general form — no request body carries a path.

## Three things caught by running them

1. **My own boundary test could not have failed.** It iterated `app.routes` for
   `APIRoute.body_field` and found **zero** bodies — `include_router` nests the real routes. It
   asserts over `app.openapi()` now, which finds five, and asserts the scan reached something
   before asserting what it did not find. Caught in the audit, before a line was written.
2. **`/draft/i` matched the wrong button.** The state facet has one called *drafted*, so the test
   clicked the filter instead of submitting the form — and the failure read as a mutation that
   never fired. `/draft it/i` now.
3. **`router.test.tsx` failed exactly as designed.** It asserts which nav entries are
   `aria-disabled`, with a comment demanding the list shrink *deliberately* rather than the
   assertion being deleted. `Sources` came off it; `Mendel` is the last one.

## What you still cannot do

- **Land from the browser.** `forge land` needs a checkout it can commit to, and phase 5 showed
  what that means: the default configuration is a submodule at a detached HEAD and refuses.
  Drafting opens work; the queue closes it; landing is still a terminal.
- **Know a tool's real version.** Nothing derives it and nothing should — the form gives you the
  container as evidence and asks. A source adapter reading a version out of `meta.yml` would
  change that, and none does.
- **See a second source.** `nf-core` is the only adapter, so the source column has one value.
  [#65](https://github.com/comeni-project/Comeni-Labs/issues/65) is the second, and it is a
  network call with a completely different cost from a directory walk.
- **Click any of it.** Seven phases running: `curl` and component tests against a mocked `fetch`.
