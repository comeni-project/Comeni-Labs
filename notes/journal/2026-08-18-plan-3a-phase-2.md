## The partial batch was exercised for real, and here is how

The plan predicted nobody would hit it by accident — both `samtools` drafts accept
`alignment.bam`, so the happy path is all a naive run exercises. **It was produced deliberately,
and the mechanism is worth writing down**: a port's *name* candidates are recomputed from its
*type* (`Hole.after`), so filling `produces[0].type_id` differently on two drafts makes their
`consumes[0].name` candidates diverge — `['input']` on one, `['bam']` on the other.

```
POST /api/questions/answer-all  {subject: "consumes[0].name", value: "input", …}

  settled: ['samtools-index']
  refused: samtools-sort -> MF0003: 'input' is not legal for consumes[0].name
```

and on disk: `samtools-index` carries the value with its provenance, `samtools-sort` is `null`.
**Not half-written** — atomic per draft, confirmed rather than asserted.

The happy batch was checked the same way: both drafts settled `consumes[0].type_id` with
*identical* `by` and `why`, which is the thing that would break first if the batch path were a
shortcut. It is not a shortcut; it is a loop that writes each value individually.

## The escape hatch, and the assertion that matters

```
POST /api/questions/propose  →  {still_open: true}
```

and the question **stays in the queue**, now carrying the proposal:

```json
{"id": "qc.index_stats", "description": "per-reference index statistics emitted beside a BAI",
 "why": "nothing declared covers idxstats output", "by": "rafaelcorreia"}
```

**If that question had disappeared, the escape hatch would have become a fill** and a draft that
cannot land would look ready. `Scaffold.propose` already guaranteed it; what phase 2 added is a
human path to it and a payload field, `still_open`, that says so where a UI can read it.

## What the audit caught, before any of this ran

Three findings, and **two were the same defect**: a hedge in the plan where one `grep` had the
answer. The writing-plans skill forbids exactly that, and one of the hedges was hiding a real gap.

**`ShowResult` did not carry `proposed`.** The plan had waved at it — *"if it is already there,
use it"*. Without that field the API could **write** a proposal and never **read** one back, so a
declined question would have rendered as untouched. It became a definite step with its own test.

The other two: there are no `registry_root`/`source_root` fixtures (the idiom is `_ctx(tmp_path)`
at `test_ops.py:9`), and `Field` was not imported in `ops.py`.

**One thing was checked and was *not* a finding**, which is worth as much: `getByText` *does* see
text broken by a nested `<span>`. I probed it rather than pattern-matching on three earlier
failures — those were *multiple matches*, not *no match*.

## A shape that has now bitten four times

Every assertion on a diagnostic code matches **twice**, because `Refusal` deliberately renders the
code in the message *and* in the `forge explain <code>` hint beside it. Same for a draft name that
appears in both the "Asked by" prose and a refusal report.

`getByText` throws on multiple matches. **The rule: assert with `getAllByText(...).length`, or on
a phrase that appears once.** Four occurrences across three phases is enough to stop calling it a
surprise.

## What you still cannot do

- **No proposal review.** Phase 2 *creates* a proposal; approving, renaming or rejecting it is
  phase 3, and until then a declined question sits in the queue with nowhere to go.
- **No contracts, no drift, no sources** — phases 4–6. Those nav entries are still
  `aria-disabled` with the phase that builds them.
- **No landing page**; `/` redirects to the queue for the whole of 3A. **No AI anywhere.**
- **The confirmable band is still unexercised.** Nothing has run `forge fill --model` over these
  drafts, so `suggested` is `null` and the `MODEL` marker has never been seen against real data —
  only in a component test. The one band the design most wants you to see is the one nobody has.
- **`answer-all` has no undo**, and neither does anything else in the forge. Deliberate for now;
  spec §5 says adding one for the batch path alone would be inconsistent.
- **`queue.read()` still re-reads every draft per request, and `answer_all` reads them all
  again.** Fine at two drafts. It is the first thing to break at scale and should be measured
  before it is designed around.
- **Nobody has clicked it.** Driven with `curl` through the Vite proxy and by checking every URL
  loads; the mouse path is covered by 39 component tests against a mocked `fetch`.

## Corrections to the plan — two, and both were test assertions

1. **Two `getByText` assertions matched twice** (the code, and the draft name), per the section

2. **The `Lookup` test waited on the wrong thing.** It awaited the heading, which renders the id

   so everything after the `waitFor` read a loading state. It waits on the data now.
