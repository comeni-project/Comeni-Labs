## What the plan got wrong, and what the work found

Recorded per task in the plan file itself. The ones that matter for an auditor:

**A human override on a *parameter* had never worked.** `_still_applies` checked membership in
a candidate list that is literally `[None]` for parameters, so every override was discarded,
counted as newly asked, and the answer thrown away. Every existing replay test used producers
or sources, which have real candidate lists. Coverage of the parts is not coverage of the path.

**The egress guard walked three doors out of four.** `_payload_types()` collected roots by
scanning `vars(egress)`. Correct while every payload lived there; silently wrong the moment the
publication payload moved to `comeni_core.pipeline`. Ten tests passed. Nothing leaked — the
swap had just happened — but a guard deriving its subject from *where a type happens to live*
rather than from *the declaration of what it guards* stops guarding without failing.

**`MD0216` shipped inert.** The refusal was written, `make verify` was green, and reverting it
broke nothing: no test covered it. The guard was written afterwards. This is A14's finding
arriving on the same afternoon as A14's ledger row, in code by whoever wrote the row. It is
recorded rather than quietly fixed, because the lesson is not "remember to write a test" — the
rule had three files of tests around it — but that **green is not evidence**.

**Two tests had been passing for the wrong reason**, both found by `MD0216` refusing. Both A27
tests hung their smuggled value on `nf-core/samtools/sort`, which declares `params: []`, so the
value was dropped before anything validated it.

**Three plan-level design errors, corrected with the reasoning recorded:** `MD0213` cannot
refuse in `emit` (that verb is the cure); `orphaned` is better derived from what the resolver
was *asked* than from diffing two pipelines; and `publish` takes no `--out`, because it
certifies rather than produces.

## Testing the new systems

For an auditor who wants to drive it by hand:

```bash
uv run mendel build --goal examples/rnaseq-goal.yml --out /tmp/audit
$EDITOR /tmp/audit/pipeline.yml                  # answer seq_platform, break something
uv run mendel emit /tmp/audit/pipeline.yml --out /tmp/audit
uv run mendel upgrade /tmp/audit/pipeline.yml --dry-run
uv run mendel publish /tmp/audit/pipeline.yml --gate lint
uv run mendel explain MD0213
```

Things worth attacking, named because naming them is cheaper than hoping:

- **`emit` on a hand-crafted `pipeline.yml`.** It runs with no registry, so the model
  validators are the only thing between a file and generated Groovy. `MD0201`'s character
  class, `NfTemplate`, `NfIdentifier` and `GroovyExpression` are the surface.
- **`channels[].expression`** is unbounded Groovy by design and reaches `main.nf` verbatim. It
  is `GroovyExpression`, marked and not validated. That is deliberate and it is the widest
  thing in the file.
- **`from_digest`** — try to make the artifact and the run diverge without any verb noticing.
- **`Resolution.source`** — a resolver may claim `HUMAN`. Declared vocabulary, not a proof.
- **The `frozen=True` on `Pipeline`** — `model_copy` bypasses validation. `stamp()` uses it
  twice.
- **`upgrade --out`** must never resolve to the input's directory. It compares `.resolve()`;
  symlinks were A9's subject once already.
