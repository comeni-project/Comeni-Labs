## The number that matters

**Six of twenty rules could be written. Now seventeen can, and the four that cannot are refused
for reasons the plan names.**

Stream 4 of the design audit took twenty real tier-3 rules from the literature and tried to write
each one against the shipped format. The result was **6 clean · 4 load and are wrong · 1
contortion · 9 cannot be written** — and the four that loaded and were wrong were the problem,
because a rule that refuses is a format behaving well and a rule that fires wrongly is not.

`tests/test_rule_corpus.py` is the same twenty, rewritten and asserted. The four still refused:
**R02 and R03 are arithmetic**, which this format still cannot express and refuses honestly
(issue #39). **R02b is the contortion** — enumerating one row per read length — and it is *newly*
caught, because `MD0311` sees that eight rows over an unbounded integer leave everything below
the lowest one uncovered, which is the defect the contortion was hiding. **R20 is refused by
design**, and now names the role rather than the missing contract.

`notes/audits/fixtures/rule-attempts/` was **not edited**. A corpus rewritten in the new
format cannot also be the record of what the old one could not express, so there are two
directories: that one says what broke, `tests/fixtures/rule-corpus/` says whether it is fixed, and
a test asserts neither has an orphan.

## What the guards did, which is again the part worth reading

**Six inert guards, all found by reverting, and four of them in code written the same hour.**
That is more than any previous plan, and the reason is that this plan added two of almost
everything — two code paths carrying a premise, two models with a `review_level`, two checks for
a duplicate key — and a test written against one of a pair says nothing about the other.

- **Task 2's never-overwrite guard was inert exactly as the plan specified it.** R15's row
  conditions on `strandedness: absent`, so with strandedness measured the row fails its own
  predicate and the rule under test is never reached. **Reading the plan carefully would not have
  found it.**
- **Task 8's premise guard covered the selection path and not the param path.** Different code,
  different field, one test.
- **Task 7's `Why.review_level` was shadowed by `ResolvedValue.review_level`**, which has computed
  the same thing since Plan 1, so the test passed against a field that already existed.
- **Task 10's unanimity branch had no fixture that could reach it**: nothing in the tree had two
  implementations of one role declaring different domains for one parameter.
- **Task 9's `_sole_premise` carried an unreachable clause** — deleted rather than kept, because
  an unreachable condition reads to the next person as a case somebody thought about.

**And two reverts were invalid**, both recorded as such. One edited the wrong call site because
its anchor string appeared five times in the file; it failed *a* test, which looked plausible, and
was caught only because the failure was the **wrong** test. The other referenced an unimported
name, so 46 tests errored rather than failed — a guard that "fails" because the module will not
import has not been watched. Every revert now asserts its anchor is unique.

## The plan was wrong about its own guards, in both directions

Task 1's Step 5 predicted no test would fail and three did. Task 2's predicted one would and none
did. Task 7's Step 5 test was inert as written. **A stale prediction costs nothing when the revert
is run either way**, which is the argument for running it rather than reasoning about it — and it
is A14's own argument, arriving from inside the plan that was supposed to be following it.

## Fixtures drift under a new rule, roughly once per task

Task 4 broke a roles fixture that had *replaced* a role rather than adding one. Task 7 turned an
`MD0301` probe into an `MD0313` case. Task 9 found **six incomplete tables across four files**, and
that is the finding rather than the inconvenience: each was a rule that answered part of its
premise's domain and demoted silently to tier 4 for the rest. Task 10 made a fixture's `then: 99`
illegal, and collapsed an overlay test's discriminator for the second time in two tasks.

Expect one per task from here. A fixture carrying its discriminator implicitly is what makes it
fragile — distinct values prove which block answered, where an absence only proves one row is
gone.

## Two things the corpus found that nothing else did

**A121 was only half closed.** `predicates.matches` implemented `not` and `in` from Task 3, and
`DecisionRow.when` was typed `dict[str, ParamValue]` — so a rule using either was refused by
pydantic before the evaluator ever saw it. An evaluator handling a case the model cannot
represent is the same defect as a model permitting one the evaluator ignores, and **neither shows
up until somebody writes the rule.** Nine of this plan's own tests exercised `matches` directly
and none of them went through the model.

**And `MD0308` made five corpus rules say what they meant.** `sjdb_overhang`, `twopass_mode` and
`cpus` are STAR's alone, and HISAT2 also fills `alignment`, so each needed
`when_implementation:`. That is A123 working: the value would have been dead whenever HISAT2 won,
and the format now makes the author narrow it rather than discovering it at run time.

## What is carried, and named

- **`presence: present` does not force insertion.** It means "leave routing alone", which is a
  real answer and the default branch of a presence decision. Forcing a step routing would not
  otherwise add is spec §4.1's open half, and R09 in the corpus records it.
- **Two implementations declaring different domains for one param falls back** to the heuristic
  rather than being refused. Refusing it outright is stronger and needs a code of its own.
- **Completeness over a product of domains is not checked**, deliberately. A check that
  half-computed it would refuse legitimate tables, which is worse than not checking.
- **Arithmetic in `then` is still unwritable** — issue #39, and R02/R03 are the evidence.
